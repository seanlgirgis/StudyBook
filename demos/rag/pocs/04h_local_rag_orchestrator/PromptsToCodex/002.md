Important architecture decision:

04h will be the RAG/business orchestrator.

The LLM container should NOT own business data, retrieval, or KB logic.

The orchestrator should own:
- business knowledge files
- retrieval
- intent cleanup orchestration
- prompt assembly
- provider routing
- /ask API contract

The LLM container is only an inference service. It can later be swapped with:
- local 8-bit Mistral
- Grok-mini
- Grok-3
- OpenAI or another provider

This separation matters because an LLM cannot automatically inspect files just because files exist in a container. The orchestrator must read the KB, retrieve relevant sections, put the selected text into the prompt, and call the model.
