Implementation requirements:

1. data/knowledge_base.json

Create synthetic North Texas Comfort & Home Services KB records.

Each record:
{
  "id": "kb_plumbing_leak_001",
  "title": "Plumbing leak repair",
  "service_type": "plumbing",
  "symptoms": ["leak", "pipe", "sink", "water under sink"],
  "text": "..."
}

Include at least these categories:
- AC repair
- AC replacement
- heating repair
- plumbing leak repair
- clogged drains
- water heater no hot water
- water heater pilot light
- maintenance plans
- emergency service
- appliance repair

2. src/kb_loader.py

Implement:
load_kb(path: str | Path) -> list[dict]

Validate required fields:
- id
- title
- service_type
- symptoms
- text

Raise clear ValueError for malformed records.

3. src/retriever.py

Implement simple deterministic retrieval:
retrieve(query: str, records: list[dict], top_k: int = 3) -> list[dict]

Scoring:
- tokenize lowercase query
- match against title, service_type, symptoms, text
- title/service_type/symptoms should count more than body text
- return top_k records with score > 0
- include score in returned dict

No vector DB yet.

4. src/llm_gateway.py

Implement:
call_local_llm(prompt: str, base_url: str = "http://localhost:8002", timeout: int = 180) -> str

It should POST:
POST {base_url}/infer
{"query": prompt}

Return response["answer"].

If LLM is unavailable, raise a clear RuntimeError.

5. src/service.py

Implement:
clean_intent_with_local_llm(original_query: str) -> dict

Prompt local 8-bit LLM to return strict JSON:
{
  "cleaned_intent": "...",
  "service_type": "AC|heating|plumbing|water_heater|appliance|maintenance|unknown",
  "symptoms": ["..."],
  "urgency": "low|normal|urgent|unknown"
}

Parse JSON robustly.
If parse fails or LLM unavailable, use deterministic fallback:
- cleaned_intent = original query stripped
- service_type inferred from keywords if possible
- symptoms = matched terms
- urgency = urgent if emergency/no heat/no cooling/leak/flood keywords appear else normal/unknown

Implement:
answer_query(original_query: str) -> dict

Flow:
- clean intent
- load KB
- retrieve top sections
- assemble grounded prompt:
  "Use only these knowledge base sections..."
- call local LLM for draft answer
- if LLM unavailable for draft answer, return fallback answer saying matching KB sections were found but local LLM unavailable
- return:
{
  "original_query": "...",
  "cleaned_intent": "...",
  "service_type": "...",
  "symptoms": [...],
  "urgency": "...",
  "retrieved_sections": [
    {"id": "...", "title": "...", "service_type": "...", "score": 0, "text": "..."}
  ],
  "draft_answer": "...",
  "provider_used": "local_8bit",
  "status": "answered|no_context|llm_unavailable"
}
