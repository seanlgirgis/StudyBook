Business behavior to implement:

The system must classify every customer request into one of these classes:

1. supported
   The request matches a service we handle.

2. clarification_needed
   The request may match supported services but is ambiguous.

3. unsupported
   The request is clearly outside our business scope.

4. human_escalation_required
   The system cannot safely classify or clarify after max clarification attempts, or the issue requires human handoff.

Supported service capabilities:

- AC repair

- emergency service
- appliance repair

- car AC / vehicle air conditioning
- vehicle repair
- carpet cleaning
- vent cleaning / duct cleaning unless explicitly supported in KB
- pest control
- roofing
- remodeling
- electrical panel work
- medical/legal/insurance questions
- anything unrelated to home-services intake

Rules:

- If classification = supported:
  - clarification_needed must usually be false
  - matched_capability must name one supported capability
  - retrieve KB sections
  - then Grok final provider may answer if available

- If classification = clarification_needed:
  - clarifying_questions must contain 1-3 concise customer questions
  - do not retrieve final answer
  - do not call Grok final answer
  - status = clarification_needed

- If classification = unsupported:
  - unsupported_reason must be clear
  - do not retrieve KB
  - do not call Grok final answer
  - status = unsupported_service
  - response may include a short supported-services list from policy, not invented services

- If classification = human_escalation_required:
  - do not call Grok final answer
  - status = human_escalation_required
  - include handoff_summary and recommended_next_message
