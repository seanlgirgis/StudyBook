CONTENT DEPTH STANDARD

Always write for a Senior Data Engineer audience:
- Explain tradeoffs, not just definitions
- Cover what breaks at scale
- Show how this topic connects to the broader data/AWS stack
- Each .hi callout = a key insight worth remembering
- Each .warn callout = a real production gotcha
- Use tables to compare options (e.g. Gateway endpoint vs Interface endpoint)
- Use pre/code blocks for any config, policy JSON, CLI command, or code example
- Include a code block where it adds value — illustrate the concept, stop there (20 lines max)

---

SIZE DISCIPLINE — NON-NEGOTIABLE

The page must complete in a single response without truncation.
If you feel a section pulling you toward exhaustive coverage, stop and summarize.
Rules:
- No section prose exceeds 4 short paragraphs
- No code block exceeds 30 lines
- No table exceeds 8 rows
- Q&A answers: 3–5 sentences maximum — sharp, not comprehensive
- If the topic has more than 10 natural sections, merge the two least distinct ones
- Do NOT add an introduction section that restates the title
- Do NOT add a "Further Reading" or "Summary" closing section
The goal is a page a senior engineer scans in 10 minutes, not reads for 45.
