Schema Inspection

information_schema gives you a safe, portable way to inspect tables and columns before you transform anything.

SQLSELECT
    table_name
FROM information_schema.tables
WHERE table_schema = 'public';
SQLSELECT
    column_name,
    data_type
FROM information_schema.columns
WHERE table_name = 'customer';
NUGGET Metadata queries often answer transformation questions faster than scanning sample rows.
COMMON TRAP A column can display like text in a result set while actually being stored as ARRAY or USER-DEFINED.

PostgreSQL Data Types

Course 06 works mainly with text, numeric, date/time, array, and custom type patterns.

  • CHAR, VARCHAR, TEXT
  • INT, DECIMAL
  • DATE, TIME, TIMESTAMP, INTERVAL
  • ARRAY
  • USER-DEFINED

How to think about them

  • TEXT is usually the most flexible string type.
  • DECIMAL is better when exact numeric precision matters.
  • INTERVAL stores duration, not clock time.
  • USER-DEFINED usually means inspect further before transforming.
COMMON TRAP STRING is not a PostgreSQL text type.
SEAN MEMORY LINE Visible shape is not storage type.

04

Date and Time Arithmetic

  • DATE - DATE returns integer days.
  • DATE + integer adds days.
  • TIMESTAMP - TIMESTAMP returns INTERVAL.
  • TIMESTAMP + INTERVAL shifts a timestamp.
  • INTERVAL can be multiplied.
SQLSELECT
    rental_date,
    return_date,
    return_date - rental_date AS days_rented
FROM rental
WHERE return_date IS NOT NULL;
SQLSELECT
    rental_date,
    rental_date + INTERVAL '3 days' AS expected_return_date
FROM rental;
SQLSELECT
    INTERVAL '1 day' * rental_duration AS allowed_rental_period
FROM film;
NUGGET Operand type controls result type, so date arithmetic and timestamp arithmetic should not be explained the same way.
COMMON TRAP DATE + integer treats the integer as days, not hours or generic units.

05

Current Date/Time and Casting

  • NOW()
  • CURRENT_TIMESTAMP
  • CURRENT_TIMESTAMP(2)
  • CURRENT_DATE
  • CURRENT_TIME
  • NOW()::timestamp
  • CAST(NOW() AS timestamp)
SQLSELECT
    NOW() AS now_value,
    CURRENT_TIMESTAMP AS current_ts,
    CURRENT_TIMESTAMP(2) AS current_ts_2dp,
    CURRENT_DATE AS current_date_value,
    CURRENT_TIME AS current_time_value;
SQLSELECT
    NOW()::timestamp AS cast_with_double_colon,
    CAST(NOW() AS timestamp) AS cast_with_cast;
INTERVIEW SENTENCE Function choice depends on the underlying data type, and explicit casting helps make time values fit the intended comparison or grouping logic.

06

AGE

AGE(later, earlier) returns an interval-style elapsed-time result.

SQLSELECT
    rental_date,
    return_date,
    AGE(return_date, rental_date) AS rental_age
FROM rental
WHERE return_date IS NOT NULL;
COMMON TRAP Use AGE(later, earlier), not the other way around.
SEAN MEMORY LINE Subtraction gives difference. AGE() gives elapsed age.

07

EXTRACT, DATE_PART, DATE_TRUNC

EXTRACT and DATE_PART return subfield values. DATE_TRUNC returns a bucketed timestamp or interval.

SQLSELECT
    EXTRACT(year FROM payment_date) AS payment_year,
    EXTRACT(quarter FROM payment_date) AS payment_quarter,
    SUM(amount) AS revenue
FROM payment
GROUP BY 1, 2
ORDER BY 1, 2;
SQLSELECT
    DATE_PART('month', payment_date) AS payment_month
FROM payment;
SQLSELECT
    DATE_TRUNC('month', payment_date) AS payment_month_start,
    SUM(amount) AS revenue
FROM payment
GROUP BY 1
ORDER BY 1;
COMMON TRAP DATE_TRUNC returns timestamp/interval, not just a number.
INTERVIEW SENTENCE For timestamp grouping, I use EXTRACT or DATE_TRUNC depending on whether I need a numeric subfield or a truncated timestamp.

08

Arrays

Arrays are common in Sakila-style examples because one row can hold multiple values in a single column.

SQLSELECT
    title,
    special_features
FROM film
WHERE special_features[1] = 'Trailers';
SQLSELECT
    title,
    special_features
FROM film
WHERE 'Trailers' = ANY(special_features);
SQLSELECT
    title,
    special_features
FROM film
WHERE special_features @> ARRAY['Deleted Scenes'];
NUGGET Arrays force you to think about position, search scope, and containment as three different operations.
COMMON TRAP PostgreSQL arrays start at 1, not 0.
INTERVIEW SENTENCE For arrays, I know position checks are different from searching the full array.

Text Parsing

SQLSELECT
    title,
    CHAR_LENGTH(title) AS title_length
FROM film;
SQLSELECT
    email,
    POSITION('@' IN email) AS at_position
FROM customer;
SQLSELECT
    email,
    SUBSTRING(email FROM 1 FOR POSITION('@' IN email) - 1) AS username
FROM customer;
SQLSELECT
    email,
    SUBSTRING(email FROM POSITION('@' IN email) + 1 FOR CHAR_LENGTH(email)) AS domain
FROM customer;
NUGGET Parsing usually combines one function that finds a marker with another that extracts a slice.
COMMON TRAP SUBSTRING positions are 1-based.

Trimming and Padding

SQLSELECT
    TRIM('  padded text  ') AS cleaned_text;
SQLSELECT
    LPAD(customer_id::text, 5, '0') AS padded_customer_id
FROM customer;
SQLSELECT
    RPAD(first_name, 12, '.') AS first_name_padded
FROM customer;
SQLSELECT
    LTRIM('---value', '-') AS left_trimmed,
    RTRIM('value---', '-') AS right_trimmed;
COMMON TRAP Padding can truncate if the requested length is shorter than the original string.
SEAN MEMORY LINE Trim removes noise. Pad creates alignment.

12

Full-Text Search

LIKE is useful but limited and case-sensitive. Full-Text Search normalizes search terms and is better for natural-language-style matching.

SQLSELECT
    title
FROM film
WHERE title LIKE 'ELF%';
SQLSELECT
    title
FROM film
WHERE to_tsvector(title) @@ to_tsquery('elf');

to_tsvector converts text into searchable tokens. to_tsquery converts query text into a search query. @@ compares the two.

COMMON TRAP Full-Text Search is not the same as LIKE.
INTERVIEW SENTENCE For text search, LIKE is useful for simple patterns, while Full-Text Search is better for natural language matching.

Extensions and Custom Database Features

SQLCREATE TYPE dayofweek AS ENUM (
    'Monday',
    'Tuesday',
    'Wednesday',
    'Thursday',
    'Friday',
    'Saturday',
    'Sunday'
);
SQLSELECT
    typname,
    typcategory
FROM pg_type
WHERE typname = 'dayofweek';
SQLSELECT
    column_name,
    data_type,
    udt_name
FROM information_schema.columns
WHERE table_name = 'film';
SQLCREATE FUNCTION example_label(input_text text)
RETURNS text
LANGUAGE sql
AS $$
    SELECT UPPER(input_text);
$$;
SQLCREATE EXTENSION IF NOT EXISTS fuzzystrmatch;
SQLSELECT
    levenshtein('GUMBO', 'GAMBOL') AS edit_distance;
SQLCREATE EXTENSION IF NOT EXISTS pg_trgm;
SQLSELECT
    similarity('word', 'words') AS similarity_score;
NUGGET PostgreSQL can be extended with custom types, custom functions, and packaged extensions, so not every useful capability is built in from the start.
COMMON TRAP USER-DEFINED means inspect the actual type name before you assume normal text behavior.

Common Traps

  • STRING is not a PostgreSQL text type.
  • PostgreSQL arrays start at 1, not 0.
  • special_features[1] checks only the first array position.
  • ANY searches anywhere in the array.
  • DATE - DATE returns integer days.
  • TIMESTAMP - TIMESTAMP returns INTERVAL.
  • DATE + integer treats the integer as days.
  • AGE(later, earlier), not the other way around.
  • DATE_TRUNC returns timestamp/interval, not just a number.
  • LIKE is case-sensitive.
  • SUBSTRING positions are 1-based.
  • Padding can truncate if requested length is shorter than the original string.
  • Full-Text Search is not the same as LIKE.
