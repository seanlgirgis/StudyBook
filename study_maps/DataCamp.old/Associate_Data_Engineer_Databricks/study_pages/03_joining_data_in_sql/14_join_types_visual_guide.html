1. Intro

A SQL join combines rows from two tables based on a matching rule. Joins matter because real data is usually split across multiple related tables.

2. Join vocabulary

  • left table
  • right table
  • matching rows
  • unmatched rows
  • NULL values

3. INNER JOIN

returns only matching rows from both tables

SELECT c.name, l.name FROM countries AS c INNER JOIN languages AS l USING (code);

4. LEFT JOIN

returns all rows from the left table and matching rows from the right table

LEFT JOIN is also called LEFT OUTER JOIN

SELECT c.name, l.name FROM countries AS c LEFT JOIN languages AS l USING (code);

5. RIGHT JOIN

returns all rows from the right table and matching rows from the left table

RIGHT JOIN is also called RIGHT OUTER JOIN

less common because it can usually be rewritten as LEFT JOIN by swapping table order

SELECT c.name, l.name FROM countries AS c RIGHT JOIN languages AS l USING (code);

6. FULL JOIN

returns all matched rows plus unmatched rows from both tables

FULL JOIN is also called FULL OUTER JOIN

conceptually, FULL JOIN gives LEFT JOIN + RIGHT JOIN style coverage

SELECT c.name, l.name FROM countries AS c FULL JOIN languages AS l USING (code);

7. CROSS JOIN

CROSS JOIN returns every possible combination of rows from the two tables. It does not use ON or USING. If table A has 3 rows and table B has 3 rows, the result has 9 rows.

SELECT
    p1.prime_minister,
    p2.president
FROM prime_ministers AS p1
CROSS JOIN presidents AS p2
WHERE p1.continent = 'Asia'
  AND p2.continent = 'South America';

8. SELF JOIN

A self join is when a table is joined to itself. It does not use a special SELF JOIN keyword. Instead, the same table appears twice with different aliases. Self joins are useful when comparing rows within the same table, such as pairing countries from the same continent.

SELECT
    p1.country AS country1,
    p2.country AS country2,
    p1.continent
FROM prime_ministers AS p1
INNER JOIN prime_ministers AS p2
ON p1.continent = p2.continent
   AND p1.country <> p2.country;

10. Common traps

  • INNER JOIN does not keep unmatched rows
  • LEFT JOIN keeps all left rows, not all rows
  • RIGHT JOIN keeps all right rows, not all rows
  • FULL JOIN can produce NULLs on either side
  • USING only works cleanly when the join key has the same name in both tables
  • CROSS JOIN does not use ON or USING.
  • CROSS JOIN can multiply row counts quickly.
  • SELF JOIN is not a SQL keyword.
  • Aliases are required when joining a table to itself.
  • Add a not-equal condition when you need to avoid pairing a row with itself.

11. Interview-safe language

  • INNER: I use INNER JOIN when I only want rows with matching keys in both tables.
  • LEFT: I use LEFT JOIN when I must keep every left-table row even if right-side values are missing.
  • FULL: I use FULL JOIN when I need complete coverage from both tables, including unmatched rows.
  • CROSS: I use CROSS JOIN when I need all possible pairings between two sets of rows.
  • SELF: I use a self join pattern with aliases when I need to compare rows within the same table.

12. Small note

LEFT, RIGHT, and FULL belong to the outer join family. INNER JOIN and CROSS JOIN are not outer joins. SELF JOIN is a pattern, not a separate join keyword; it can use INNER JOIN, LEFT JOIN, or another join type depending on the goal.

CROSS JOIN and SELF JOIN are shown separately above.
