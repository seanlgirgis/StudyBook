1. Purpose

This page translates SQL joins into business decisions. The question is not only "what does the join do?" but "which business problem does it solve?"

2. INNER JOIN - only matching records

Meaning:
Use when you only want rows that exist in both tables.

Business examples:

  • Sales order + payment table: show only orders that have confirmed payments.
  • Employee + badge access: show only employees who actually entered the building.
  • Product + active price: show only products that currently have a valid price.
  • Customer + signed contract: show only customers with completed contracts.
  • Server + monitoring agent: show only servers that are registered and sending telemetry.

SQL pattern:

SELECT ...
FROM table_a AS a
INNER JOIN table_b AS b
ON a.key = b.key;

3. LEFT JOIN - keep the main list

Meaning:
Use when the left table is your main list and you do not want to lose any rows.

Business examples:

  • All customers + weekly orders: keep every customer, show NULL where they placed no order.
  • All servers + latest monitoring data: keep every server, show NULL where telemetry is missing.
  • All job applicants + interview schedule: keep every applicant, show who has not been scheduled yet.
  • All bank accounts + fraud alerts: keep all accounts, show alerts only where they exist.
  • All products + inventory: keep all products, find products with missing stock records.

SQL pattern:

SELECT ...
FROM main_table AS m
LEFT JOIN detail_table AS d
ON m.key = d.key;

4. RIGHT JOIN - keep the right-side list

Meaning:
Use when the right table is the main list. Less common because most teams rewrite it as a LEFT JOIN by swapping table order.

Business examples:

  • Languages RIGHT JOIN countries: keep all countries even if language data is missing.
  • Orders RIGHT JOIN customers: keep all customers even if there are no orders.
  • Monitoring records RIGHT JOIN CMDB: keep all CMDB assets even if monitoring is missing.

Teaching note:
Prefer rewriting as LEFT JOIN when possible.

5. FULL JOIN - reconciliation and gap finding

Meaning:
Use when you want to compare two systems and see matched and unmatched records from both sides.

Business examples:

  • Payroll system vs HR system: find employees missing from either side.
  • CMDB assets vs monitoring inventory: show assets in CMDB only, monitoring only, and both.
  • Bank transactions vs ledger entries: detect unmatched transactions and unmatched accounting records.
  • Customer CRM vs billing platform: find customers that exist in one system but not the other.
  • Data migration source vs target: verify what copied, what failed, and what is extra.

SQL pattern:

SELECT ...
FROM system_a AS a
FULL JOIN system_b AS b
ON a.key = b.key;

6. CROSS JOIN - every possible combination

Meaning:
Use when you intentionally want every possible pairing between two tables. CROSS JOIN does not use ON or USING.

Business examples:

  • Products × regions: create a product-region planning grid.
  • Employees × training modules: create required training assignments.
  • Drivers × delivery zones: evaluate possible coverage combinations.
  • Prime ministers × presidents: generate all possible meeting pairs.
  • Price scenarios × demand scenarios: test every business planning combination.

Warning:
Rows multiply fast. 100 rows × 100 rows = 10,000 rows.

7. SELF JOIN - compare a table to itself

Meaning:
Use when comparing rows inside the same table. SELF JOIN is not a special SQL keyword. It is a pattern using aliases.

Business examples:

  • Employees table: match employees to their managers.
  • Populations table: compare 2010 population to 2015 population for the same country.
  • Products table: find products in the same category.
  • Transactions table: find suspicious transactions from the same account close in time.
  • Server events table: compare current incident to previous incident on the same server.

SQL pattern:

SELECT ...
FROM same_table AS a
INNER JOIN same_table AS b
ON a.key = b.key;

8. Quick decision guide

QuestionJoin to consider
Only matching rows?INNER JOIN
Keep every row from my main list?LEFT JOIN
Keep every row from the right-side list?RIGHT JOIN, or rewrite as LEFT JOIN
Compare two systems and find gaps on both sides?FULL JOIN
Generate every possible pairing?CROSS JOIN
Compare rows inside the same table?SELF JOIN pattern

9. Sean interview-safe summary

I choose the join based on the business question. If I only need matched records, I use INNER JOIN. If I need to preserve my main list and show missing detail as NULL, I use LEFT JOIN. If I am reconciling two systems and need unmatched rows from both sides, I use FULL JOIN. For all possible combinations, I use CROSS JOIN. For comparing records inside one table, I use a self join with aliases.

10. Semi joins and anti joins

Semi join business examples:

  • Find customers who placed at least one order.
  • Find servers that appear in the monitoring feed.
  • Find applicants who already completed an assessment.
  • Find products that have at least one active price record.

Anti join business examples:

  • Find customers who have not placed an order.
  • Find CMDB servers that are not reporting telemetry.
  • Find applicants who have not completed an assessment.
  • Find products missing an active price record.

Teaching note:
Semi and anti joins usually filter the first table using a subquery. They do not add columns like normal joins.

11. Subqueries inside WHERE and SELECT

Business examples:

  • WHERE subquery: Find customers who placed an order last month.
  • WHERE subquery: Find servers that appear in an outage event table.
  • WHERE subquery: Find products whose category appears in a priority-category list.
  • SELECT subquery: Show each continent with a count of monarchs.
  • SELECT subquery: Show each customer with their number of support tickets.

Teaching note:
A WHERE subquery filters rows. A SELECT subquery calculates a value to display as a column.

12. Subqueries inside FROM

Business examples:

  • Build a temporary table of latest transaction date per customer, then join or filter from it.
  • Build a temporary table of highest server utilization per application, then rank the risky applications.
  • Build a temporary table of most recent independence year per continent, then compare only continents with monarchs.
  • Build a temporary table of monthly sales totals, then compare months.
  • Build a temporary table of incident counts per service, then filter high-risk services.

Teaching note:
A FROM subquery is useful when the inner query creates a summarized or prepared dataset that the outer query can treat like a table.
