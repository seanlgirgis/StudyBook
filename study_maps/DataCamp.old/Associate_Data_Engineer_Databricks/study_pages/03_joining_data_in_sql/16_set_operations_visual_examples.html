1. Big idea

Set operations combine result sets from SELECT statements. They do not join tables side-by-side. They stack or compare rows.

JOIN = side-by-side using keys.
SET OPERATION = stack or compare SELECT results.

Set operations do not use ON or USING. Each SELECT must return the same number of columns. Matching columns must have compatible data types. Final column names come from the first SELECT.

2. UNION

Meaning:
Returns all rows from both SELECT results and removes exact duplicates.

SQL pattern:

SELECT column1, column2
FROM table_a

UNION

SELECT column1, column2
FROM table_b;

Business examples:

  • Combine 2024 customers and 2025 customers into one unique customer list.
  • Combine students from multiple classes into one consolidated roster, removing duplicates.
  • Combine active vendor lists from two systems and remove repeated vendors.
  • Combine countries from two reports and keep each country once.
  • Combine incident IDs from two monitoring sources without duplicate incidents.

Use when:
You want one clean list and duplicates should be removed.

3. UNION ALL

Meaning:
Returns all rows from both SELECT results and keeps duplicates.

SQL pattern:

SELECT column1, column2
FROM table_a

UNION ALL

SELECT column1, column2
FROM table_b;

Business examples:

  • Combine monthly sales records where repeated transactions must remain.
  • Combine log records from two systems where duplicates may be meaningful.
  • Combine attendance submissions from multiple classes before deduplication.
  • Combine all claim records from multiple feeds for audit review.
  • Combine all leader records when the same person may hold two roles.

Use when:
Duplicates matter or you want raw combined data.

Warning:
UNION ALL can return more rows than UNION because it keeps duplicates.

4. INTERSECT

Meaning:
Returns only rows that appear in both SELECT results.

SQL pattern:

SELECT column1, column2
FROM table_a

INTERSECT

SELECT column1, column2
FROM table_b;

Business examples:

  • Find customers who appear in both CRM and billing.
  • Find students who selected the same room preference list.
  • Find products sold in both online and retail channels.
  • Find country/year pairs that exist in both economies and populations.
  • Find employees present in both HR and payroll extracts.

Use when:
You want what both result sets have in common.

Trap:
INTERSECT compares the full selected row, not just one key column.

5. EXCEPT

Meaning:
Returns rows from the first SELECT result that do not appear in the second SELECT result.

SQL pattern:

SELECT column1, column2
FROM table_a

EXCEPT

SELECT column1, column2
FROM table_b;

Business examples:

  • Find songs a user has not listened to yet.
  • Find customers in CRM but missing from billing.
  • Find city names that are not also country names.
  • Find source records that did not migrate to the target system.
  • Find servers in CMDB that are not reporting telemetry.

Use when:
You want left-side records that are missing from the right side.

Trap:
Order matters. A EXCEPT B is not the same as B EXCEPT A.

6. Quick decision table

QuestionSet operation
Combine two lists and remove duplicates?UNION
Combine two lists and keep duplicates?UNION ALL
Find rows common to both lists?INTERSECT
Find rows in the first list but missing from the second?EXCEPT

8. Interview-safe summary

I use joins when I need to combine related columns from different tables using keys. I use set operations when I need to combine or compare complete SELECT results. UNION removes duplicates, UNION ALL keeps duplicates, INTERSECT keeps only common rows, and EXCEPT returns rows from the first result that are missing from the second.
