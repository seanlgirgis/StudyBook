Terraform 1000-Foot View

This page gives a first mental model for Terraform concepts and safe workflow thinking.

Model Diagram

What Terraform is

Terraform manages infrastructure as code with a desired-state workflow.

The desired-state idea

Configuration defines target end state; Terraform computes required changes.

Providers and resources

Providers connect to platforms. Resources describe managed objects.

Plan and apply

Plan previews blast radius. Apply executes approved changes.

Why state matters

State maps config addresses to real managed objects, enabling safe diffs.

Drift and team safety

Manual out-of-band changes cause drift; teams use review, remote state, locking, and controls.

Safe interview wording

Terraform uses desired-state code, plan review, and controlled apply with state tracking to manage infrastructure safely across teams.

Common traps

  • Calling Terraform just a script runner
  • Skipping plan review
  • Ignoring state sensitivity
  • Overlooking drift risk
