1. Course Big Picture

This course teaches four major ways to combine or compare data: joins, outer-join preservation, set operations, and subqueries.

Need related fields side by side? → JOIN Need unmatched rows preserved? → OUTER JOIN Need compatible rows stacked or compared? → SET OPERATION Need one query to feed another? → SUBQUERY
Core question: what result population do I need, which rows must survive, and what shape should the final result have?

4. Introducing Inner Joins

Basic INNER JOIN

SELECT c.name,
       p.year,
       p.population
FROM countries AS c
INNER JOIN populations AS p
  ON c.code = p.country_code;

ON versus USING

ON

Use when key names differ or the relationship needs several conditions.

USING

Use when both tables share the same key-column name.

Composite relationship

SELECT c.name,
       p.year,
       p.size,
       e.gdp_percapita
FROM countries AS c
INNER JOIN populations AS p
  ON c.code = p.country_code
INNER JOIN economies AS e
  ON c.code = e.country_code
 AND p.year = e.year;
Omitting year can combine values from unrelated periods.

5. Outer, Cross, and Self Joins

LEFT JOIN preservation

SELECT c.name,
       e.year,
       e.gdp_percapita
FROM countries AS c
LEFT JOIN economies AS e
  ON c.code = e.country_code;

ON versus WHERE

A right-side filter in WHERE can remove unmatched left rows. Put the filter in ON when it controls eligible matches but the left population must remain.

FULL JOIN reconciliation

SELECT c.code AS country_code,
       e.country_code AS economy_code
FROM countries AS c
FULL JOIN economies AS e
  ON c.code = e.country_code;

CROSS JOIN size rule

result rows = left rows × right rows

Self join for two years

SELECT p1.country_code,
       p1.size AS size2010,
       p2.size AS size2015
FROM populations AS p1
INNER JOIN populations AS p2
  ON p1.country_code = p2.country_code
 AND p1.year = 2010
 AND p2.year = 2015;
Conditional aggregation may be cleaner than a self join when the task is only to place fixed years side by side.

6. Set Theory for SQL Joins

Set operations align fields by position. Each SELECT must return the same number of fields with compatible data types and logically comparable values.

Operator Behavior
UNIONAppend rows and remove duplicates.
UNION ALLAppend every row and preserve duplicates.
INTERSECTKeep rows present in both results.
EXCEPTKeep rows from the first result absent from the second.

INTERSECT versus INNER JOIN

SELECT name
FROM cities

INTERSECT

SELECT name
FROM countries;

An equivalent inner join may require DISTINCT because joins can reproduce duplicate matches.

Direction matters: A EXCEPT B is not the same as B EXCEPT A.

7. Subqueries, Semi Joins, and Anti Joins

Semi join

SELECT c.name
FROM countries AS c
WHERE EXISTS (
  SELECT 1
  FROM economies AS e
  WHERE e.country_code = c.code
);

Anti join

SELECT c.name
FROM countries AS c
WHERE NOT EXISTS (
  SELECT 1
  FROM economies AS e
  WHERE e.country_code = c.code
);

Scalar subquery

SELECT name,
       population
FROM cities
WHERE population > (
  SELECT AVG(population)
  FROM cities
);

FROM subquery

SELECT region,
       AVG(country_population)
FROM (
  SELECT region,
         population AS country_population
  FROM countries
) AS country_data
GROUP BY region;
Prefer NOT EXISTS to NOT IN when NULL may appear in the inner result.

8. Core SQL Patterns

Preserve the main population

SELECT ...
FROM main_table AS m
LEFT JOIN detail_table AS d
  ON m.key = d.key;

Find missing relationships

SELECT m.key
FROM main_table AS m
WHERE NOT EXISTS (
  SELECT 1
  FROM detail_table AS d
  WHERE d.key = m.key
);

Append all rows

SELECT ...
FROM source_a

UNION ALL

SELECT ...
FROM source_b;

Shared rows

SELECT key
FROM source_a

INTERSECT

SELECT key
FROM source_b;

First-only rows

SELECT key
FROM source_a

EXCEPT

SELECT key
FROM source_b;

9. Common Traps and Corrections

Trap Correction
Joining on only part of a keyInclude every key field, such as entity plus year.
Assuming LEFT JOIN keeps the exact left row countCheck right-side uniqueness and one-to-many matches.
Filtering right fields in WHEREMove match filters into ON when unmatched left rows must remain.
Running CROSS JOIN without estimating sizeCalculate left rows × right rows first.
Self joining without role restrictionsAdd year, role, hierarchy, or inequality conditions.
Using UNION when duplicates matterUse UNION ALL.
Reversing EXCEPTState the first population explicitly.
Using = with a multi-row subqueryUse IN, EXISTS, or reduce the result to one row.
Using NOT IN with possible NULLUse NOT EXISTS.
Forgetting a FROM-subquery aliasAdd AS alias_name.

10. Interview Translation

How do you choose between INNER JOIN and LEFT JOIN? I start from the required output population. If unmatched rows should be excluded, I use INNER JOIN. If every row from the primary population must remain, I use LEFT JOIN.
Why can a join increase row count? One key may match several rows. One-to-many and many-to-many relationships create one output row for each valid combination.
What is a common LEFT JOIN bug? Filtering a right-side field in WHERE can remove NULL-extended rows and produce inner-join behavior.
What is the difference between UNION and UNION ALL? UNION removes duplicate rows. UNION ALL preserves all rows and usually performs less work.
How does INTERSECT differ from INNER JOIN? INTERSECT compares compatible result sets and returns common rows. INNER JOIN matches tables through a condition and may return fields from both sides.
What is a semi join? It keeps rows from the first table when at least one related row exists, without returning fields from the second table.
Why is NOT EXISTS safer than NOT IN? NOT IN can behave unexpectedly when NULL appears in the inner result. NOT EXISTS checks for matching rows directly.
What is a correlated subquery? It is a subquery that references the outer query and is evaluated logically in the context of each outer row.

11. Memory Nuggets

Fifteen quick rules
  1. INNER JOIN keeps matches only.
  2. LEFT JOIN preserves the left population.
  3. FULL JOIN preserves both populations.
  4. CROSS JOIN multiplies row counts.
  5. A self join means one table with multiple roles.
  6. UNION removes duplicates.
  7. UNION ALL preserves duplicates.
  8. INTERSECT means common rows.
  9. EXCEPT means first result minus second result.
  10. IN tests list membership.
  11. EXISTS tests whether a related row exists.
  12. NOT EXISTS is the safest common anti-join pattern.
  13. A scalar subquery must return one value.
  14. A FROM subquery acts like a temporary table.
  15. Always validate row counts after joins.
