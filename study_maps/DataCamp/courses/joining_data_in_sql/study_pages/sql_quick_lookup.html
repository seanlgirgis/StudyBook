2. Join Patterns

INNER JOIN

SELECT ...
FROM table_a AS a
INNER JOIN table_b AS b
  ON a.key = b.key;

Use when unmatched rows should disappear.

Trap: one-to-many matches may increase row count.

LEFT JOIN

SELECT ...
FROM main_table AS m
LEFT JOIN detail_table AS d
  ON m.key = d.key;

Preserves every row from the left table.

Trap: right-side WHERE filters can remove unmatched rows.

RIGHT JOIN

SELECT ...
FROM table_a AS a
RIGHT JOIN table_b AS b
  ON a.key = b.key;

Preserves every row from the right table.

Often clearer as a LEFT JOIN with reversed table order.

FULL JOIN

SELECT ...
FROM table_a AS a
FULL JOIN table_b AS b
  ON a.key = b.key;

Preserves matched and unmatched rows from both sides.

Best for reconciliation; inspect NULLs on both sides.

USING

SELECT ...
FROM table_a AS a
INNER JOIN table_b AS b
  USING (shared_key);

Use when both tables share the same join-column name.

Cannot directly express different key names.

Composite Join

SELECT ...
FROM table_a AS a
JOIN table_b AS b
  ON a.entity_id = b.entity_id
 AND a.period_id = b.period_id;

Use when the real relationship requires several fields.

Omitting period or version may create false combinations.

3. Outer Join Filter Placement

Filter in WHERE — unmatched rows removed

SELECT c.name,
       e.year
FROM countries AS c
LEFT JOIN economies AS e
  ON c.code = e.country_code
WHERE e.year = 2015;

Filter in ON — unmatched left rows preserved

SELECT c.name,
       e.year
FROM countries AS c
LEFT JOIN economies AS e
  ON c.code = e.country_code
 AND e.year = 2015;
Rule: put a right-side condition in ON when it defines which rows may match. Put it in WHERE when you intentionally want to filter the final result.

4. CROSS JOIN and Self Join

CROSS JOIN

SELECT c.code,
       y.year
FROM countries AS c
CROSS JOIN target_years AS y;

Returns every possible combination.

Row count = left rows × right rows.

Self Join

SELECT p1.country_code,
       p1.size AS size2010,
       p2.size AS size2015
FROM populations AS p1
JOIN populations AS p2
  ON p1.country_code = p2.country_code
 AND p1.year = 2010
 AND p2.year = 2015;

One table plays two roles through aliases.

Without role restrictions, every row may pair with every related row.

Conditional Aggregation Alternative

SELECT country_code,
       MAX(size) FILTER (WHERE year = 2010) AS size2010,
       MAX(size) FILTER (WHERE year = 2015) AS size2015
FROM populations
GROUP BY country_code;

Often cleaner for fixed side-by-side reporting periods.

5. Set Operators

UNION

SELECT key FROM source_a
UNION
SELECT key FROM source_b;

Appends rows and removes duplicates.

Duplicate removal compares the complete selected row.

UNION ALL

SELECT key FROM source_a
UNION ALL
SELECT key FROM source_b;

Appends all rows and preserves duplicates.

Use this when row counts and lineage matter.

INTERSECT

SELECT key FROM source_a
INTERSECT
SELECT key FROM source_b;

Returns rows found in both results.

An INNER JOIN may need DISTINCT to match the same result.

EXCEPT

SELECT key FROM source_a
EXCEPT
SELECT key FROM source_b;

Returns first-result rows absent from the second.

Direction matters: A EXCEPT B is not B EXCEPT A.
Compatibility rule: each SELECT must return the same number of fields in the same order with compatible data types.

6. Subqueries

Scalar Subquery in WHERE

SELECT name
FROM cities
WHERE population > (
  SELECT AVG(population)
  FROM cities
);

Inner query must return one value.

Use IN or EXISTS if several rows may return.

Subquery in SELECT

SELECT c.name,
       (
         SELECT COUNT(*)
         FROM cities AS ci
         WHERE ci.country_code = c.code
       ) AS city_count
FROM countries AS c;

Returns one derived scalar value per outer row.

Subquery in FROM

SELECT region,
       AVG(country_population)
FROM (
  SELECT region,
         population AS country_population
  FROM countries
) AS country_data
GROUP BY region;

Creates an intermediate result table.

PostgreSQL requires an alias.

Correlated Subquery

SELECT c.name
FROM countries AS c
WHERE EXISTS (
  SELECT 1
  FROM cities AS ci
  WHERE ci.country_code = c.code
);

References the current row from the outer query.

Forgetting the correlation condition changes the logic completely.

7. Semi Joins and Anti Joins

Semi Join with EXISTS

SELECT c.name
FROM countries AS c
WHERE EXISTS (
  SELECT 1
  FROM economies AS e
  WHERE e.country_code = c.code
);

Anti Join with NOT EXISTS

SELECT c.name
FROM countries AS c
WHERE NOT EXISTS (
  SELECT 1
  FROM economies AS e
  WHERE e.country_code = c.code
);

Anti Join with LEFT JOIN

SELECT c.name
FROM countries AS c
LEFT JOIN economies AS e
  ON c.code = e.country_code
WHERE e.country_code IS NULL;
NULL warning: avoid NOT IN when the inner result may contain NULL. Prefer NOT EXISTS.

8. Validation Patterns

Count duplicate join results

SELECT entity_id,
       period_id,
       COUNT(*) AS joined_rows
FROM joined_result
GROUP BY entity_id,
         period_id
HAVING COUNT(*) > 1;

Find unmatched left rows

SELECT a.key
FROM table_a AS a
LEFT JOIN table_b AS b
  ON a.key = b.key
WHERE b.key IS NULL;

Find unmatched rows on either side

SELECT a.key AS a_key,
       b.key AS b_key
FROM table_a AS a
FULL JOIN table_b AS b
  ON a.key = b.key
WHERE a.key IS NULL
   OR b.key IS NULL;
Always check: source row counts, key uniqueness, output row count, unmatched rows, duplicate growth, and whether time/version belongs in the join key.
