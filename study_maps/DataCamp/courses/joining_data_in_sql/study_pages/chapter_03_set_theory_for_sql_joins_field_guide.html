Set Theory for SQL Joins

1. Big Picture

Set operations combine the rows returned by separate SELECT statements. Unlike joins, they do not add related columns side by side. They stack, compare, or subtract compatible result sets.

First SELECT result ↓ Set operator ↓ Second SELECT result ↓ One combined result set

UNION

Append rows and remove duplicates.

UNION ALL

Append every row and preserve duplicates.

INTERSECT

Keep rows found in both results.

EXCEPT

Keep first-result rows not found in the second.

Chapter punchline: joins combine columns horizontally; set operations combine compatible rows vertically.

2. Joins versus Set Operations

Feature Join Set operation
Main direction Horizontal Vertical
Combines Columns from related rows Rows from separate query results
Main requirement A relationship condition such as ON Compatible selected columns
Typical question Bring related attributes together Combine, compare, or subtract result sets
JOIN countries + economies → country fields beside economy fields SET OPERATION country codes from economies UNION country codes from populations → one longer list of country codes
Set operations do not need a foreign-key relationship. They need compatible output shapes.

3. Set Compatibility Rules

Each SELECT participating in a set operation must return the same number of columns in the same order, with compatible data types.

Compatible result shapes

SELECT country_code,
       year
FROM economies

UNION

SELECT country_code,
       year
FROM populations;

Incompatible column counts

SELECT country_code,
       year,
       gdp_percapita
FROM economies

UNION

SELECT country_code,
       year
FROM populations;
Rule Meaning
Same number of columns Every SELECT must return the same number of expressions.
Same positional meaning The first field aligns with the first, the second with the second, and so on.
Compatible data types Fields in the same position must be comparable or convertible.
Output names The final result normally takes its field names from the first SELECT.
Memory rule: set operations align fields by position, not by name.

4. UNION

UNION stacks the rows returned by two queries and removes duplicate rows from the combined result. 

SELECT country_code
FROM economies

UNION

SELECT country_code
FROM populations;
First query: USA, CAN, MEX Second query: USA, BRA UNION: USA, CAN, MEX, BRA

Combine two years

SELECT country_code,
       year
FROM economies
WHERE year = 2010

UNION

SELECT country_code,
       year
FROM economies
WHERE year = 2015;
Duplicate rule: UNION compares the entire selected row. Two rows are duplicates only when all selected values match.

5. UNION ALL

UNION ALL stacks all rows and does not remove duplicates. 

SELECT country_code
FROM economies

UNION ALL

SELECT country_code
FROM populations;
First query: USA, CAN, MEX Second query: USA, BRA UNION ALL: USA, CAN, MEX, USA, BRA

Why UNION ALL is often preferred

  • It preserves every source row.
  • It avoids accidental deduplication.
  • It usually performs less work.
  • It is appropriate for event, audit, transaction, and append-style datasets.
Engineering habit: ask whether duplicate removal is truly required. If not, use UNION ALL.

6. UNION versus UNION ALL

Feature UNION UNION ALL
Duplicates Removed Preserved
Typical performance More work because duplicates must be detected Usually faster
Typical use Create a distinct combined list Append complete datasets
Row count Less than or equal to the combined inputs Exactly the sum of both result counts
Duplicate removal applies to the complete row, not to one chosen field.

7. INTERSECT

INTERSECT returns rows present in both query results. 

SELECT country_code
FROM economies

INTERSECT

SELECT country_code
FROM populations;
First query: USA, CAN, MEX Second query: USA, BRA, CAN INTERSECT: USA, CAN

Compare country-year availability

SELECT country_code,
       year
FROM economies

INTERSECT

SELECT country_code,
       year
FROM populations;

This returns only country-year combinations that exist in both sources.

Use case: identify the shared key universe before joining or comparing measures.

8. EXCEPT

EXCEPT returns rows from the first query that do not appear in the second query. The direction matters. 

SELECT country_code
FROM economies

EXCEPT

SELECT country_code
FROM populations;
First query: USA, CAN, MEX Second query: USA, BRA First EXCEPT second: CAN, MEX Second EXCEPT first: BRA

Find economy records missing from populations

SELECT country_code,
       year
FROM economies

EXCEPT

SELECT country_code,
       year
FROM populations;
Direction rule: A EXCEPT B is not the same as B EXCEPT A.

9. Ordering a Set Result

A final ORDER BY applies to the complete combined result and normally appears after the final SELECT. 

SELECT country_code,
       year
FROM economies

UNION

SELECT country_code,
       year
FROM populations

ORDER BY country_code,
         year;

Use the output name from the first SELECT

SELECT country_code AS code
FROM economies

UNION

SELECT country_code
FROM populations

ORDER BY code;
Never assume the output order of a set operation unless you add a final ORDER BY.

10. Choosing the Correct Set Operator

Business requirement Operator Reason
Combine two lists without repeated rows UNION Duplicates are removed.
Append every row from two extracts UNION ALL All source rows are preserved.
Find rows present in both datasets INTERSECT Only shared rows remain.
Find first-source rows absent from the second EXCEPT The second result is subtracted from the first.
Decision shortcut: all rows → UNION ALL; unique combined rows → UNION; common rows → INTERSECT; first-only rows → EXCEPT.

11. Common Mistakes

Using different field counts Every SELECT must return the same number of fields.
Assuming fields align by name Set operations align fields by position.
Using UNION when duplicates are meaningful UNION may remove valid repeated rows. Use UNION ALL when preservation matters.
Assuming UNION ALL removes duplicates UNION ALL preserves every row returned by both queries.
Reversing EXCEPT The first query defines the population from which rows are removed.
Expecting a guaranteed order Add a final ORDER BY to sort the complete set result.
Combining unrelated fields merely because their types match Compatible data types do not guarantee compatible business meaning.

12. Interview Translation

What is the difference between UNION and UNION ALL? UNION combines compatible query results and removes duplicate rows. UNION ALL preserves every row and is generally faster because it avoids duplicate elimination.
How do set operations differ from joins? Joins combine related columns horizontally. Set operations append or compare compatible rows vertically.
What does INTERSECT do? It returns rows that appear in both query results.
What does EXCEPT do? It returns rows from the first query that do not appear in the second, so query order matters.
What must be compatible in a set operation? The SELECT statements must return the same number of fields in the same positional order with compatible data types.
Why is UNION ALL common in data engineering? It preserves row counts and lineage, avoids accidental deduplication, and normally requires less processing.

13. Memory Review

Six-sentence chapter summary
  1. Set operations combine compatible query results vertically.
  2. UNION removes duplicate rows.
  3. UNION ALL preserves every row.
  4. INTERSECT keeps rows found in both results.
  5. EXCEPT keeps first-query rows absent from the second.
  6. Field count, order, meaning, and compatible types must align.
