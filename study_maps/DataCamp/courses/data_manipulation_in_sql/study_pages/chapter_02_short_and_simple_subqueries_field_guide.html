2. Big Picture

A subquery is a query nested inside another query. The inner query produces a result, and the outer query uses that result.

inner query ↓ returns one value, a list, or a table ↓ outer query ↓ filters, joins, or calculates

WHERE

Use an inner result to decide which outer rows survive.

FROM

Use an inner query as a temporary derived table.

SELECT

Add a scalar result as a column in the outer output.

Shape first

Determine whether the inner query returns one value, one column, or a table.

Chapter punchline: choose the subquery location by how the outer query needs to use the inner result.

3. Scalar Subqueries in WHERE

A scalar subquery returns exactly one value and works with operators such as =, >, and <.

SELECT date,
       home_goal,
       away_goal
FROM match
WHERE home_goal > (
    SELECT AVG(home_goal)
    FROM match
);

The inner query returns one average. The outer query compares every row to that value.

Trap: a scalar operator fails when the inner query returns more than one row.

4. Filtering with a List Subquery

A list subquery returns one column with multiple rows. Use it with IN, NOT IN, ANY, or ALL.

SELECT team_long_name
FROM team
WHERE team_api_id IN (
    SELECT hometeam_id
    FROM match
    WHERE home_goal >= 8
);

The inner query returns team IDs; the outer query retrieves their names.

NULL warning: NOT IN can produce unexpected results when the inner list contains NULL.

5. More Complex Subquery Conditions

Subqueries can calculate a benchmark and combine it with an outer expression.

SELECT date,
       home_goal,
       away_goal
FROM match
WHERE (home_goal + away_goal) > (
    SELECT 3 * AVG(home_goal + away_goal)
    FROM match
);

This identifies matches whose total goals exceeded three times the overall average.

ANY and ALL

OperatorMeaningTypical idea
> ANY (...)Greater than at least one returned valueAbove the minimum of the set
> ALL (...)Greater than every returned valueAbove the maximum of the set
= ANY (...)Equal to at least one returned valueSimilar to IN

6. Subqueries in FROM

A subquery in FROM becomes a temporary derived table. It must have an alias.

SELECT country,
       AVG(matches_played) AS avg_matches
FROM (
    SELECT c.name AS country,
           m.season,
           COUNT(m.id) AS matches_played
    FROM country AS c
    LEFT JOIN match AS m
      ON c.id = m.country_id
    GROUP BY c.name, m.season
) AS season_counts
GROUP BY country;
What to notice: the inner query aggregates by country and season; the outer query aggregates those results again by country.

7. Joining Derived Tables

A FROM subquery can be joined to a regular table or another derived table.

SELECT c.name AS country,
       s.avg_goals
FROM country AS c
LEFT JOIN (
    SELECT country_id,
           AVG(home_goal + away_goal) AS avg_goals
    FROM match
    GROUP BY country_id
) AS s
  ON c.id = s.country_id;
Good pattern: pre-aggregate a large fact table, then join the smaller summary to descriptive data.

8. Subqueries in SELECT

A subquery in SELECT normally must return one scalar value.

SELECT c.name AS country,
       (
           SELECT COUNT(*)
           FROM match
       ) AS total_matches
FROM country AS c;

The total is repeated for every outer row because the inner query is independent of the country.

Performance note: correlated SELECT subqueries may execute once per outer row. Chapter 3 explores that pattern.

9. SELECT Subqueries for Calculations

A scalar subquery can provide a global benchmark beside a grouped outer result.

SELECT c.name AS country,
       AVG(m.home_goal + m.away_goal) AS country_avg,
       (
           SELECT AVG(home_goal + away_goal)
           FROM match
       ) AS overall_avg,
       AVG(m.home_goal + m.away_goal)
       - (
           SELECT AVG(home_goal + away_goal)
           FROM match
         ) AS difference
FROM country AS c
LEFT JOIN match AS m
  ON c.id = m.country_id
GROUP BY c.name;
Pattern: local aggregate − global aggregate = difference from benchmark.

10. Best Practices

PracticeReason
Run the inner query firstConfirm its row count, columns, and shape.
Indent nested queries clearlyMakes query boundaries visible.

Avoid unnecessary nestingDeep nesting becomes difficult to test and maintain.

11. Worked Example

Return country-season averages that exceeded the overall match average.

SELECT country,
       season,
       avg_goals
FROM (
    SELECT c.name AS country,
           m.season,
           AVG(m.home_goal + m.away_goal) AS avg_goals
    FROM country AS c
    INNER JOIN match AS m
      ON c.id = m.country_id
    GROUP BY c.name, m.season
) AS country_season
WHERE avg_goals > (
    SELECT AVG(home_goal + away_goal)
    FROM match
)
ORDER BY avg_goals DESC;
Why it works: the FROM subquery creates country-season rows, while the WHERE subquery supplies one global benchmark.

12. Common Mistakes

Using = with multiple rowsUse IN when the inner query returns a list.
Forgetting the FROM-subquery aliasEvery derived table should have a clear alias.
Returning too many columnsA scalar or list subquery generally returns one column; a SELECT subquery must return one value.
Using NOT IN without handling NULLFilter NULLs inside the subquery or use a safer anti-join pattern.
Nesting before testingExecute the inner query independently first.
Repeating an expensive subqueryConsider a derived table, join, or CTE when the same calculation is reused.

13. Interview Translation

What is a subquery?A query nested inside another query whose result is consumed as a scalar value, a list, or a derived table.
When do you use one in WHERE?When filtering depends on a value or set calculated by another query, such as a global average or a list of IDs.
When do you use one in FROM?When data must be transformed or aggregated first and then queried as an intermediate table.
What is the risk of a SELECT subquery?It must return one value, and correlated forms may execute repeatedly for outer rows.
How do you debug nested SQL?Validate the innermost query first, then add one outer layer at a time.

14. Memory Review

Chapter summary
  1. A scalar subquery returns one value.
  2. A list subquery returns one column with many rows.
  3. A FROM subquery returns a temporary table.
  4. A SELECT subquery normally returns one value.
  5. = expects one value; IN accepts a list.
  6. Test the inner query before nesting it.

Quick self-check

  • Can you predict whether the inner query returns one value, a list, or a table?
  • Can you filter rows above an overall average?
  • Can you join a pre-aggregated FROM subquery?
  • Can you add a global benchmark through SELECT?
  • Can you explain the NULL risk with NOT IN?
