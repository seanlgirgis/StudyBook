2. Big Picture

This chapter compares three ways to build complex SQL: correlate an inner query to the current outer row, nest one query inside another, or name intermediate steps with CTEs.

Need a value related to the current outer row? ↓ correlated subquery Need one result to feed another result? ↓ nested subquery Need readable, named stages? ↓ CTE

Correlated subquery

References a column from the outer query and may run once per outer row.

Nested subquery

Contains multiple query levels where one inner result feeds another.

CTE

Names an intermediate query so the final statement reads like a sequence of steps.

Decision point

Choose clarity first, then validate performance and correctness.

Chapter punchline: correlated queries solve row-by-row comparisons, nested queries compose results, and CTEs make multi-step logic easier to read and maintain.

3. Correlated Subqueries

A correlated subquery references a column from the outer query. The inner query cannot run independently because it depends on the current outer row.

SELECT
    m1.country_id,
    m1.date,
    m1.home_goal,
    m1.away_goal
FROM match AS m1
WHERE (m1.home_goal + m1.away_goal) > (
    SELECT AVG(m2.home_goal + m2.away_goal)
    FROM match AS m2
    WHERE m2.country_id = m1.country_id
);

For each match, the inner query calculates the average total goals for that match's country.

What to notice: m1.country_id comes from the outer query. That outer reference creates the correlation.

4. Correlated Subqueries with Multiple Conditions

Correlation can depend on more than one outer value, such as country and season.

SELECT
    m1.country_id,
    m1.season,
    m1.date,
    m1.home_goal,
    m1.away_goal
FROM match AS m1
WHERE (m1.home_goal + m1.away_goal) > (
    SELECT AVG(m2.home_goal + m2.away_goal)
    FROM match AS m2
    WHERE m2.country_id = m1.country_id
      AND m2.season = m1.season
);

Each row is compared with the average for its own country and season.

Performance caution: a correlated subquery may execute repeatedly. On large data, a grouped join or window function can be more efficient.

5. Nested Subqueries

A nested subquery has more than one inner level. The deepest query runs first, then its result is consumed by the next level.

SELECT
    country_id,
    date,
    home_goal,
    away_goal
FROM match
WHERE country_id IN (
    SELECT id
    FROM country
    WHERE name IN (
        SELECT name
        FROM country
        WHERE continent = 'Europe'
    )
);
deepest query ↓ middle query ↓ outer query
Debugging rule: test the innermost query first, then test each containing layer.

6. Nesting a Subquery in FROM

A FROM subquery can itself contain another subquery.

SELECT
    country,
    avg_goals
FROM (
    SELECT
        c.name AS country,
        AVG(m.home_goal + m.away_goal) AS avg_goals
    FROM country AS c
    INNER JOIN match AS m
      ON c.id = m.country_id
    WHERE m.season IN (
        SELECT DISTINCT season
        FROM match
        WHERE season >= '2012/2013'
    )
    GROUP BY c.name
) AS country_summary
WHERE avg_goals > 2.5;

The inner list subquery filters seasons, the derived table calculates country averages, and the outer query filters those averages.

7. Common Table Expressions

A CTE is a named query defined with WITH. It exists only for the duration of the statement.

WITH country_averages AS (
    SELECT
        country_id,
        AVG(home_goal + away_goal) AS avg_goals
    FROM match
    GROUP BY country_id
)
SELECT
    c.name,
    ca.avg_goals
FROM country AS c
INNER JOIN country_averages AS ca
  ON c.id = ca.country_id;
Why CTEs help: they separate preparation logic from the final query and give intermediate results meaningful names.

8. Organizing with Multiple CTEs

Multiple CTEs are separated by commas and can form a readable pipeline.

WITH season_matches AS (
    SELECT *
    FROM match
    WHERE season = '2013/2014'
),
league_averages AS (
    SELECT
        country_id,
        AVG(home_goal + away_goal) AS avg_goals
    FROM season_matches
    GROUP BY country_id
),
overall_average AS (
    SELECT
        AVG(home_goal + away_goal) AS avg_goals
    FROM season_matches
)
SELECT
    c.name,
    l.avg_goals,
    o.avg_goals AS overall_avg,
    l.avg_goals - o.avg_goals AS difference
FROM league_averages AS l
INNER JOIN country AS c
  ON c.id = l.country_id
CROSS JOIN overall_average AS o;
Pipeline: filter once → aggregate by league → calculate overall benchmark → compare.

9. CTEs with Nested Subqueries

CTEs and subqueries can be combined. A CTE can contain a subquery, and the final query can also contain one.

WITH high_scoring_matches AS (
    SELECT
        country_id,
        date,
        home_goal,
        away_goal
    FROM match
    WHERE (home_goal + away_goal) > (
        SELECT AVG(home_goal + away_goal)
        FROM match
    )
)
SELECT
    c.name,
    COUNT(h.date) AS high_scoring_matches
FROM country AS c
LEFT JOIN high_scoring_matches AS h
  ON c.id = h.country_id
GROUP BY c.name;

The scalar subquery calculates one threshold; the CTE names the filtered set; the final query summarizes it.

10. Choosing the Technique

NeedBest starting choiceReason
Compare each row with its own groupCorrelated subqueryThe inner query depends on the outer row.
Feed one result into anotherNested subqueryThe query naturally has inner-to-outer layers.
Build several readable stagesCTEEach stage receives a meaningful name.
Reuse the same logical resultCTE or derived tableAvoid duplicating the same nested logic.
Need row-by-row group statistics at scaleWindow function or grouped joinOften clearer and potentially more efficient.
Practical rule: use the simplest form that clearly expresses the logic, then inspect the execution plan when performance matters.

11. Worked Example: Team Names Three Ways

Uncorrelated subquery

SELECT team_long_name
FROM team
WHERE team_api_id IN (
    SELECT hometeam_id
    FROM match
    WHERE home_goal >= 8
);

Correlated subquery with EXISTS

SELECT
    t.team_long_name
FROM team AS t
WHERE EXISTS (
    SELECT 1
    FROM match AS m
    WHERE m.hometeam_id = t.team_api_id
      AND m.home_goal >= 8
);

CTE

WITH high_scoring_home_teams AS (
    SELECT DISTINCT hometeam_id
    FROM match
    WHERE home_goal >= 8
)
SELECT
    t.team_long_name
FROM team AS t
INNER JOIN high_scoring_home_teams AS h
  ON t.team_api_id = h.hometeam_id;
Result: all three can return the same teams. The best choice depends on readability, reuse, and the database optimizer.

12. Validation and Troubleshooting

  • Run each CTE body or inner query separately.
  • Confirm whether a correlated subquery returns one row or many rows for each outer row.
  • Check that outer aliases are referenced intentionally inside correlated subqueries.
  • Compare result counts between equivalent subquery, CTE, and join solutions.
  • Inspect for accidental duplicate rows after joining summarized results.
  • Use EXPLAIN or EXPLAIN ANALYZE when performance matters.
Red flag: if an inner query cannot run independently, it is correlated. If that was not intentional, check alias references.

13. Common Mistakes

Forgetting the outer referenceA correlated subquery becomes uncorrelated and may compare every row to the same global result.
Using ambiguous aliasesUse clear outer and inner aliases such as m1 and m2.
Returning multiple rows to a scalar comparisonEnsure the correlated subquery aggregates or otherwise returns one value per outer row.
Deep nesting without testing layersValidate the innermost query first.
Assuming a CTE is automatically fasterCTEs mainly improve structure and readability; performance depends on the engine and plan.
Repeating the same filtering logic in several CTEsCreate one base CTE and build later steps from it.
Using a correlated subquery when a window function is clearerFor per-group averages or rankings, Chapter 4 techniques may be better.

14. Interview Translation

What is a correlated subquery?A correlated subquery references values from the outer query, so its result is evaluated in the context of each outer row.
How is it different from a normal subquery?An uncorrelated subquery can run independently. A correlated subquery depends on an outer alias or value.
What is a nested subquery?It is a query with multiple levels of nesting where one inner result feeds another query level.
Why use a CTE?I use a CTE to name intermediate logic, break a complex query into stages, and make testing and maintenance easier.
Are CTEs always faster?No. Their main benefit is readability. I compare execution plans when performance is important.
When would you avoid a correlated subquery?When it repeatedly scans a large table and the same result can be produced more clearly with a grouped join or window function.
