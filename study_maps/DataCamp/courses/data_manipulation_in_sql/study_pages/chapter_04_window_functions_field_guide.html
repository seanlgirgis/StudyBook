2. Big Picture

A regular aggregate collapses many rows into fewer rows. A window function calculates across related rows while preserving every original row.

detail rows ↓ window definition with OVER(...) ↓ calculate across a group or frame ↓ return one result per original row

OVER()

Turns an aggregate or ranking function into a window calculation.

PARTITION BY

Restarts the calculation for each logical group.

ORDER BY

Defines sequence inside the window.

Frame clause

Defines which neighboring rows contribute to the current row's result.

Chapter punchline: window functions add group-level context to detail rows without losing those rows.

3. The OVER Clause

OVER() tells SQL to calculate across a window of rows rather than collapse them with GROUP BY.

SELECT
    date,
    home_goal,
    away_goal,
    AVG(home_goal + away_goal) OVER () AS overall_avg
FROM match;

The overall average appears beside each match row.

Compare with GROUP BY

ApproachOutput shapeUse case
GROUP BYOne row per groupSummary report
OVER()One row per original rowDetail plus group context
What to notice: the window result repeats because the row grain is preserved.

4. OVER with PARTITION BY

PARTITION BY divides the result set into groups and restarts the window calculation for each group.

SELECT
    country_id,
    date,
    home_goal,
    away_goal,
    AVG(home_goal + away_goal)
      OVER (PARTITION BY country_id) AS country_avg
FROM match;

Every match retains its own values while also showing the average for its country.

Memory rule: GROUP BY reduces rows; PARTITION BY labels rows with a group calculation.

5. PARTITION BY Multiple Columns

You can partition by more than one column when the comparison group has multiple dimensions.

SELECT
    country_id,
    season,
    date,
    home_goal,
    away_goal,
    AVG(home_goal + away_goal)
      OVER (PARTITION BY country_id, season) AS country_season_avg
FROM match;

This restarts the average for every country-season combination.

Trap: adding more partition columns makes groups smaller. Confirm that the group definition matches the business question.

6. Sliding Windows

A frame clause narrows an ordered partition to a moving subset around the current row.

SELECT
    date,
    home_goal,
    SUM(home_goal) OVER (
        ORDER BY date
        ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
    ) AS three_match_running_total
FROM match;

Each row sees itself and the two previous rows in date order.

Common frame boundaries

BoundaryMeaning
UNBOUNDED PRECEDINGStart at the first row in the partition
n PRECEDINGInclude n earlier rows
CURRENT ROWUse the current row as a boundary
n FOLLOWINGInclude n later rows
UNBOUNDED FOLLOWINGContinue to the last row in the partition

7. Slide to the Left and Right

Previous rows only

AVG(home_goal) OVER (
    ORDER BY date
    ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
)

Centered window

AVG(home_goal) OVER (
    ORDER BY date
    ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING
)

Forward-looking window

AVG(home_goal) OVER (
    ORDER BY date
    ROWS BETWEEN CURRENT ROW AND 2 FOLLOWING
)
Order matters: a sliding frame without a meaningful ORDER BY has no reliable sequence.

8. Setting Up the Home-Team CTE

The final exercise begins by normalizing home-team results into a team-centered shape.

WITH home AS (
    SELECT
        m.id,
        m.date,
        m.season,
        m.hometeam_id AS team_id,
        t.team_long_name AS team,
        m.home_goal AS goals_for,
        m.away_goal AS goals_against
    FROM match AS m
    LEFT JOIN team AS t
      ON m.hometeam_id = t.team_api_id
)
SELECT *
FROM home;

The home CTE renames match columns into team-oriented fields.

9. Setting Up the Away-Team CTE

The away-team CTE produces the same column layout so both sets can be combined.

WITH away AS (
    SELECT
        m.id,
        m.date,
        m.season,
        m.awayteam_id AS team_id,
        t.team_long_name AS team,
        m.away_goal AS goals_for,
        m.home_goal AS goals_against
    FROM match AS m
    LEFT JOIN team AS t
      ON m.awayteam_id = t.team_api_id
)
SELECT *
FROM away;
Design rule: set operations are easiest when both queries return the same columns in the same order and compatible types.

10. Putting the CTEs Together

Use UNION ALL to stack home and away appearances into one team-match dataset.

WITH home AS (
    SELECT
        m.id,
        m.date,
        m.season,
        m.hometeam_id AS team_id,
        t.team_long_name AS team,
        m.home_goal AS goals_for,
        m.away_goal AS goals_against
    FROM match AS m
    LEFT JOIN team AS t
      ON m.hometeam_id = t.team_api_id
),
away AS (
    SELECT
        m.id,
        m.date,
        m.season,
        m.awayteam_id AS team_id,
        t.team_long_name AS team,
        m.away_goal AS goals_for,
        m.home_goal AS goals_against
    FROM match AS m
    LEFT JOIN team AS t
      ON m.awayteam_id = t.team_api_id
),
team_matches AS (
    SELECT * FROM home
    UNION ALL
    SELECT * FROM away
)
SELECT *
FROM team_matches;
Why UNION ALL: home and away appearances are distinct records; duplicate removal is not needed.

11. Add a Window Function

Once the team-centered data is assembled, window functions can calculate running totals and team-level averages.

WITH home AS (...),
away AS (...),
team_matches AS (
    SELECT * FROM home
    UNION ALL
    SELECT * FROM away
)
SELECT
    team,
    season,
    date,
    goals_for,
    SUM(goals_for) OVER (
        PARTITION BY team_id, season
        ORDER BY date
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS running_goals,
    AVG(goals_for) OVER (
        PARTITION BY team_id, season
    ) AS season_avg_goals
FROM team_matches
ORDER BY team, season, date;
What this gives you: one row per team appearance, plus cumulative goals and season-average goals.

12. Worked Example

Calculate each match's total goals, the country-season average, and a three-match moving average.

SELECT
    country_id,
    season,
    date,
    home_goal + away_goal AS total_goals,
    AVG(home_goal + away_goal) OVER (
        PARTITION BY country_id, season
    ) AS country_season_avg,
    AVG(home_goal + away_goal) OVER (
        PARTITION BY country_id, season
        ORDER BY date
        ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
    ) AS moving_avg_3
FROM match
ORDER BY country_id, season, date;
Result: detail rows remain intact while each row receives both a full-partition benchmark and a local moving average.

13. Validation and Troubleshooting

  • Check that the result row count still matches the detail source unless joins or set operations intentionally changed it.
  • Verify partition columns match the intended business group.
  • Confirm the window ORDER BY is deterministic; add a tie-breaker when dates can repeat.
  • Inspect the first few rows of each partition because partial frames contain fewer rows.
  • Compare a window aggregate with a separate grouped query to validate totals.
  • Use UNION ALL when stacking distinct home and away appearances.
Red flag: if a running value appears to jump unpredictably, check ordering, duplicate sort values, and accidental row multiplication before the window step.

14. Common Mistakes

Using GROUP BY when detail rows are neededUse a window function to keep the original row grain.
Forgetting OVERAn aggregate without OVER is a regular aggregate and may require grouping.
Confusing PARTITION BY with GROUP BYPARTITION BY defines calculation groups but does not collapse rows.
Omitting ORDER BY for a running totalRunning and moving calculations require a sequence.
Relying on non-unique order columnsAdd a second ordering column such as match ID when dates tie.
Ignoring frame defaultsState the frame explicitly when the intended behavior matters.
Using UNION instead of UNION ALLUNION removes duplicates and adds unnecessary work when stacking home and away records.

15. Interview Translation

What is a window function?A window function calculates across related rows while preserving one output row for each input row.
How is PARTITION BY different from GROUP BY?GROUP BY reduces rows to one per group. PARTITION BY defines a group for a window calculation but keeps the detail rows.
What does ORDER BY do inside OVER?It defines row sequence for ranking, running totals, and moving calculations.
What is a window frame?A frame defines the subset of ordered rows around the current row that contributes to the calculation.
How do you calculate a running total?I use SUM(value) OVER (PARTITION BY ... ORDER BY ... ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW).
When would you prefer a window function to a correlated subquery?When I need per-group calculations on every detail row, because the window form is often clearer and may avoid repeated row-by-row subqueries.
