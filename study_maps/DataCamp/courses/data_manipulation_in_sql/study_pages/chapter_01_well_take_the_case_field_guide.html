2. Big Picture

A CASE expression is SQL's way of applying conditional logic inside a query. It evaluates conditions from top to bottom and returns the result associated with the first true condition.

row ↓ evaluate WHEN conditions from top to bottom ↓ first true condition → return its THEN result ↓ no match → return ELSE result ↓ new derived value in the result set

Create categories

Convert numeric or text values into labels such as win, loss, draw, high, medium, or low.

Create flags

Return 1 or 0 to make later counting, summing, and averaging easy.

Conditional aggregation

Count or sum only rows that meet a condition without removing other rows from the group.

Fractions and percentages

Use AVG over a 1/0 flag or divide conditional counts by total counts.

Chapter punchline: Use CASE to classify rows first; then combine it with aggregates to summarize those classifications.

3. Basic CASE Statements

The searched form of CASE is the most flexible form because each WHEN can contain a full Boolean condition. 

SELECT
    match_id,
    CASE
        WHEN home_goal > away_goal THEN 'Home win'
        WHEN home_goal < away_goal THEN 'Away win'
        ELSE 'Draw'
    END AS result
FROM matches;
What to notice: CASE does not create a table or permanently change data. It creates a derived value in the query result.

Simple CASE versus searched CASE

Form Best for Example
Simple CASE Comparing one expression to fixed values CASE status WHEN 'A' THEN ...
Searched CASE Ranges, multiple columns, and compound conditions CASE WHEN score > 10 THEN ...

4. Comparing Column Values

A powerful use of CASE is comparing two columns from the same row. In soccer data, comparing home and away goals lets you label a match outcome. 

SELECT
    date,
    hometeam_id,
    awayteam_id,
    CASE
        WHEN home_goal > away_goal THEN hometeam_id
        WHEN home_goal < away_goal THEN awayteam_id
        ELSE NULL
    END AS winner_team_id
FROM match;
Common trap: The output data types of all THEN branches and the ELSE branch must be compatible. Avoid mixing integers and text unless you cast deliberately.

Condition order matters

CASE
    WHEN score >= 90 THEN 'A'
    WHEN score >= 80 THEN 'B'
    WHEN score >= 70 THEN 'C'
    ELSE 'Below C'
END

The most specific or highest-threshold condition must appear first. Once a condition is true, later branches are ignored.

5. More Complex CASE Logic

Conditions can combine multiple columns with AND, OR, and parentheses. 

SELECT
    match_id,
    CASE
        WHEN home_team = 'Team A'
             AND home_goal > away_goal THEN 'Team A home win'
        WHEN away_team = 'Team A'
             AND away_goal > home_goal THEN 'Team A away win'
        WHEN home_team = 'Team A'
             OR away_team = 'Team A' THEN 'Team A did not win'
        ELSE 'Team A not involved'
    END AS team_a_result
FROM matches;
What to notice: Parentheses make mixed AND/OR logic easier to read and protect against precedence mistakes.

Rivalry pattern

CASE
    WHEN hometeam_id = 101 AND awayteam_id = 202 THEN 'Rivalry'
    WHEN hometeam_id = 202 AND awayteam_id = 101 THEN 'Rivalry'
    ELSE 'Other match'
END

The same logical relationship may appear in either column order. When the order should not matter, cover both arrangements.

6. Filtering Your CASE Statement

CASE changes values; WHERE removes rows. They solve different problems and are often used together. 

SELECT
    date,
    CASE
        WHEN home_goal > away_goal THEN 'Home win'
        WHEN home_goal < away_goal THEN 'Away win'
        ELSE 'Draw'
    END AS result
FROM matches
WHERE season = '2013/2014';

Use WHERE when...

You do not want nonmatching rows included in the result at all.

Use CASE when...

You want to retain rows but label or measure them differently.

Important distinction: A condition inside CASE is not automatically a filter. Rows remain unless the WHERE clause excludes them.

7. CASE WHEN with Aggregate Functions

Conditional aggregation lets one grouped query calculate several metrics at once. The most common patterns use COUNT, SUM, and AVG.

COUNT using CASE WHEN

SELECT
    season,
    COUNT(CASE
              WHEN home_goal > away_goal THEN 1
          END) AS home_wins
FROM matches
GROUP BY season;

COUNT(expression) ignores NULL. The expression returns 1 for matching rows and NULL otherwise.

SUM using CASE WHEN

SELECT
    season,
    SUM(CASE
            WHEN home_goal > away_goal THEN 1
            ELSE 0
        END) AS home_wins
FROM matches
GROUP BY season;

This pattern explicitly contributes 1 for a match and 0 for a nonmatch.

Conditional sums of values

SELECT
    season,
    SUM(CASE
            WHEN home_goal > away_goal THEN home_goal
            ELSE 0
        END) AS goals_in_home_wins
FROM matches
GROUP BY season;

AVG to derive a fraction

SELECT
    season,
    AVG(CASE
            WHEN home_goal > away_goal THEN 1.0
            ELSE 0.0
        END) AS home_win_fraction
FROM matches
GROUP BY season;

Because the average of 1s and 0s is the proportion of 1s, this returns the fraction of matches won by the home team.

Memory shortcut: SUM(flag) gives the count; AVG(flag) gives the fraction.

8. Worked Example

Produce one row per season with total matches, counts by outcome, and the percentage of home wins. 

SELECT
    season,
    COUNT(*) AS total_matches,

    SUM(CASE
            WHEN home_goal > away_goal THEN 1
            ELSE 0
        END) AS home_wins,

    SUM(CASE
            WHEN home_goal < away_goal THEN 1
            ELSE 0
        END) AS away_wins,

    SUM(CASE
            WHEN home_goal = away_goal THEN 1
            ELSE 0
        END) AS draws,

    ROUND(
        100.0 * AVG(
            CASE
                WHEN home_goal > away_goal THEN 1.0
                ELSE 0.0
            END
        ),
        2
    ) AS home_win_pct
FROM matches
GROUP BY season
ORDER BY season;
Result: The query keeps every match, groups by season, derives several conditional metrics, and calculates a percentage without a separate subquery.

9. Validation and Troubleshooting

  • Check that outcome counts add up to COUNT(*).
  • Verify that the percentage stays between 0 and 100.
  • Use decimal values such as 1.0 or multiply by 100.0 to avoid integer-division surprises.
  • Confirm that nullable goal columns are handled as intended.
  • Temporarily select the raw columns beside the CASE output to inspect row-level classification.
Red flag: If category totals do not reconcile with the total row count, a condition may overlap, omit a case, or mishandle NULL.

10. Common Mistakes

Forgetting END Every CASE expression must close with END, normally followed by an alias.
Putting broad conditions first A broad branch can capture rows before a more precise branch gets a chance. Order conditions from most specific to least specific.
Assuming CASE filters rows CASE derives values. Use WHERE when rows must be removed.
Using COUNT with ELSE 0 COUNT counts both 1 and 0 because both are non-NULL. For COUNT(CASE ...), omit ELSE or return NULL.
Integer division Dividing integers may truncate the result in some SQL systems. Force a decimal with 1.0, 100.0, or an explicit cast.
Mixing incompatible result types All branches should return compatible types. Use explicit casting when a consistent output type is needed.

11. Interview Translation

What is a CASE expression? A CASE expression applies conditional logic inside SQL and returns one value based on the first true condition. I use it for categorization, flags, and conditional metrics.
How do you perform conditional aggregation? I place a CASE expression inside an aggregate. For example, SUM(CASE WHEN condition THEN 1 ELSE 0 END) counts matching rows while preserving the grouping context.
What is the difference between WHERE and CASE? WHERE filters rows before aggregation, while CASE keeps rows and assigns conditional values that can later be selected or aggregated.
How can AVG calculate a percentage? I return 1.0 for rows that meet the condition and 0.0 otherwise. The average of that flag is the fraction of matching rows, which I can multiply by 100 for a percentage.

12. Memory Review

Chapter summary
  1. CASE checks conditions from top to bottom.
  2. The first true branch wins.
  3. ELSE is optional; without it, unmatched rows return NULL.
  4. SUM(CASE ... THEN 1 ELSE 0 END) counts matches.
  5. AVG(CASE ... THEN 1.0 ELSE 0.0 END) returns a fraction.
  6. WHERE filters rows; CASE derives values.
