1. Big Picture

Single-turn requests contain one user input and one model output. Multi-turn conversations keep a list of messages so the model can use earlier context. Each message has a role: system defines behavior, user provides requests, and assistant stores prior model replies or structured examples.

messages = [ system instruction, user message, assistant reply, user follow-up, assistant reply ] New user message ↓ Send full history to model ↓ Receive assistant response ↓ Append response to history

System, user, and assistant roles

System controls behavior, user carries the request, and assistant represents model replies or examples.

Assistant messages as examples

Assistant messages can demonstrate the response style, tone, and format you want the model to continue.

Conversation history

Append both user and assistant messages so future requests include the full conversation context.

Guardrails and behavior control

System instructions can add guardrails such as refusing unrelated topics or keeping answers concise.

Section punchline: A chatbot is mainly a growing messages list: preserve the roles, append each turn, and resend the history.

2. System, user, and assistant roles

Chat messages are dictionaries with role and content fields. The system role sets overall behavior, the user role contains the current request, and the assistant role represents prior model responses. The order matters because the list describes the conversation from oldest to newest.

messages = [
    {
        "role": "system",
        "content": "You are a patient Python tutor. Keep answers concise."
    },
    {
        "role": "user",
        "content": "What is a Python list?"
    }
]
What to notice: The role name identifies who supplied the message. The content field contains the actual instruction, question, example, or prior reply.

3. Assistant messages as examples

Assistant messages can provide examples in a structured chat format. A user example is followed by the assistant answer you want the model to imitate. Add a new user question last, and the model continues the pattern using the demonstrated style.

messages = [
    {"role": "system", "content": "You are a concise Python tutor."},
    {"role": "user", "content": "What is a variable?"},
    {"role": "assistant", "content": "A variable is a named reference to a value."},
    {"role": "user", "content": "What is a function?"}
]
Common trap: Do not place the example answer under the user role. The example question should be user, and the example answer should be assistant.

4. Conversation history

The API does not automatically remember earlier requests. Your application must store the conversation history and send it again. After receiving a response, append the assistant message to the same list. Before the next call, append the new user message.

Step Code pattern Purpose
Add user turn messages.append({"role": "user", "content": user_input}) Stores the newest question in the conversation
Add assistant turn messages.append({"role": "assistant", "content": reply}) Preserves the model reply for the next request

5. Worked Example

This two-turn example sends the initial question, stores the reply, then asks a follow-up that depends on the earlier context.

from openai import OpenAI

client = OpenAI()

messages = [
    {"role": "system", "content": "You are a patient Python tutor."}
]

messages.append({"role": "user", "content": "What is a Python list?"})

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=messages
)

reply = response.choices[0].message.content
messages.append({"role": "assistant", "content": reply})

messages.append({"role": "user", "content": "Give me a tiny example."})

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=messages
)

print(response.choices[0].message.content)
Result: The follow-up can refer to the earlier topic because both the first question and first assistant reply were included in the second request.

6. Validation and Troubleshooting

  • Print the messages list and confirm roles appear in the correct chronological order.
  • Append the assistant reply using response.choices[0].message.content.
  • Send the complete messages list on every request that needs conversation context.
  • Keep the API key outside the source file and load it through the environment.
Red flag: If the follow-up behaves as if it has no memory, the previous user or assistant turns were probably not included in the messages list.

7. Common Mistakes

Assuming the API remembers automatically The application must preserve and resend conversation history. Each API call is otherwise independent.
Appending only user messages Store both sides of the conversation. Without assistant replies, later context is incomplete.
Using the wrong role for examples Example questions use the user role; their desired answers use the assistant role.

8. Interview Translation

How does a multi-turn OpenAI conversation maintain memory? The application stores previous user and assistant messages and sends the complete ordered history with each new request. The model itself does not retain state between independent calls.
What is the purpose of the system role? It defines overall behavior, tone, scope, and guardrails for the assistant.
Why would you include assistant messages before the newest user message? They can represent earlier model replies or provide structured examples that demonstrate the desired style and format.

9. Memory Review

Section summary
  1. System = behavior and guardrails.
  2. User = request or question.
  3. Assistant = prior model reply or example answer.
  4. Conversation memory = resend the ordered messages list.

Quick self-check

  • Can I explain why an API call has no memory unless I resend history?
  • Can I append a user message and assistant response correctly?
  • Can I use assistant messages as structured few-shot examples?
  • Can I write a system instruction with a useful guardrail?
Lab decision: Build three small labs: system-role behavior control, assistant-role examples, and a two-turn conversation that appends history.
Completion standard: You can construct a role-based messages list, add guardrails, preserve conversation history, and explain why both user and assistant turns must be appended.
