2. Course Big Picture

OpenAI API applications follow a repeatable cycle: create a client, build an ordered messages list, call a model, inspect the response, extract the assistant text, and preserve selected messages when a later request needs context.

Python application ↓ OpenAI client ↓ model + messages + controls ↓ Chat Completions endpoint ↓ response.choices[0].message.content ↓ print/use reply or append it to history
Course punchline: The API generates one response at a time; your application owns prompt structure, safety rules, token controls, and conversation memory.

3. Core Concepts

Client and endpoint

The client sends authenticated requests to an API operation.

Messages and roles

System defines behavior, user supplies requests, and assistant represents replies or examples.

Prompt quality

Useful prompts specify task, context, tone, format, and constraints.

Temperature

Lower values favor consistency; higher values favor variety but may increase drift.

Tokens and limits

Input and output tokens are counted separately; completion limits can truncate replies.

Conversation memory

Store and resend ordered user and assistant messages because independent calls are stateless.

4. Core Syntax and Patterns

Basic request

from openai import OpenAI

client = OpenAI()

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Give me one tip."}]
)

print(response.choices[0].message.content)

Create the client, send one user message, and extract the first generated reply.

Controlled prompt

response = client.chat.completions.create(
    model="gpt-4o-mini",
    temperature=0.2,
    max_completion_tokens=150,
    messages=messages
)

Use a low temperature for steadier output and a completion limit large enough to finish the required response.

Multi-turn history

messages.append({"role": "user", "content": user_text})
response = client.chat.completions.create(model="gpt-4o-mini", messages=messages)
reply = response.choices[0].message.content or ""
messages.append({"role": "assistant", "content": reply})

Append the user turn, send the full history, extract the reply, and store the assistant turn.

5. Comparisons and Decision Rules

Zero-shot

Use an instruction without examples when the task and output format are obvious.

Few-shot

Provide polished examples when labels, scoring rules, tone, or exact formatting need stronger guidance.

Need Preferred choice Reason
Stable classification Low temperature + examples Reduces variation and defines the scoring pattern
Creative brainstorming Higher temperature Allows more varied wording and ideas
Multi-turn follow-up Resend message history The API does not retain prior calls automatically

6. Common Mistakes

Hard-coding a real API key Use an environment variable and never commit or paste a real secret into source files.
Swapping system and user roles Behavior instructions belong to system; the human task belongs to user.
Assuming automatic memory Store both user and assistant turns and resend the ordered history.
Appending a truncated reply Check finish_reason and avoid storing replies that ended because of the token ceiling.

7. Interview Translation

How do you make a basic OpenAI API request? Create a client, send a model and messages list, then extract response.choices[0].message.content.
How does multi-turn memory work? The application stores prior user and assistant messages and resends the complete ordered history.
What is temperature? A control that influences randomness: lower values generally favor consistency, while higher values allow more variation.
How do you detect truncation? Inspect response.choices[0].finish_reason. A value of length indicates the output ceiling was reached.
