1. Big Picture

Chapter 2 applies Hugging Face models to four common NLP needs. Classification assigns labels to text; summarization compresses long content; AutoClasses expose the model and tokenizer for customization; and document Q&A extracts answers from supplied context such as PDF text. The local lab validates grammar classification, QNLI, zero-shot classification, summarization, token inspection, AutoClasses, PDF creation, PDF extraction, and confidence-threshold rejection.

raw text or document ↓ choose the NLP task ↓ select a task-compatible model ↓ pipeline() for speed or AutoModel + AutoTokenizer for control ↓ inspect labels, scores, summaries, or answers

Text Classification

Assign sentiment, grammatical-correctness, entailment, or user-defined category labels to text.

Text Summarization

Reduce long text while balancing faithfulness, readability, resource use, and output length.

AutoModels and AutoTokenizers

Load a task-specific model and its paired tokenizer separately when you need custom preprocessing or model behavior.

Document Question Answering

Extract text from documents, supply it as context, and ask focused questions with a question-answering pipeline.

Section punchline: Use pipeline() when the default workflow is enough; move to AutoClasses when you need explicit control over tokenization, model choice, thresholds, or multi-stage processing.

2. Text Classification

Text classification assigns predefined labels to text. The chapter covers sentiment analysis, grammatical acceptability, Question Natural Language Inference (QNLI), and zero-shot classification. Always read the model card because labels such as LABEL_0 and LABEL_1 only become meaningful when mapped to the model's documented label definitions.

from transformers import pipeline

classifier = pipeline(
    task="text-classification",
    model="distilbert/distilbert-base-uncased-finetuned-sst-2-english"
)

result = classifier("This course is useful.")
print(result)
# [{'label': 'POSITIVE', 'score': ...}]
What to notice: Different classification tasks require different models and input shapes. Sentiment uses one text string; QNLI evaluates a question together with a premise; zero-shot classification also receives candidate_labels.

Observed lab patterns

# Grammar checking
grammar_checker = pipeline(
    task="text-classification",
    model="abdulmatinomotoso/English_Grammar_Checker"
)

# QNLI
qnli = pipeline(
    task="text-classification",
    model="cross-encoder/qnli-electra-base"
)

# Zero-shot classification
zero_shot = pipeline(
    task="zero-shot-classification",
    model="facebook/bart-large-mnli"
)
Generic-label trap: LABEL_0 and LABEL_1 are model-specific. In the grammar lab, LABEL_0 behaved as incorrect and LABEL_1 as correct. In QNLI, the score had to be read carefully because the same displayed label appeared with high confidence for a supporting passage and very low confidence for a non-supporting passage.

3. Text Summarization

Summarization reduces a long input while preserving its important ideas. Extractive methods select original wording and are useful when faithfulness is critical. Abstractive methods generate new wording and are often more readable, but they can introduce unsupported details. The selected model determines which behavior you receive.

from transformers import pipeline

summarizer = pipeline(
    task="summarization",
    model="sshleifer/distilbart-cnn-12-6"
)

result = summarizer(
    long_text,
    min_length=10,
    max_length=40
)

print(result[0]["summary_text"])
Common trap: Do not treat a fluent abstractive summary as automatically accurate. Compare it with the source, especially for legal, financial, medical, or policy documents.
Version lesson: The local environment initially used a newer Transformers release where the summarization pipeline was not registered. Installing a course-compatible Transformers 4.x release restored the task. For this model and version, min_length and max_length avoided truncation and removed the warning caused by the model's larger default max_length.
Observed limitation: The summary reduced 297 characters to 159 characters, but it dropped the caution about model quality, source data, and task design. A shorter summary can still omit an important qualification.

4. AutoModels and AutoTokenizers

AutoClasses infer the correct implementation from a model repository. AutoModelForSequenceClassification loads a classification model, while AutoTokenizer loads the tokenizer paired with it. This pairing matters because different models may split and encode the same text differently.

Approach Use it when Trade-off
pipeline() You want quick experimentation and standard preprocessing, inference, and postprocessing. Less direct control over intermediate steps and custom logic.
AutoModel + AutoTokenizer You need custom tokenization, thresholds, batching, model outputs, or multi-stage workflows. More code and responsibility for preprocessing, tensors, and output interpretation.

Token and model internals observed locally

  • tokenizer.tokenize() returned token strings such as ['la', '##zier']; ## marked a continuation subword.
  • The encoded input included special tokens [CLS] and [SEP], so 10 visible token pieces became 12 input IDs.
  • attention_mask contained all 1s because there was no padding.
  • Direct model inference returned logits, which are raw unnormalized class scores. argmax() selected the predicted class ID.
  • Explicit AutoModel and AutoTokenizer objects were also passed back into pipeline() for convenient inference.

5. Worked Example

Extract text from a PDF and ask a focused question using a question-answering pipeline.

from pathlib import Path
from pypdf import PdfReader
from transformers import pipeline

pdf_path = Path("US_Employee_Policy.pdf")
reader = PdfReader(str(pdf_path))

document_text = ""
for page_number, page in enumerate(reader.pages, start=1):
    page_text = page.extract_text() or ""
    print(f"Extracted page {page_number}: {len(page_text)} characters")
    document_text += page_text + "\n"

qa = pipeline(
    task="question-answering",
    model="distilbert/distilbert-base-cased-distilled-squad"
)

result = qa(
    question="What is the notice period for resignation?",
    context=document_text
)

if result["score"] < 0.30:
    print("Answer: Not enough information in the document.")
else:
    print("Answer:", result["answer"])
Validated result: PyPDF extracted 186 characters from page 1 and 153 from page 2. The Q&A model returned two weeks with a score of about 0.793, so the threshold accepted the answer.
Failure-case evidence: When asked for information absent from the context, the model still forced an answer span with a low score of about 0.088. The confidence threshold correctly converted that into “Not enough information in the context.”

6. Validation and Troubleshooting

  • Confirm that the chosen model was trained for the exact task: sentiment, grammar, QNLI, zero-shot classification, summarization, or question answering.
  • Read the model card before interpreting generic labels such as LABEL_0 or LABEL_1.
  • Inspect the complete returned structure before indexing keys such as labels, scores, summary_text, or answer.
  • For document Q&A, confirm that PDF extraction produced readable text and that the relevant passage fits within the model's context limit.
  • Use top_k=None when you need to inspect all class scores instead of only the highest returned result.
  • Use a confidence threshold for extractive Q&A because the model may force an answer even when the context does not contain one.
  • Remember that normal PyPDF extraction requires a text layer; scanned image PDFs require OCR.
Red flag: A high confidence score does not prove that the label, summary, or answer is correct. Validate against representative examples and the original source.

7. Common Mistakes

Using one classifier for every classification task Sentiment, grammar, QNLI, and zero-shot classification require task-compatible models and may require different inputs.
Assuming LABEL_0 has a universal meaning Generic label IDs are model-specific. Use the model card or model configuration to map IDs to meanings.
Passing an entire document without checking extraction or length Inspect extracted text and account for context limits. Longer documents may require chunking and retrieval rather than one enormous context string.
Trusting a high-confidence classifier outside its domain A movie-review sentiment model classified “This course is getting much easier to understand” as negative with high confidence. Clearer wording changed the result, showing that confidence does not equal deep reasoning.
Assuming summarization settings are version-independent The course-compatible Transformers 4.x environment accepted the summarization task and behaved better with min_length and max_length for this model.
Accepting every extracted answer Extractive Q&A can return the best available span even when no valid answer exists. Reject low-confidence results or add an upstream entailment/retrieval check.

8. Interview Translation

When would you use zero-shot classification? I would use it when I need to classify text into candidate categories that were not part of a dedicated supervised training set. I would validate the candidate-label wording and confidence quality because the model was not trained specifically for my business taxonomy.
When would you choose AutoClasses instead of pipeline()? I would use pipeline() for standard, fast inference. I would use AutoModel and AutoTokenizer when I need custom tokenization, batching, thresholds, access to raw outputs, or integration into a larger workflow.
What is the main risk of abstractive summarization? It can generate fluent wording that is not fully supported by the source. For high-stakes material I would compare the summary with the source and favor faithfulness checks or extractive methods where appropriate.
How would you make document Q&A safer? I would validate extraction quality, retrieve or screen relevant passages, use a task-appropriate Q&A model, apply a confidence threshold, and return “not enough information” instead of forcing a low-confidence span.

9. Memory Review

Section summary
  1. Classification = text in, label and score out.
  2. Summarization = long text in, shorter summary_text out; length is controlled with token parameters.
  3. pipeline() hides the workflow; AutoModel and AutoTokenizer expose it for control.
  4. Document Q&A = question + extracted context → answer + score.
  5. Generic labels are model-specific; inspect the model card, configuration, and all class scores when needed.
  6. Low-confidence Q&A answers should be rejected rather than displayed as facts.
