Foundations

Privacy vs. Security

Separate appropriate data handling from technical protection.

Security = protect data
Privacy = govern collection, use, sharing, retention, deletion
Securely misusing personal data is still a privacy failure.

CIA Triad

Classify information-security goals.

Confidentiality = who can see
Integrity = can we trust it
Availability = can we reach it
CIA is foundational, not the only security model.

PREACH

Quickly assess a privacy program.

Purpose
Right to Request
Easy to understand
Alerting
Consent
How
A policy or consent click alone does not prove meaningful privacy.

Privacy by Design and Risk

Seven PbD Principles

Build privacy into the system from the start.

Proactive
Private by default
Embedded
Full functionality
End-to-end security
Transparency
Respect users
Privacy controls can add modest overhead; the goal is proportionate protection, not zero cost.

Classification

Match handling controls to sensitivity.

Public < Internal < Confidential < Restricted
A label is useless unless access, storage, sharing, and retention rules follow it.

Risk

Estimate likelihood and potential harm.

Risk = Likelihood x Impact
The same classification can have different risk depending on controls and exposure.

De-identification and Lifecycle

Pseudonymization

Replace identifiers while preserving a reversible link.

Sean Girgis -> Person 4821
Separate key: 4821 -> Sean Girgis
Pseudonymized data is still personal data when it can be re-linked.

Anonymization

Aim to prevent reasonable re-identification.

Remove direct identifiers
Generalize unique details
Aggregate where possible
Removing names alone does not make data anonymous.

Lifecycle

Apply controls from collection through deletion.

Collect -> Store -> Use -> Share -> Archive -> Delete
Deleting the primary database copy is not enough if exports or shared copies remain.

Law, Vendors, and Emerging Technology

jAsper

Break down a privacy law consistently.

J Jurisdiction
A Author/Aim
S Scope
P Penalty
E Enforcement
R Requirements
Enforcement is who acts; penalty is what happens.

Vendor Governance

Control third parties that process personal data.

Due diligence
Purpose limits
Security terms
Breach notice
Retention/deletion
Audit rights
Outsourcing processing does not outsource responsibility.

Shift Left

Resolve privacy issues before design hardens.

Plan -> assess privacy -> design controls -> build -> test
For blockchain, ask about deletion and correction before putting personal data on-chain.

Whole-course decision map

Need protection? -> CIA / access / encryption / monitoring Need appropriate use? -> purpose / minimization / consent / rights Need lower identification risk? -> pseudonymize / generalize / aggregate Need legal analysis? -> jAsper Need proof? -> inventories / reviews / logs / audits Need safer design? -> shift privacy left
The strongest privacy answer usually combines purpose, minimization, proportional controls, lifecycle management, user rights, legal requirements, and evidence.
