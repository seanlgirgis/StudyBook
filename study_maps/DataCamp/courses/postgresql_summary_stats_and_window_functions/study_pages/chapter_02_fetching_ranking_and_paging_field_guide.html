Fetching, Ranking, and Paging

This chapter applies window functions to three practical tasks: fetching values from nearby or boundary rows, ranking rows by value, and splitting ordered results into approximately equal groups.

1. Big Picture

ordered rows │ ├── fetch another row's value │ LAG / LEAD / FIRST_VALUE / LAST_VALUE │ ├── assign position │ ROW_NUMBER / RANK / DENSE_RANK │ └── split into buckets NTILE

Fetching

Look backward, forward, or to a boundary row.

Ranking

Assign an ordered position based on values.

Paging

Split ordered rows into roughly equal groups.

Partitioning

Apply each calculation independently per group.

Chapter punchline: Window functions can move across rows, label row position, and divide ordered results without collapsing detail.

2. Fetching Values from Other Rows

The chapter introduces four fetching functions:

FunctionTypeMeaning
LAG(column, n)RelativeReturns the value from n rows before the current row.
LEAD(column, n)RelativeReturns the value from n rows after the current row.
FIRST_VALUE(column)AbsoluteReturns the first value in the current window or partition.
LAST_VALUE(column)AbsoluteReturns the last value in the current frame.
Key distinction: LAG() and LEAD() use a relative offset. FIRST_VALUE() and LAST_VALUE() use the first or last row defined by the window frame.

3. LEAD() and LAG()

Fetch the next Olympic host city

WITH hosts AS (
    SELECT DISTINCT year, city
    FROM summer_medals
)
SELECT
    year,
    city,
    LEAD(city, 1) OVER (
        ORDER BY year
    ) AS next_city,
    LEAD(city, 2) OVER (
        ORDER BY year
    ) AS after_next_city
FROM hosts
ORDER BY year;

The last row returns NULL because there is no following row. The same idea applies to LAG() at the beginning of a partition.

Partition before fetching

SELECT
    year,
    event,
    champion,
    LEAD(champion, 1) OVER (
        PARTITION BY event
        ORDER BY year
    ) AS next_champion
FROM champions;
Common trap: Without PARTITION BY event, LEAD() may fetch a champion from a different event.

4. FIRST_VALUE() and LAST_VALUE()

SELECT
    year,
    city,
    FIRST_VALUE(city) OVER (
        ORDER BY year
    ) AS first_city,
    LAST_VALUE(city) OVER (
        ORDER BY year
        RANGE BETWEEN
            UNBOUNDED PRECEDING AND
            UNBOUNDED FOLLOWING
    ) AS last_city
FROM hosts
ORDER BY year;

FIRST_VALUE() usually behaves as expected because the default frame starts at the beginning. LAST_VALUE() is different: by default, the frame often ends at the current row, so the result may simply repeat the current value.

Critical rule: To get the true last value of the entire partition, explicitly extend the frame through UNBOUNDED FOLLOWING.

5. Ranking Rows

Ranking functions assign a position based on the window order.

WITH country_games AS (
    SELECT
        country,
        COUNT(DISTINCT year) AS games
    FROM summer_medals
    GROUP BY country
)
SELECT
    country,
    games,
    ROW_NUMBER() OVER (ORDER BY games DESC) AS row_n,
    RANK()       OVER (ORDER BY games DESC) AS rank_n,
    DENSE_RANK() OVER (ORDER BY games DESC) AS dense_rank_n
FROM country_games
ORDER BY games DESC, country;

The ranking value comes from ORDER BY inside OVER(). The final query ORDER BY controls display.

Rank independently by country

WITH country_medals AS (
    SELECT
        country,
        athlete,
        COUNT(*) AS medals
    FROM summer_medals
    WHERE country IN ('CHN', 'RUS')
      AND year = 2012
    GROUP BY country, athlete
)
SELECT
    country,
    athlete,
    medals,
    DENSE_RANK() OVER (
        PARTITION BY country
        ORDER BY medals DESC
    ) AS athlete_rank
FROM country_medals
ORDER BY country, athlete_rank, athlete;

6. ROW_NUMBER vs RANK vs DENSE_RANK

FunctionTiesSequence after a tieBest use
ROW_NUMBER()Always uniqueNo ties existDeterministic row sequence or one-row selection
RANK()Same rank for tiesLeaves gapsCompetition-style ranking
DENSE_RANK()Same rank for tiesNo gapsConsecutive ranking levels
Values: 27, 26, 26, 25 ROW_NUMBER → 1, 2, 3, 4 RANK → 1, 2, 2, 4 DENSE_RANK → 1, 2, 2, 3
Decision rule: Use ROW_NUMBER() when every row must receive a unique position, RANK() when gaps should reflect ties, and DENSE_RANK() when ties should not create gaps.

7. Paging with NTILE()

Paging means splitting ordered data into approximately equal-sized chunks. NTILE(n) assigns each row to one of n buckets.

Split disciplines into 15 pages

WITH disciplines AS (
    SELECT DISTINCT discipline
    FROM summer_medals
)
SELECT
    discipline,
    NTILE(15) OVER (
        ORDER BY discipline
    ) AS page
FROM disciplines
ORDER BY page, discipline;

If 67 rows are split into 15 pages, the pages will contain approximately four or five rows each.

Top, middle, and bottom thirds

WITH country_medals AS (
    SELECT
        country,
        COUNT(*) AS medals
    FROM summer_medals
    GROUP BY country
)
SELECT
    country,
    medals,
    NTILE(3) OVER (
        ORDER BY medals DESC
    ) AS third
FROM country_medals
ORDER BY third, medals DESC;
BucketInterpretation
1Top third
2Middle third
3Bottom third
Important: NTILE() balances row counts, not value ranges. Rows with equal values can land in different buckets.

8. Worked Examples

Future gold medalists

SELECT
    year,
    athlete,
    LEAD(athlete) OVER (
        PARTITION BY event
        ORDER BY year
    ) AS future_gold_medalist
FROM summer_medals
WHERE medal = 'Gold';

First athlete alphabetically

SELECT
    athlete,
    FIRST_VALUE(athlete) OVER (
        ORDER BY athlete
    ) AS first_athlete
FROM summer_medals;

Last country alphabetically

SELECT
    country,
    LAST_VALUE(country) OVER (
        ORDER BY country
        RANGE BETWEEN
            UNBOUNDED PRECEDING AND
            UNBOUNDED FOLLOWING
    ) AS last_country
FROM summer_medals;

Rank athletes by medals earned

WITH athlete_medals AS (
    SELECT
        athlete,
        COUNT(*) AS medals
    FROM summer_medals
    GROUP BY athlete
)
SELECT
    athlete,
    medals,
    DENSE_RANK() OVER (
        ORDER BY medals DESC
    ) AS medal_rank
FROM athlete_medals
ORDER BY medal_rank, athlete;

9. Common Mistakes

Using LEAD or LAG without a meaningful order Relative row position only makes sense when the window has a stable ORDER BY.
Forgetting to partition independent groups Fetching or ranking can cross from one event, country, or category into another.
Trusting LAST_VALUE() with the default frame The default frame often stops at the current row. Add UNBOUNDED FOLLOWING for the true final value.
Choosing the wrong ranking function Decide explicitly whether ties should be unique, tied with gaps, or tied without gaps.
Treating NTILE as equal value ranges NTILE() creates approximately equal row counts, not equally sized numeric intervals.

10. Interview Translation

What is the difference between LAG and LEAD? LAG() reads a value from a previous row in the window order, while LEAD() reads from a following row.
Why can LAST_VALUE be surprising? Because it respects the current window frame. With the default frame, the last row is often the current row, so I explicitly extend the frame when I need the partition's true final value.
How do ROW_NUMBER, RANK, and DENSE_RANK differ? ROW_NUMBER() is always unique, RANK() leaves gaps after ties, and DENSE_RANK() does not leave gaps.
What does NTILE do? It divides ordered rows into a requested number of approximately equal buckets and assigns each row a bucket number.

11. Memory Review

Chapter summary
  1. LAG looks backward; LEAD looks forward.
  2. FIRST_VALUE and LAST_VALUE depend on the window frame.
  3. ROW_NUMBER is unique; RANK gaps; DENSE_RANK does not.
  4. NTILE(n) creates approximately equal row-count buckets.
