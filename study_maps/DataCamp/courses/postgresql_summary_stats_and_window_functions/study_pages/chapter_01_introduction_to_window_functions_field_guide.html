Introduction to Window Functions

Window functions calculate across rows related to the current row while preserving every detail row. This chapter introduces the core shape of a window expression, explains why it differs from GROUP BY, and builds the two essential subclauses: ORDER BY and PARTITION BY.

1. Big Picture

A window function looks at a set of rows connected to the current row and produces a value for each input row. Unlike ordinary aggregation, it does not collapse the result into one row per group.

detail rows │ ├── GROUP BY → fewer output rows │ one row per group │ └── window function → same number of output rows extra analytical column per row

Function

The calculation, such as ROW_NUMBER().

OVER()

Marks the function as a window function.

ORDER BY

Controls row sequence inside the window.

PARTITION BY

Restarts the calculation for each group.

Chapter punchline: Window functions add analytical context to each row without losing the original row-level detail.

2. Window Functions vs GROUP BY

GROUP BY combines many rows into one summarized row per group. A window function calculates over related rows but keeps each original row visible.

FeatureGROUP BYWindow function
Output rowsReducedPreserved
Detail columnsUsually unavailable unless groupedRemain available
Typical useOne summary row per groupRank, compare, number, or aggregate per row
 
-- GROUP BY collapses rows
SELECT country, COUNT(*) AS medals
FROM summer_medals
GROUP BY country;

-- Window calculation preserves rows
SELECT
    year,
    event,
    country,
    COUNT(*) OVER (PARTITION BY country) AS country_medals
FROM summer_medals;

3. Numbering Rows with ROW_NUMBER()

ROW_NUMBER() assigns a unique sequence number to each row. With an empty OVER(), the numbering order is not guaranteed. Add ORDER BY inside OVER() when the sequence matters. 

SELECT
    year,
    event,
    country,
    ROW_NUMBER() OVER () AS row_n
FROM summer_medals
WHERE medal = 'Gold';
Common trap: A row number without an explicit window order may change between executions because SQL tables have no inherent row order.

4. ORDER BY Inside OVER()

ORDER BY inside OVER() determines the order used by the window function. It is separate from the query-level ORDER BY, which controls the final display order. 

SELECT
    year,
    event,
    country,
    ROW_NUMBER() OVER (
        ORDER BY year, event
    ) AS row_n
FROM summer_medals
WHERE medal = 'Gold';

Ascending and descending

ROW_NUMBER() OVER (ORDER BY year ASC)  -- oldest first
ROW_NUMBER() OVER (ORDER BY year DESC) -- newest first

Ordering by multiple columns

ROW_NUMBER() OVER (
    ORDER BY year DESC, event ASC
)
What to notice: The first sort expression is the primary order. Later expressions break ties.

Inside vs outside OVER()

SELECT
    year,
    event,
    country,
    ROW_NUMBER() OVER (
        ORDER BY year, event
    ) AS row_n
FROM summer_medals
WHERE medal = 'Gold'
ORDER BY country, row_n;

Here, the window numbers rows by year, event, but the final output is displayed by country, row_n. These are two independent operations.

5. PARTITION BY

PARTITION BY splits the result into separate windows based on one or more column values. The window function restarts inside each partition. 

SELECT
    year,
    event,
    country,
    ROW_NUMBER() OVER (
        PARTITION BY country
        ORDER BY year
    ) AS row_n
FROM summer_medals
WHERE medal = 'Gold';

Partitioning by multiple columns

SELECT
    year,
    event,
    gender,
    country,
    ROW_NUMBER() OVER (
        PARTITION BY gender, event
        ORDER BY year
    ) AS row_n
FROM summer_medals
WHERE medal = 'Gold';
Window clauseEffectQuestion answered
No partitionOne window for all rowsWhat is the row number overall?
PARTITION BY countryNumbering restarts per countryWhat is the row number within each country?
PARTITION BY gender, eventRestarts for every gender-event pairWhat is the sequence within each event category?

6. Worked Example — Reigning Champions

A reigning champion is a competitor who won the same event in the previous Games and again in the current Games. Chapter 1 prepares the structure needed for that analysis by ordering results and partitioning comparable competitors. 

WITH champions AS (
    SELECT
        year,
        gender,
        event,
        country
    FROM summer_medals
    WHERE medal = 'Gold'
      AND sport = 'Weightlifting'
)
SELECT
    year,
    gender,
    event,
    country,
    ROW_NUMBER() OVER (
        PARTITION BY gender, event
        ORDER BY year
    ) AS appearance_n
FROM champions
ORDER BY gender, event, year;
Result: The row number restarts for each gender-event combination, creating the ordered structure needed for later comparisons with LAG().

7. Validation and Troubleshooting

  • Confirm the number of output rows is unchanged after adding only a window column.
  • Check that row numbers restart exactly where the partition changes.
  • Use enough ORDER BY columns to make tie handling predictable.
  • Keep window ordering separate from final result ordering in your mental model.
Red flag: If detail rows disappear, the query probably used aggregation or filtering rather than only a window calculation.

8. Common Mistakes

Assuming OVER() alone creates a meaningful order It does not. Add ORDER BY inside OVER() when sequence matters.
Confusing window ORDER BY with final ORDER BY The first controls the calculation. The second controls display order.
Partitioning too broadly or too narrowly Choose the columns that define the independent analytical groups. Extra columns may restart the calculation too often.
Expecting ROW_NUMBER() to preserve ties ROW_NUMBER() always assigns a unique number. Tie-aware ranking comes later with RANK() and DENSE_RANK().

9. Interview Translation

What is a window function? A window function calculates across rows related to the current row while preserving one output row for every input row.
How is a window function different from GROUP BY? GROUP BY collapses rows into grouped summaries. Window functions preserve detail rows and add analytical values beside them.
What does ORDER BY inside OVER() do? It defines the sequence used by the window calculation. It does not necessarily determine the final display order.
What does PARTITION BY do? It divides rows into independent groups and restarts the window calculation for each group.
