Aggregate Window Functions and Frames

This chapter turns familiar aggregates such as SUM(), AVG(), MIN(), and MAX() into per-row analytical calculations. It also introduces frames, moving windows, running totals, and the difference between ROWS and RANGE.

1. Big Picture

aggregate function + OVER(...) │ ├── no ORDER BY │ full-window value repeated on every row │ ├── ORDER BY │ cumulative result by default │ └── explicit frame moving or bounded result

Aggregate window

Apply SUM, AVG, MIN, or MAX without collapsing rows.

Running result

Accumulate from the start of the partition through the current row.

Frame

Define exactly which rows around the current row participate.

Moving result

Use a bounded frame such as the current row plus two preceding rows.

Chapter punchline: Aggregate window functions preserve detail rows, while frames control how much of the ordered partition each row can see.

2. Aggregate Window Functions

A traditional aggregate returns one result for a group. Adding OVER() turns it into a window function, so the aggregate result can appear beside every row. 

SELECT
    Year,
    Medals,
    MAX(Medals) OVER () AS Max_Medals,
    SUM(Medals) OVER () AS Total_Medals
FROM Brazil_Medals;
ExpressionMeaning
MAX(Medals)One scalar result after aggregation.
MAX(Medals) OVER ()The maximum repeated beside every input row.
SUM(Medals) OVER ()The total repeated beside every input row.
What to notice: OVER() changes the output shape. The rows remain visible instead of being collapsed.

3. Running Totals and Running Maximums

Adding ORDER BY to an aggregate window creates an ordered cumulative calculation. 

SELECT
    Year,
    Medals,
    SUM(Medals) OVER (
        ORDER BY Year ASC
    ) AS Medals_RT
FROM Brazil_Medals
ORDER BY Year ASC;
SELECT
    Year,
    Medals,
    MAX(Medals) OVER (
        ORDER BY Year ASC
    ) AS Max_Medals
FROM Brazil_Medals
ORDER BY Year ASC;

The running sum increases over time. The running maximum stays the same until a new record value appears.

4. Partitioning Aggregate Windows

PARTITION BY creates independent cumulative calculations for each group. 

SELECT
    Year,
    Country,
    Medals,
    SUM(Medals) OVER (
        PARTITION BY Country
        ORDER BY Year ASC
    ) AS Medals_RT
FROM Medals
ORDER BY Country, Year;
Common trap: Without PARTITION BY Country, the running total continues across country boundaries.

5. Window Frames

A frame defines the subset of rows within the ordered partition used for the current row’s calculation.

Frame-size rule: ROWS BETWEEN 3 PRECEDING AND CURRENT ROW can contain up to four rows: three prior rows plus the current row.

6. ROWS vs RANGE

Frame typeHow it countsTie behavior
ROWSPhysical row positionsEach row is counted separately.
RANGELogical values of the window orderRows tied on the ordering value are treated as peers.
Important: With duplicate values in the window ORDER BY, RANGE can include multiple peer rows at once. Use ROWS when you mean an exact number of physical records.

7. Moving Averages and Moving Totals

A moving average smooths short-term changes by averaging a fixed number of recent rows. A moving total sums a fixed number of recent rows.

Three-row moving average

SELECT
    Year,
    Medals,
    AVG(Medals) OVER (
        ORDER BY Year ASC
        ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
    ) AS Medals_MA
FROM US_Medals
ORDER BY Year ASC;

Three-row moving total

SELECT
    Year,
    Medals,
    SUM(Medals) OVER (
        ORDER BY Year ASC
        ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
    ) AS Medals_MT
FROM US_Medals
ORDER BY Year ASC;
What to notice: “Three-row moving” means two preceding rows plus the current row. Early rows use fewer observations because the full frame does not yet exist.

8. Core Patterns

Full-partition aggregate

SUM(value) OVER (
    PARTITION BY group_col
)

Running total

SUM(value) OVER (
    PARTITION BY group_col
    ORDER BY time_col
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
)

Moving average

AVG(value) OVER (
    PARTITION BY group_col
    ORDER BY time_col
    ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
)

Centered three-row maximum

MAX(value) OVER (
    PARTITION BY group_col
    ORDER BY time_col
    ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING
)

9. Common Mistakes

Forgetting that ORDER BY changes the aggregate behavior Without a frame, an ordered aggregate often becomes cumulative rather than repeating the full-partition total.
Miscounting the frame 2 PRECEDING AND CURRENT ROW is a three-row frame, not two.
Using RANGE when physical row count matters Duplicate ordering values can cause RANGE to include additional peer rows.
Forgetting PARTITION BY Running totals or moving calculations can bleed across unrelated groups.
Expecting a full-size frame at the beginning Early rows use only the rows that exist before them.

10. Interview Translation

How do aggregate window functions differ from GROUP BY? They calculate aggregates across related rows while preserving each input row in the result.
What is a window frame? It is the subset of rows inside an ordered partition used for the current row’s calculation.
How do you create a running total? Use SUM() as a window function ordered by time, typically with a frame from UNBOUNDED PRECEDING through CURRENT ROW.
What is the difference between ROWS and RANGE? ROWS counts physical records, while RANGE groups peers that share the same ordering value.
