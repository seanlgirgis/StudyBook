2. Full-text search

The LIKE operator checks character patterns using % for any number of characters and _ for exactly one character. Full-text search is different: PostgreSQL transforms text into a tsvector and compares it to a tsquery with the @@ operator. This is more appropriate for document-style searches because words are normalized and indexed as lexemes.

-- Pattern matching
SELECT title
FROM film
WHERE title LIKE '%ELF';

-- Full-text search
SELECT title, description
FROM film
WHERE to_tsvector('english', title || ' ' || description)
      @@ to_tsquery('english', 'elf');
What to notice: The expression on the left of @@ is searchable document text; the expression on the right is the search query. Use the same text-search configuration on both sides.

3. User-defined types and functions

PostgreSQL can be extended with custom database objects. ENUM types restrict values to a defined list. User-defined functions package reusable logic close to the data. PostgreSQL catalogs and information_schema views let you inspect these objects instead of guessing how they were defined.

CREATE TYPE dayofweek AS ENUM (
  'Monday', 'Tuesday', 'Wednesday',
  'Thursday', 'Friday', 'Saturday', 'Sunday'
);

SELECT typname, typcategory
FROM pg_type
WHERE typname = 'dayofweek';

SELECT column_name, data_type, udt_name
FROM information_schema.columns
WHERE table_name = 'film';
Common trap: A column reported as USER-DEFINED is not self-explanatory. Check udt_name or pg_type to learn the actual underlying custom type.

4. Extensions and fuzzy matching

Extensions install packaged PostgreSQL features. Query pg_available_extensions to see what can be installed and pg_extension to see what is already enabled. fuzzystrmatch provides functions such as levenshtein(); pg_trgm provides similarity() and trigram-based matching.

Need Function or object Key idea
Edit distance levenshtein(text, text) Lower result means fewer edits and closer strings.
Trigram similarity similarity(text, text) Higher result means more similar strings; 1 is an exact match.

5. Worked Example

Enable the required extensions, verify they are installed, then compare a misspelled search term to stored titles using both similarity score and edit distance.

CREATE EXTENSION IF NOT EXISTS fuzzystrmatch;
CREATE EXTENSION IF NOT EXISTS pg_trgm;

SELECT extname
FROM pg_extension
WHERE extname IN ('fuzzystrmatch', 'pg_trgm');

SELECT
  title,
  similarity(title, 'GAMBOL') AS similarity_score,
  levenshtein(lower(title), lower('GAMBOL')) AS edit_distance
FROM film
ORDER BY similarity_score DESC, edit_distance ASC
LIMIT 10;
Result: The strongest candidates sort toward similarity values near 1 and edit distances near 0. These measures are complementary, not interchangeable.

6. Validation and Troubleshooting

  • Confirm an extension is available before trying to install it with pg_available_extensions.
  • Confirm installation with pg_extension after CREATE EXTENSION.
  • Use the same full-text search configuration, such as english, for both tsvector and tsquery.
  • Test fuzzy matching with known identical and intentionally misspelled strings so the direction of each score is obvious.
Red flag: A fuzzy-search query that treats a larger Levenshtein distance as a better match has the ranking direction reversed.

7. Common Mistakes

Using LIKE as full-text search LIKE is character-pattern matching. It does not tokenize, normalize, or understand search terms as document words.
Assuming every extension is already installed Available and installed are different states. Inspect pg_available_extensions and pg_extension separately.
Confusing fuzzy-match directions For similarity(), higher is better. For levenshtein(), lower is better.

8. Interview Translation

When would you use PostgreSQL full-text search instead of LIKE? Use full-text search when searching documents or descriptions by normalized words and search expressions. Use LIKE for direct character-pattern matching.
How do you determine whether a PostgreSQL extension is installed? Query pg_extension for installed extensions. Query pg_available_extensions when you need to know what the server can install.
What is the difference between similarity() and levenshtein()? similarity() returns a closeness score where larger values are better. levenshtein() counts the edits needed to transform one string into another, so smaller values are better.

9. Memory Review

Section summary
  1. % matches zero or more characters; _ matches exactly one character in LIKE patterns.
  2. Full-text search follows document → tsvector, query text → tsquery, then @@ to test a match.
  3. Available extension does not mean installed extension.
  4. Similarity goes up as strings get closer; Levenshtein distance goes down.
