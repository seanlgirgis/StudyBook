1. Big Picture

PostgreSQL treats dates, timestamps, and intervals as values that can be added, subtracted, compared, filtered, and grouped. The key is knowing the result type produced by each operation and choosing the function that matches the business question.

DATE - DATE → integer number of days TIMESTAMP - TIMESTAMP → INTERVAL TIMESTAMP + INTERVAL → TIMESTAMP EXTRACT(field FROM value) → numeric component DATE_TRUNC('unit', value) → timestamp bucket

2. Date, Timestamp, and Interval Arithmetic

Subtracting two DATE values returns a whole-number day count. Subtracting two TIMESTAMP values returns an INTERVAL. To move a timestamp forward by a numeric duration, convert the number into an interval by multiplying it by a unit such as INTERVAL '1 day'.

SELECT DATE '2026-06-10' - DATE '2026-06-01' AS days_between;

SELECT TIMESTAMP '2026-06-10 18:00'
     - TIMESTAMP '2026-06-09 08:30' AS elapsed_time;

SELECT rental_date
     + rental_duration * INTERVAL '1 day' AS expected_return_date
FROM rental_schedule;
What to notice: The operator may look the same, but PostgreSQL chooses the result type from the input types.

3. Current Date and Time Functions

PostgreSQL supplies several expressions for the current date and time. CURRENT_DATE returns only the calendar date. CURRENT_TIMESTAMP and NOW() return the current timestamp with time zone. LOCALTIME and LOCALTIMESTAMP omit time-zone information. NOW() and CURRENT_TIMESTAMP remain stable within the same transaction.

SELECT CURRENT_DATE,
       CURRENT_TIME,
       CURRENT_TIMESTAMP,
       NOW(),
       LOCALTIME,
       LOCALTIMESTAMP;

SELECT *
FROM rental
WHERE rental_date >= CURRENT_TIMESTAMP - INTERVAL '7 days';
Common trap: Do not assume every current-time expression has the same type or time-zone behavior. Choose deliberately, especially when comparing stored timestamps.

4. EXTRACT, DATE_PART, and DATE_TRUNC

EXTRACT and DATE_PART return an individual numeric component such as year, month, day, hour, or day of week. DATE_TRUNC rounds a timestamp down to the beginning of a chosen unit and is usually better for grouping records into reporting buckets.

Expression Returns Best use
EXTRACT(MONTH FROM rental_date) Numeric month component Filtering, labeling, or calculations using one component
DATE_TRUNC('month', rental_date) Timestamp at the start of the month Grouping and ordering monthly reports

5. Worked Example

This query calculates each rental's expected return date, keeps only overdue unreturned rentals, and exposes the month in which the rental began.

SELECT
    r.rental_id,
    r.rental_date,
    DATE_TRUNC('month', r.rental_date) AS rental_month,
    r.rental_date + f.rental_duration * INTERVAL '1 day' AS expected_return_date
FROM rental AS r
JOIN inventory AS i ON r.inventory_id = i.inventory_id
JOIN film AS f ON i.film_id = f.film_id
WHERE r.return_date IS NULL
  AND CURRENT_TIMESTAMP >
      r.rental_date + f.rental_duration * INTERVAL '1 day'
ORDER BY expected_return_date;
Result: Each returned row represents an open rental whose calculated due timestamp is earlier than the current timestamp.

6. Validation and Troubleshooting

  • Check the data type of every operand before predicting the result of date/time arithmetic.
  • Verify whether stored timestamps include time-zone information before comparing them with NOW().
  • Handle NULL return dates explicitly because arithmetic and comparisons involving NULL produce NULL.
  • When grouping across several years, group by a complete bucket such as DATE_TRUNC('month', value), not only EXTRACT(MONTH FROM value).
Red flag: A report that groups only by month number can combine January from different years into one row.

7. Common Mistakes

Treating one month as exactly thirty days INTERVAL '1 month' follows calendar boundaries and is not always equal to INTERVAL '30 days'.
Adding a bare number to a timestamp Express the unit explicitly: multiply the count by INTERVAL '1 day', INTERVAL '1 hour', or another appropriate interval.
Using EXTRACT when a time bucket is needed Use DATE_TRUNC() for chronological grouping because it preserves a complete timestamp boundary.

8. Interview Translation

What does PostgreSQL return when two timestamps are subtracted? It returns an INTERVAL representing the elapsed time. By contrast, subtracting two DATE values returns the number of days.
When would you use EXTRACT instead of DATE_TRUNC? Use EXTRACT when one numeric component is needed, such as hour or day of week. Use DATE_TRUNC when a complete time bucket is needed for grouping and ordering.
How would you calculate an expected return timestamp from a duration stored as an integer? Multiply the integer by an interval unit, such as rental_duration * INTERVAL '1 day', and add the resulting interval to the rental timestamp.
