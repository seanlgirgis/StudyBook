Parsing and Manipulating Text

1. Big Picture

Text manipulation usually follows a small pipeline: standardize the value, locate a delimiter or boundary, extract the part you need, and finally clean or format the result. PostgreSQL provides both operators and functions for every stage, and the functions can be nested when one transformation depends on another.

raw text ↓ concatenate / case / replace / reverse standardized text ↓ length + position known boundaries ↓ left / right / substring / substr extracted text ↓ trim / lpad / rpad analysis-ready output

Reformatting String Data

Use || or CONCAT() to combine values; UPPER(), LOWER(), INITCAP(), REPLACE(), and REVERSE() reshape their contents.

Measuring and Parsing Text

Use LENGTH()/CHAR_LENGTH() and STRPOS()/POSITION() to discover where useful text begins and ends.

Truncating, Trimming, and Padding

Use LEFT(), RIGHT(), SUBSTRING()/SUBSTR(), TRIM(), LPAD(), and RPAD() to return exactly the portion and width you need.

Combining String Functions

Nest functions so the output of one function becomes the input or argument of another.

Section punchline: Find the boundary first, then extract or format the text around that boundary.

2. Reformatting String Data

PostgreSQL can concatenate strings with the || operator or the CONCAT() function. Case functions standardize capitalization, while replacement and reversal functions reshape existing content. These operations are especially useful for names, email addresses, labels, and dirty descriptive fields.

SELECT
    first_name || ' ' || last_name AS full_name,
    CONCAT(first_name, ' ', last_name) AS full_name_function,
    UPPER(email) AS email_upper,
    LOWER(email) AS email_lower,
    INITCAP(first_name || ' ' || last_name) AS display_name,
    REPLACE(description, 'A Astounding', 'An Astounding') AS corrected_text,
    REVERSE(title) AS reversed_title
FROM customer;
What to notice: The || operator is concise, while CONCAT() is often easier when combining several values. Case conversion changes presentation, not the stored source value, unless it is used in an UPDATE.

3. Measuring and Parsing Text

Before extracting text, determine its total length or locate a delimiter. LENGTH() and CHAR_LENGTH() return the number of characters. STRPOS(string, substring) and POSITION(substring IN string) return the first matching character position. Once a boundary is known, LEFT(), RIGHT(), SUBSTRING(), or the alias SUBSTR() can return the desired fragment.

SELECT
    email,
    CHAR_LENGTH(email) AS email_length,
    STRPOS(email, '@') AS at_position,
    SUBSTRING(email FROM 1 FOR POSITION('@' IN email) - 1) AS username,
    SUBSTRING(email FROM POSITION('@' IN email) + 1) AS domain
FROM customer;

SELECT
    LEFT(description, 50) AS first_50_chars,
    RIGHT(description, 20) AS last_20_chars,
    SUBSTR(description, 10, 50) AS chars_10_to_59
FROM film;
Common trap: Position functions return 0 when the substring is not found. A computed length such as POSITION(...) - 1 can therefore become invalid or misleading unless missing delimiters are handled.

4. Truncating, Trimming, and Padding

Truncation limits text to a useful portion, trimming removes unwanted edge characters, and padding produces a fixed-width display. TRIM() can remove whitespace or a specified character from both ends, or only from the leading or trailing edge. LPAD() and RPAD() extend a value to a requested total length and truncate it when the requested length is shorter.

Function Smallest useful pattern Primary use
TRIM / LTRIM / RTRIM TRIM(BOTH ' ' FROM value) Remove whitespace or selected edge characters.
LPAD / RPAD LPAD(value, 10, '0') Create fixed-width labels, codes, or display values.

5. Worked Example

This example parses an email address, standardizes its case, and formats a compact customer label. Each inner function produces a value consumed by the next function.

SELECT
    customer_id,
    LOWER(email) AS normalized_email,
    INITCAP(first_name || ' ' || last_name) AS customer_name,
    SUBSTRING(LOWER(email) FROM 1 FOR POSITION('@' IN LOWER(email)) - 1) AS username,
    SUBSTRING(LOWER(email) FROM POSITION('@' IN LOWER(email)) + 1) AS domain,
    LPAD(customer_id::text, 6, '0') || ' - ' ||
        INITCAP(TRIM(first_name || ' ' || last_name)) AS customer_label
FROM customer;
Result: The query returns a normalized email, a display-ready name, separate username and domain components, and a six-character zero-padded customer identifier.

6. Validation and Troubleshooting

  • Check POSITION() or STRPOS() before using a delimiter-derived length.
  • Compare the original value beside the transformed value while developing a query.
  • Confirm whether the requested substring start and length are one-based and inclusive for the function form being used.
  • Test padding with values both shorter and longer than the requested output width.
Red flag: Unexpected empty strings, missing final characters, or negative substring lengths usually indicate an off-by-one boundary or a delimiter that was not present.

7. Common Mistakes

Forgetting separators during concatenation first_name || last_name produces one fused value. Add an explicit literal such as ' ', ', ', or ' - '.
Including the delimiter in the extracted text Subtract 1 when extracting the text before a delimiter, and add 1 when starting after it.
Treating LPAD or RPAD as append-only functions The length argument is the total output length. PostgreSQL may truncate an input that is already longer than that width.

8. Interview Translation

How would you split an email address into username and domain? Locate @ with POSITION() or STRPOS(), extract the characters before it for the username, and start one character after it for the domain.
When would you use CONCAT() instead of ||? Both combine text. || is compact and readable for a few expressions; CONCAT() can be clearer for a longer argument list and has different NULL handling that should be chosen deliberately.
How do you clean and standardize a user-entered label? Trim unwanted edge whitespace, normalize case with LOWER(), UPPER(), or INITCAP(), replace known bad text where appropriate, and validate the transformed result beside the source.

9. Memory Review

Section summary
  1. Concatenate with || or CONCAT(); include separators explicitly.
  2. Use length and position functions to calculate text boundaries.
  3. Use LEFT/RIGHT for edge extraction and SUBSTRING/SUBSTR for position-based extraction.
  4. TRIM cleans edges; LPAD and RPAD create a requested total width.

Quick self-check

  • Can you extract everything before and after @ without including the delimiter?
  • Can you explain the difference between a start position and a substring length?
  • Can you predict what LPAD does when the source value is already too long?
  • Can you combine trimming, case conversion, and concatenation in one readable expression?
