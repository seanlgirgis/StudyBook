1. Big Picture

A PostgreSQL data type determines what a column can store, which operators are valid, how comparisons behave, and which functions can be applied. Before manipulating unfamiliar data, inspect the actual type instead of guessing from how the value looks.

column value ↓ identify actual data type ↓ choose valid function or operator ↓ validate returned type and result

2. Text, Numeric, and Metadata Types

Text values may use CHAR, VARCHAR, or TEXT. Whole numbers commonly use SMALLINT, INTEGER, or BIGINT, while exact decimal values use NUMERIC or DECIMAL. When the type is unknown, query information_schema.columns rather than inferring it from displayed values.

SELECT
    column_name,
    data_type,
    character_maximum_length,
    numeric_precision,
    numeric_scale
FROM information_schema.columns
WHERE table_schema = 'public'
  AND table_name = 'payment'
ORDER BY ordinal_position;
What to notice: A value that looks numeric may still be stored as text. Metadata reveals the real type.

3. Date, Time, Timestamp, and Interval

DATE stores a calendar date, TIME stores a time of day, TIMESTAMP stores both date and time, and TIMESTAMPTZ represents an absolute moment displayed in the session time zone. INTERVAL stores an amount of elapsed time rather than a point on the calendar.

SELECT create_date
FROM customer
LIMIT 5;

SELECT rental_date,
       return_date,
       return_date - rental_date AS rental_duration
FROM rental
WHERE return_date IS NOT NULL
LIMIT 5;
Common trap: Do not treat TIMESTAMP and INTERVAL as interchangeable. One is a point in time; the other is a duration.

4. Arrays, Indexing, ANY, and Containment

PostgreSQL arrays hold ordered collections of values of the same base type. Array subscripts normally start at 1. ANY compares one scalar value with each array element, while @> checks whether one array contains another array.

Pattern Question answered Important rule
'Trailers' = ANY(special_features) Does this scalar equal at least one array element? ANY compares one value against each element.
special_features @> ARRAY['Trailers'] Does the left array contain the right array? Both sides are arrays; cast when PostgreSQL cannot infer the type.

5. Worked Example

This example first inspects the type of the film.special_features column, then searches for films containing the Trailers feature using both supported patterns.

SELECT column_name, data_type
FROM information_schema.columns
WHERE table_schema = 'public'
  AND table_name = 'film'
  AND column_name = 'special_features';

SELECT title
FROM film
WHERE 'Trailers' = ANY (special_features);

SELECT title
FROM film
WHERE special_features @> ARRAY['Trailers']::text[];
Result: The metadata query confirms the column type, and the two search expressions return films whose special_features array includes Trailers.

6. Validation and Troubleshooting

  • Filter information_schema.columns by both table_schema and table_name when duplicate table names may exist.
  • Confirm that an array column has the expected base type before constructing a typed array literal.
  • Remember that PostgreSQL array indexing normally begins at 1, not 0.
  • Use NUMERIC or DECIMAL for exact monetary values instead of approximate floating-point types.
Red flag: Choosing a function only because a displayed value looks like text, a number, or a date can produce invalid logic.

7. Common Mistakes

Guessing a column type from its displayed value Inspect information_schema.columns or another catalog view before selecting functions and operators.
Using zero-based array indexes PostgreSQL arrays normally begin at index 1; array_col[1] retrieves the first element.
Confusing ANY with array containment Use = ANY(array_col) for scalar-to-element comparison and @> for array-to-array containment.

8. Interview Translation

How do you determine a column's data type in PostgreSQL? I query information_schema.columns, usually filtering by schema, table, and column, so I can choose functions and operators based on the real type.
What is the difference between TIMESTAMP and INTERVAL? A timestamp represents a point in time, while an interval represents an amount of elapsed time.
How do ANY and @> differ for arrays? ANY compares one scalar value against the elements of an array. @> tests whether the left array contains the right array.
