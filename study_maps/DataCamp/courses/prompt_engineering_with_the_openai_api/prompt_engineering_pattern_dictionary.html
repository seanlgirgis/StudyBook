1. Prompt Structure and Control

System Prompt

Defines persistent role, scope, tone, rules, and fallback behavior.

System: "You are a finance assistant. Answer only finance questions."
Do not rely on the system prompt alone for security or guaranteed compliance.

User Prompt

Carries the current request, source text, or task-specific input.

User: "Summarize the report in three bullets."
A vague request produces a vague or inconsistent result.

Assistant Example

Demonstrates a desired answer pattern inside a conversation.

User: "Great service."\nAssistant: "Positive"
One example does not define the entire valid label set unless the rules also do so.

Delimiter Pattern

Separates instructions from source text or data.

Summarize the text delimited by triple backticks.\n```{text}```
Delimiters improve separation but do not make untrusted content safe.

Explicit Constraint

Makes length, tone, format, labels, or exclusions testable.

Return exactly three bullets. Use only: Positive, Negative, Neutral.
Too many conflicting constraints can reduce quality.

Output Contract

Defines the exact sections, keys, order, or labels expected.

CATEGORY: <label>\nCUSTOMER: <name>\nAMOUNT: <number>
Human-readable structure is not automatically machine-validated.

2. Example-Based Prompting

Zero-Shot Prompting

Gives the task with no worked examples.

Classify as Positive, Negative, or Neutral. Return only the label.
Best for simple, familiar tasks with clear instructions.

One-Shot Prompting

Adds one input-output example to demonstrate a pattern.

Example: "Excellent service" → Positive\nNow classify: "Delivery was late"
One example may overrepresent one class or style.

Few-Shot Prompting

Uses several examples to teach classes, formats, or transformations.

Positive example\nNegative example\nNeutral example\nNew input
Examples should be consistent and representative; cover every class when classifying.

Few-Shot Reasoning

Demonstrates a brief calculation or reasoning format before a new problem.

60 ÷ 3 = 20. Final answer: 20 tickets/hour.\nNow solve: 150 in 5 hours.
Do not encourage unnecessary long reasoning for trivial tasks.

Sample Conversation Context

Uses prior user/assistant turns to teach facts and response behavior.

User: "Do you build apps?"\nAssistant: "Yes, we provide mobile app development."
The model may still strengthen wording beyond the exact source.

Pattern Consistency

Keeps labels, field names, punctuation, and ordering identical across examples.

Customer: ...\nInvoice: ...\nAmount: ...
Inconsistent examples teach inconsistent output.

3. Decomposition and Reasoning Styles

Multi-Step Prompting

Breaks a task into ordered stages where later work uses earlier results.

Step 1: Identify the problem.\nStep 2: Infer the trigger.\nStep 3: Recommend the first action.
Several requested fields are not automatically multi-step; dependency matters.

Tiered Response Pattern

A memory label for multi-step output where each tier builds on the previous tier.

Problem → Trigger → First action
This is a useful personal label, not the standard industry term.

Brief Reasoning Prompt

Requests a concise calculation or explanation before the final answer.

Give a brief calculation, then the final answer.
Prefer concise, inspectable reasoning over long internal traces.

Self-Consistency

Compares multiple candidate solutions and selects the majority or best-supported answer.

Generate 3 independent solutions. Choose by majority vote.
Agreement does not prove correctness; candidates may share the same error.

Hypothesis Comparison

Generates competing explanations, attaches evidence, and selects the strongest.

HYPOTHESIS 1... EVIDENCE 1... BEST SUPPORTED CAUSE...
A plausible hypothesis is not a confirmed root cause.

Temperature Comparison

Tests how low and moderate temperature affect stability and variation.

temperature=0.0 vs temperature=0.7
Higher temperature permits variation; it does not guarantee meaningfully different reasoning.

4. Business Transformation Patterns

Summarization

Compresses source material while preserving the essential meaning.

Summarize into 3 bullets: result, concern, next action.
Always compare the summary with the source for omissions or changed meaning.

Expansion

Turns short notes into polished prose.

Expand these notes into one paragraph under 120 words.
Expand the wording, not the facts; forbid invented causes, claims, and applications.

Tone Adjustment

Changes presentation for an audience while preserving facts and intent.

Rewrite in a professional, positive, user-centric tone.
Do not let improved tone create promises, deadlines, or guarantees.

Translation

Changes language while preserving meaning, timing, and brand tone.

Translate into French, Spanish, and Japanese. Label each section.
Localization may change phrasing; customer-facing output still needs review.

Proofreading

Corrects grammar, spelling, and punctuation without broad rewriting.

Correct language errors only. Preserve meaning and structure.
Proofreading is narrower than rewriting.

Conditional Prompting

Applies a rule only when a condition is met.

If more than one sentence, generate a title; otherwise use N/A.
Define every branch and fallback explicitly.

5. Classification, Extraction, and Machine Output

Classification

Maps input into one allowed category.

Choose exactly one: Billing, Technical, Account, General.
Define the complete label set and reject unexpected labels.

Entity Extraction

Pulls named facts from unstructured text.

Extract customer, invoice, amount, action, deadline.
Use null or N/A for missing fields; do not invent values.

JSON-Only Output

Produces machine-readable structured data.

{"category":"Billing","amount_usd":249}
Valid-looking JSON may still contain incorrect facts or extra keys.

Parse and Validate

Uses deterministic code to parse and check model output.

data = json.loads(response)\nassert data["category"] in allowed
The model proposes; application code decides whether to accept.

Exact Key Validation

Checks that no required keys are missing and no extra keys appear.

if set(data) != expected_keys: reject()
Type checks alone do not catch missing or unexpected fields.

Safe Accept/Reject

Handles malformed or invalid output without crashing the pipeline.

try: parse_and_validate()\nexcept ...: reject\nelse: accept
Production systems also need retry, logging, audit, and human-review paths.

6. Chatbot Design and Stateful Memory

Dual-Prompt Chatbot

Separates persistent system behavior from the current user request.

get_response(system_prompt, user_prompt)
The API call itself is stateless unless history or state is resent.

Domain Boundary

Defines what the chatbot may answer and how it should refuse other requests.

If outside personal finance, reply exactly: "Sorry, I only answer..."
Prompt boundaries improve behavior but are not a complete safety layer.

Role-Playing Prompt

Assigns professional perspective, expertise, audience, and priorities.

You are a cloud engineer. Focus on elasticity, reliability, and operations.
A role should change focus and vocabulary, not merely tone.

System-Prompt Context

Places a small stable knowledge base inside the system message.

COMPANY CONTEXT:\n- Web development\n- Mobile development
Inline context does not scale to large or frequently changing knowledge.

Rolling Conversation State

Carries a compact state forward with each new request.

old_state + new_request → answer + updated_state
Free-form summaries can drift and turn assumptions into facts.

Structured Chat State

Separates facts, recommendations, completed actions, and open questions.

{"confirmed_facts":[],"recommended_actions":[],"completed_actions":[],"open_questions":[]}
Validate the proposed state before storing it.

Technique Selection Map

Need a direct answer? → Zero-shot Need to demonstrate one pattern? → One-shot Need several classes or formats? → Few-shot Need dependent stages? → Multi-step Need multiple candidate answers? → Self-consistency Need polished business text? → Summarize / expand / transform Need machine-readable data? → JSON + deterministic validation Need a focused chatbot? → System contract + boundaries + context Need stateful chat? → Recent messages + structured rolling state
Use the lightest technique that reliably controls the task. Prompt instructions guide the model; deterministic validation, source checking, and application logic decide whether the result is safe enough to use.
