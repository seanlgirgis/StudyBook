Advanced Prompt Engineering Strategies

Use examples, ordered instructions, explicit reasoning structures, and repeated candidate solutions to guide models through more complex tasks. This chapter compares zero-shot, one-shot, few-shot, multi-step, chain-of-thought, and self-consistency prompting.

1. Big Picture

Advanced prompting techniques control a model in different ways. Shots teach by example. Steps teach by explicit instructions. Chain-of-thought asks for intermediate reasoning. Self-consistency compares several independent candidate solutions and selects the most common result. The right technique depends on whether the main need is format imitation, task decomposition, reasoning visibility, or reliability.

Task ↓ Need only a direct answer? → Zero-shot Need one format example? → One-shot Need several patterns or classes? → Few-shot Need ordered work? → Multi-step Need intermediate reasoning? → Chain-of-thought Need more robust reasoning? → Self-consistency

Zero-shot, One-shot, and Few-shot Prompting

Choose the number and diversity of examples based on task complexity and the output pattern the model must learn.

Multi-step Prompting

Break a complex goal into smaller ordered instructions so the model follows a clear roadmap.

Chain-of-Thought and Self-Consistency

Ask for intermediate reasoning when the path matters, and compare multiple candidate solutions when one reasoning path may fail.

Choosing the Right Strategy

Use the lightest technique that gives reliable output: direct instruction first, then examples, ordered steps, or repeated reasoning as complexity grows.

2. Zero-shot, One-shot, and Few-shot Prompting

Zero-shot prompting gives no examples and relies on the model’s existing knowledge. One-shot prompting gives one example, often to teach a desired style or output structure. Few-shot prompting gives multiple examples, which is useful for more complex classification or pattern-learning tasks. In chat models, each example can be represented as a user message followed by the corresponding assistant answer.

messages = [
    {"role": "user", "content": "I love this product."},
    {"role": "assistant", "content": "positive"},
    {"role": "user", "content": "This was a terrible experience."},
    {"role": "assistant", "content": "negative"},
    {"role": "user", "content": "The service was acceptable."}
]

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=messages
)
What to notice: The examples are part of the conversation history. The final user message has no paired assistant answer, so the model completes the demonstrated pattern.

3. Multi-step Prompting

Multi-step prompting explicitly tells the model which steps to perform and in what order. It is useful for sequential generation, such as building a travel blog from introduction to adventure to conclusion, and for evaluation tasks, such as checking syntax first and then checking business or safety rules. Steps are instructions; they are not examples.

prompt = f"""
Review the Python calculator delimited by triple backticks.

Step 1: Check whether the code is syntactically valid.
Step 2: Check whether division by zero is handled.
Step 3: Give a final verdict and one recommended fix.

```{calculator}```
"""
Common trap: Do not confuse steps with shots. Steps tell the model what to do; shots demonstrate how an answer should look.

4. Chain-of-Thought and Self-Consistency

Chain-of-thought prompting requests intermediate reasoning before a final answer, which can help on complex reasoning tasks and make the result easier to inspect. It can also be demonstrated through few-shot examples that include worked reasoning. Self-consistency extends this idea by generating several independent candidate solutions and selecting the most common final answer. This reduces dependence on a single flawed reasoning path.

Technique Best use Main caution
Few-shot prompting Teaching a format, style, class set, or input-output pattern. Examples must be representative and should cover every class in classification tasks.
Multi-step / reasoning prompts Sequential generation, evaluation, and tasks that benefit from decomposed reasoning. Too many vague steps can add noise; a flawed reasoning path can still produce a wrong answer.

5. Worked Example

This example combines few-shot classification with a strict output label. The earlier user/assistant pairs teach the categories, and the final user message is the item to classify.

messages = [
    {"role": "system", "content": "Classify sentiment using only: positive, neutral, or negative."},
    {"role": "user", "content": "The update solved every problem."},
    {"role": "assistant", "content": "positive"},
    {"role": "user", "content": "The product is fine, but not remarkable."},
    {"role": "assistant", "content": "neutral"},
    {"role": "user", "content": "Support never answered my request."},
    {"role": "assistant", "content": "negative"},
    {"role": "user", "content": "The new dashboard works as expected."}
]

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=messages,
    temperature=0
)

print(response.choices[0].message.content)
Result: The model should return one of the demonstrated labels, most likely neutral. The examples constrain both the category set and the expected output format.

6. Validation and Troubleshooting

  • For few-shot classification, include at least one representative example for every class.
  • Keep example labels and formatting consistent so the model learns one clear pattern.
  • For multi-step prompts, verify that every requested step appears in the response and is performed in order.
  • For reasoning tasks, verify the final answer independently; a plausible explanation can still contain an error.
Red flag: Do not treat model-generated reasoning or majority agreement as proof. Self-consistency improves robustness, but several candidates can still share the same mistake.

7. Common Mistakes

Using too few or unbalanced examples Match the number and variety of examples to the task. Multi-class classification should show every class, not only the easiest examples.
Calling a list of instructions “few-shot” A shot is an example input-output pair. A step is an instruction in a task sequence. They solve different control problems.
Trusting one reasoning path automatically Inspect the logic, test edge cases, or generate multiple independent candidates. Reasoning text can be fluent and still be wrong.

8. Interview Translation

What is the difference between zero-shot, one-shot, and few-shot prompting? The difference is the number of examples supplied. Zero-shot uses none, one-shot uses one, and few-shot uses several examples so the model can imitate a desired pattern, format, or classification scheme.
How is multi-step prompting different from few-shot prompting? Multi-step prompting gives explicit ordered instructions. Few-shot prompting gives demonstrations. Steps act as a roadmap; shots act as examples the model generalizes from.
What is self-consistency prompting? It generates multiple independent reasoning-based answers and chooses the most common final result. It reduces reliance on one potentially flawed reasoning path, although it does not guarantee correctness.

9. Memory Review

Section summary
  1. No examples is zero-shot; one example is one-shot; several examples is few-shot.
  2. Shots demonstrate. Steps instruct.
  3. Chain-of-thought exposes intermediate reasoning; multi-step embeds the task steps directly in the prompt.
  4. Self-consistency compares multiple candidate answers and selects the majority result.
