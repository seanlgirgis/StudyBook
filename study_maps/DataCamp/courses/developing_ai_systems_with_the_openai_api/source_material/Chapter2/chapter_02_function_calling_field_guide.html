Function Calling

1. Big Picture

Function calling lets the model select a developer-defined tool and return arguments that follow a declared JSON schema. The model does not execute your Python function by itself: your application must inspect the tool call, parse the arguments, run the matching function, and decide how to present or continue with the result.

User message | v Chat Completions request + tools | v Model selects tool and returns arguments | v Application validates tool name and JSON arguments | v Python function / external API executes | v Application formats the result for the user

Tool Definitions and Structured Arguments

Declare a function name, description, and JSON-schema parameters, then read the returned arguments from message.tool_calls[0].function.arguments.

Multiple Functions and Tool Choice

Pass several functions in tools, inspect every item in tool_calls, and use tool_choice only when the application must require one function.

External API Integration

Use model-generated arguments as validated inputs to a normal Python function that calls a service such as the Art Institute of Chicago API.

Validation and Clarification

Tell the model not to invent missing values, detect empty or incomplete arguments, and ask for clarification rather than silently guessing.

Section punchline: The model proposes a tool call; trusted application code validates and executes it.

2. Tool Definitions and Structured Arguments

A tool definition is supplied through the tools parameter as a list of dictionaries. Each function contains a stable name, a useful description, and a JSON-schema parameters object. The properties define the expected argument names and data types. When the model chooses the function, the arguments arrive as a JSON string inside the first tool call.

import json
from openai import OpenAI

client = OpenAI()

extract_job_tool = {
    "type": "function",
    "function": {
        "name": "extract_job_info",
        "description": "Extract job title and office location from text.",
        "parameters": {
            "type": "object",
            "properties": {
                "job": {
                    "type": "string",
                    "description": "The job title.",
                },
                "location": {
                    "type": "string",
                    "description": "The office location.",
                },
            },
            "required": ["job", "location"],
            "additionalProperties": False,
        },
    },
}

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {
            "role": "user",
            "content": (
                "We are hiring a Data Scientist in our Berlin office."
            ),
        }
    ],
    tools=[extract_job_tool],
)

tool_call = response.choices[0].message.tool_calls[0]
arguments = json.loads(tool_call.function.arguments)

print(tool_call.function.name)
print(arguments)
What to notice: tool_calls is a list because the model may request more than one function. The arguments value is JSON text, so parse it with json.loads() before validation or execution.

3. Multiple Functions and Tool Choice

Parallel function calling occurs when the model returns multiple tool calls for one user request. By default, tool_choice behaves like auto, allowing the model to select a suitable function. A specific function can be required by passing a tool_choice dictionary naming that function. Forcing a tool can improve routing consistency, but it may also encourage the model to fill missing values unless the prompt explicitly forbids assumptions.

tools = [extract_job_tool, timezone_tool]

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=messages,
    tools=tools,
    tool_choice="auto",
)

for tool_call in response.choices[0].message.tool_calls or []:
    name = tool_call.function.name
    arguments = json.loads(tool_call.function.arguments)
    print(name, arguments)

# Force one function when the workflow requires it
forced_response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=messages,
    tools=tools,
    tool_choice={
        "type": "function",
        "function": {"name": "extract_job_info"},
    },
)
Common trap: Do not assume tool_calls[0] is always the only result. Iterate over the list, validate the function name against an allow-list, and reject or clarify missing arguments instead of trusting model assumptions.

4. External API Integration

Function calling can bridge natural-language requests to external services. The model should extract a narrow argument such as an artwork keyword; your Python code then uses requests to call the external API. Always check the finish reason or presence of tool_calls, parse the arguments, validate them, apply a timeout, check the HTTP response, and post-process the provider-specific payload.

Stage Responsibility Failure to guard against
Model tool selection Choose a declared function and return schema-shaped arguments. Unknown tool name, missing argument, invented value, or malformed JSON.
Application execution Validate arguments, call the Python function or external API, and handle its response. Network timeout, non-200 response, unsafe input, or provider payload changes.

5. Worked Example

This end-to-end pattern lets the model extract one artwork keyword and then safely calls the Art Institute of Chicago public API. The application—not the model—performs the network request.

import json
import requests
from openai import OpenAI

client = OpenAI()

def get_artwork(keyword: str) -> list[dict[str, str]]:
    response = requests.get(
        "https://api.artic.edu/api/v1/artworks/search",
        params={
            "q": keyword,
            "fields": "title,artist_display",
            "limit": 3,
        },
        timeout=10,
    )
    response.raise_for_status()

    return [
        {
            "title": item.get("title", "Unknown"),
            "artist": item.get("artist_display", "Unknown"),
        }
        for item in response.json().get("data", [])
    ]

artwork_tool = {
    "type": "function",
    "function": {
        "name": "get_artwork",
        "description": "Find artworks related to one keyword.",
        "parameters": {
            "type": "object",
            "properties": {
                "keyword": {
                    "type": "string",
                    "description": "One artwork search keyword.",
                }
            },
            "required": ["keyword"],
            "additionalProperties": False,
        },
    },
}

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {
            "role": "system",
            "content": (
                "Extract one artwork keyword. Do not invent details "
                "that are not present in the user's request."
            ),
        },
        {
            "role": "user",
            "content": "I enjoy paintings of the seaside.",
        },
    ],
    tools=[artwork_tool],
)

message = response.choices[0].message

if not message.tool_calls:
    raise ValueError("No tool call was returned.")

tool_call = message.tool_calls[0]

if tool_call.function.name != "get_artwork":
    raise ValueError("Unexpected tool requested.")

arguments = json.loads(tool_call.function.arguments)
keyword = arguments.get("keyword", "").strip()

if not keyword:
    raise ValueError("A keyword is required.")

print(get_artwork(keyword))
Result: The model supplies a narrow keyword such as seaside; the application validates it, calls the museum API with a timeout, checks the HTTP status, and returns selected artwork fields.

6. Validation and Troubleshooting

  • Confirm message.tool_calls exists before indexing it, and inspect every returned call when parallel function calling is possible.
  • Allow only known function names, parse arguments with json.loads(), and validate required fields, data types, ranges, and allowed values.
  • When information is absent, instruct the model not to assume and handle empty dictionaries or incomplete arguments by asking the user for clarification.
  • For external APIs, use timeouts, raise_for_status(), bounded retries where appropriate, and defensive parsing because provider response formats can change.
Red flag: Executing an arbitrary function name or passing unvalidated model arguments directly into a database, shell command, payment action, or external API.

7. Common Mistakes

Believing the model executes the function The model returns a proposed function name and arguments. Your application must validate them and run the actual Python function.
Reading normal content instead of tool_calls A tool response is normally found in message.tool_calls, with arguments in tool_call.function.arguments—not in message.content.
Forcing a function and trusting invented values A forced function can still receive guessed arguments. Tell the model not to assume, declare required fields carefully, and reject missing or unsupported values.

8. Interview Translation

What is OpenAI function calling? It is a mechanism for giving the model developer-defined tool schemas so it can return a selected function name and structured arguments. The application remains responsible for validation and execution.
How do you safely execute a tool call? I verify that a tool call exists, allow-list the function name, parse the JSON arguments, validate them against business rules, execute only the mapped function, handle failures, and log the outcome without exposing secrets.
What is parallel function calling? It is when the model returns multiple tool calls for one request. I iterate over tool_calls, validate each call independently, execute allowed tools, and combine or return their results according to the workflow.

9. Memory Review

Section summary
  1. tools describes available capabilities; it does not execute them.
  2. Read arguments from message.tool_calls[n].function.arguments and parse the JSON string.
  3. tool_choice='auto' lets the model route; forcing a function requires extra checks against invented values.
  4. External APIs are normal application code: validate inputs, use timeouts, check statuses, and parse defensively.

Quick self-check

  • Can I build a tools list containing a function name, description, parameter schema, and required fields?
  • Can I extract and parse one or several tool calls without assuming only index 0 exists?
  • Can I explain when to use auto tool choice and when forcing a specific function is justified?
  • Can I safely map a validated tool call to a Python function that invokes an external API?
