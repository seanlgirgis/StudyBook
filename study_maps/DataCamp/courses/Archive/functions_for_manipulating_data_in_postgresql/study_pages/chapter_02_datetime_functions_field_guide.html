Section 4

Date Arithmetic

This section is about knowing both the arithmetic pattern and the resulting type. PostgreSQL is consistent here, and that consistency helps when you build production logic.

SELECT DATE '2026-06-01' + 5 AS five_days_later;
SELECT DATE '2026-06-10' - DATE '2026-06-01' AS day_count;
SELECT
  rental_date,
  rental_date + INTERVAL '5 days' AS expected_return_date
FROM rental;
SELECT
  return_date - rental_date AS elapsed_time
FROM rental;
ExpressionResult
DATE + integerDATE
DATE - integerDATE
DATE - DATEinteger days
TIMESTAMP + INTERVALTIMESTAMP
TIMESTAMP - TIMESTAMPINTERVAL
Common trap: DATE - DATE returns integer days. TIMESTAMP - TIMESTAMP returns INTERVAL.

Section 5

Interval Arithmetic

Intervals are how PostgreSQL represents durations and offsets. They are essential when an integer count of days needs to become a true duration.

SELECT INTERVAL '1 day' * 5 AS five_days;
SELECT
  rental_date
  + INTERVAL '1 day' * rental_duration
  AS expected_return_date
FROM film_rentals;

Note: film_rentals is a conceptual teaching table name here. Adapt it to a real joined query or local table before running it. 

SELECT
  INTERVAL '2 hours' + INTERVAL '30 minutes'
  AS total_duration;
SELECT
  CURRENT_TIMESTAMP - INTERVAL '12 hours' AS prior_moment;
INTERVAL '1 day' * rental_duration turns an integer count of days into a real interval.

Section 6

Current Date and Time

Core current-value tools

CURRENT_DATE, CURRENT_TIME, CURRENT_TIMESTAMP, and NOW() are the main built-ins for current values.

Precision control

CURRENT_TIMESTAMP(0) means current timestamp with no fractional seconds.

SELECT
  CURRENT_DATE AS today,
  CURRENT_TIME AS current_time,
  CURRENT_TIMESTAMP AS right_now;
SELECT
  CURRENT_TIMESTAMP(0)::timestamp AS right_now,
  CURRENT_TIMESTAMP(0)::timestamp + INTERVAL '5 days'
    AS five_days_from_now;
SELECT NOW() AS now_value;
Trap: The number in CURRENT_TIMESTAMP(0) is precision, not a date value.

Section 7

AGE()

Use AGE() when you want a calendar-style interval, especially for years/months/days style interpretation. Use direct subtraction when you want raw elapsed duration.

SELECT
  AGE(return_date, rental_date) AS rental_age
FROM rental;
SELECT
  AGE(rental_date) AS time_since_rental;

SELECT
  AGE(CURRENT_DATE, DATE '1968-06-21') AS age_interval;
AGE(timestamp) compares the timestamp with CURRENT_DATE at midnight.
MethodBest for
end - startdirect elapsed interval
AGE(end, start)calendar-style years/months/days
Trap: AGE() returns an INTERVAL, not a number.

Section 8

EXTRACT() and DATE_PART()

These functions turn timestamps and intervals into numeric features. They are great for slicing, labeling, and building derived metrics.

SELECT
  EXTRACT(year FROM rental_date) AS rental_year,
  EXTRACT(month FROM rental_date) AS rental_month,
  EXTRACT(quarter FROM rental_date) AS rental_quarter
FROM rental;
SELECT
  DATE_PART('year', rental_date) AS rental_year,
  DATE_PART('month', rental_date) AS rental_month
FROM rental;
SELECT
  EXTRACT(EPOCH FROM return_date - rental_date) / 3600
    AS total_hours
FROM rental;
SELECT
  EXTRACT(hour FROM rental_date) AS rental_hour,
  EXTRACT(minute FROM rental_date) AS rental_minute
FROM rental;
EXTRACT(hour FROM interval) returns only the hour component. EXTRACT(EPOCH FROM interval) / 3600 returns total hours.

Section 9

Day of Week

day

Day of month.

dow

Sunday 0 through Saturday 6.

isodow

Monday 1 through Sunday 7.

SELECT
  rental_date,
  EXTRACT(day FROM rental_date) AS day_of_month,
  EXTRACT(dow FROM rental_date) AS postgres_day_of_week,
  EXTRACT(isodow FROM rental_date) AS iso_day_of_week
FROM rental;
SELECT
  EXTRACT(dow FROM DATE '2026-06-07') AS postgres_dow,
  EXTRACT(isodow FROM DATE '2026-06-07') AS iso_dow;
SELECT
  rental_date,
  TO_CHAR(rental_date, 'FMDay') AS weekday_name
FROM rental;
SELECT
  CASE
    WHEN EXTRACT(isodow FROM rental_date) IN (6, 7)
      THEN 'Weekend'
    ELSE 'Weekday'
  END AS day_type,
  COUNT(*) AS rental_count
FROM rental
GROUP BY day_type;
SELECT
  EXTRACT(isodow FROM rental_date) AS iso_weekday,
  TO_CHAR(rental_date, 'FMDay') AS weekday_name,
  COUNT(*) AS rental_count
FROM rental
GROUP BY
  EXTRACT(isodow FROM rental_date),
  TO_CHAR(rental_date, 'FMDay')
ORDER BY iso_weekday;
Common trap: EXTRACT(day FROM date) is day of month, not weekday.

Section 10

DATE_TRUNC()

Use DATE_TRUNC() when you need a timestamp bucket for grouping and reporting. It gives you a normalized timestamp anchor, not just a number.

SELECT
  DATE_TRUNC('day', rental_date) AS rental_day
FROM rental;
SELECT
  DATE_TRUNC('month', rental_date) AS rental_month,
  COUNT(*) AS rental_count
FROM rental
GROUP BY DATE_TRUNC('month', rental_date)
ORDER BY rental_month;
SELECT
  DATE_TRUNC('quarter', payment_date) AS payment_quarter,
  SUM(amount) AS total_amount
FROM payment
GROUP BY DATE_TRUNC('quarter', payment_date)
ORDER BY payment_quarter;
SELECT
  DATE_TRUNC('week', rental_date) AS rental_week,
  DATE_TRUNC('year', rental_date) AS rental_year_bucket,
  DATE_TRUNC('hour', rental_date) AS rental_hour_bucket
FROM rental;
In PostgreSQL, DATE_TRUNC('week', timestamp) returns the Monday at the start of the ISO-style week.
EXTRACT returns a number. DATE_TRUNC returns a timestamp bucket. Grouping by EXTRACT(month) alone can mix different years.

Section 12

NULL and Open Records

Open rentals often have a missing return_date. Reporting still needs an endpoint, so queries often use COALESCE().

SELECT
  rental_id,
  rental_date,
  COALESCE(return_date, CURRENT_TIMESTAMP) AS effective_return_date
FROM rental;
SELECT
  rental_id,
  COALESCE(return_date, CURRENT_TIMESTAMP) - rental_date
    AS elapsed_or_open_duration
FROM rental;
COALESCE does not update the stored return_date. It only provides a fallback value in the query result.

Section 13

Overdue Logic

SELECT
  rental_date,
  rental_date
    + INTERVAL '1 day' * rental_duration
    AS expected_return_date
FROM rental_report;

Note: rental_report is a conceptual reporting table name here. Replace it with a real report CTE, join, or local table when you run the query. 

SELECT
  CASE
    WHEN COALESCE(return_date, CURRENT_TIMESTAMP)
         >
         rental_date + INTERVAL '1 day' * rental_duration
      THEN TRUE
    ELSE FALSE
  END AS past_due
FROM rental_report;
CASE
  WHEN DATE_TRUNC(
         'day',
         AGE(return_date, rental_date)
       ) > rental_duration * INTERVAL '1 day'
    THEN TRUE
  ELSE FALSE
END AS past_due
Both sides of the comparison must be compatible. The actual duration is an interval. The allowed duration must also be converted to an interval.

Section 14

Combined Examples

Example 1: Expected return date

Business question: When is each rental expected back?

SELECT
  rental_id,
  rental_date,
  rental_date + INTERVAL '1 day' * rental_duration
    AS expected_return_date
FROM rental_report;

What to notice: integer rental days are converted into interval days.

Likely mistake: adding bare integer days to a timestamp.

Example 2: Current timestamp plus five days

Business question: What will the current moment be five days from now?

SELECT
  CURRENT_TIMESTAMP(0)::timestamp AS right_now,
  CURRENT_TIMESTAMP(0)::timestamp + INTERVAL '5 days'
    AS five_days_from_now;

What to notice: precision control cleans up the current timestamp.

Likely mistake: thinking (0) is part of the date logic.

Example 3: Rental duration in total hours

Business question: How many hours did each rental last?

SELECT
  rental_id,
  ROUND(
    EXTRACT(EPOCH FROM return_date - rental_date) / 3600.0,
    2
  ) AS rental_hours
FROM rental;

What to notice: EPOCH converts interval into total seconds first.

Likely mistake: using EXTRACT(hour FROM interval) for total hours.

Example 4: Monthly rental count

Business question: How many rentals occurred each month?

SELECT
  DATE_TRUNC('month', rental_date) AS rental_month,
  COUNT(*) AS rental_count
FROM rental
GROUP BY DATE_TRUNC('month', rental_date)
ORDER BY rental_month;

What to notice: month bucket preserves year context.

Likely mistake: grouping only by numeric month.

Example 5: Weekday/weekend rental report

Business question: Are rentals happening more on weekdays or weekends?

SELECT
  CASE
    WHEN EXTRACT(isodow FROM rental_date) IN (6, 7)
      THEN 'Weekend'
    ELSE 'Weekday'
  END AS day_type,
  COUNT(*) AS rental_count
FROM rental
GROUP BY day_type;

What to notice: ISO weekday keeps weekend logic readable.

Likely mistake: mixing dow and isodow.

Example 6: Open rental duration

Business question: How long has each still-open rental been out so far?

SELECT
  rental_id,
  COALESCE(return_date, CURRENT_TIMESTAMP) - rental_date
    AS elapsed_or_open_duration
FROM rental;

What to notice: current timestamp is only a reporting fallback.

Likely mistake: assuming COALESCE changes stored data.

Example 7: Past-due flag

Business question: Which rentals are overdue right now?

SELECT
  rental_id,
  CASE
    WHEN COALESCE(return_date, CURRENT_TIMESTAMP)
         > rental_date + INTERVAL '1 day' * rental_duration
      THEN TRUE
    ELSE FALSE
  END AS past_due
FROM rental_report;

What to notice: actual and allowed durations are compared with compatible types.

Likely mistake: comparing interval logic to raw integer days.

Example 8: Ninety-day rental window

Business question: Which rentals fall inside a 90-day study window?

SELECT
  rental_id,
  rental_date
FROM rental
WHERE rental_date BETWEEN DATE '2005-05-01'
                      AND DATE '2005-05-01' + INTERVAL '90 days';

What to notice: the range endpoint is built from the start date plus interval.

Likely mistake: forgetting how inclusive BETWEEN is.

Production note: half-open ranges are often safer, for example rental_date >= TIMESTAMP '2005-05-01' AND rental_date < TIMESTAMP '2005-05-01' + INTERVAL '90 days'.

Section 16

Interview Q&A

DATE versus TIMESTAMP?

DATE stores the day only; TIMESTAMP stores both date and time.

TIMESTAMP versus INTERVAL?

A timestamp is a moment; an interval is a duration or offset.

DATE subtraction versus TIMESTAMP subtraction?

DATE - DATE returns integer days. TIMESTAMP - TIMESTAMP returns interval.

What does CURRENT_TIMESTAMP(0) mean?

It means current timestamp with zero fractional-second precision.

AGE() versus direct subtraction?

AGE() is calendar-style. Direct subtraction gives raw elapsed interval.

EXTRACT versus DATE_PART?

They are equivalent in purpose; DATE_PART uses quoted part names.

EXTRACT versus DATE_TRUNC?

EXTRACT returns a number. DATE_TRUNC returns a truncated timestamp bucket.

Why does DATE_TRUNC help reporting?

It creates stable day/week/month/quarter buckets for grouping.

How do you get weekday?

Use EXTRACT(dow FROM ...) or EXTRACT(isodow FROM ...), and TO_CHAR for readable names.

dow versus isodow?

dow is Sunday 0 to Saturday 6. isodow is Monday 1 to Sunday 7.

How do you calculate total hours?

Use EXTRACT(EPOCH FROM interval) / 3600.

How do you handle open rentals?

Use COALESCE(return_date, CURRENT_TIMESTAMP) as a reporting fallback endpoint.

How do you calculate expected return date?

Add an interval to the rental timestamp, often INTERVAL '1 day' * rental_duration.

How do you build a past-due flag?

Compare actual end time or fallback end time to expected return time inside a CASE.

Why must both sides of interval comparison be compatible?

Because comparing interval to integer or unrelated type produces wrong logic or errors.
