1. Big Picture

Filtering reduces a table to only the rows that meet a condition. The WHERE clause is logically evaluated after FROM and before SELECT.

FROM films ↓ WHERE condition ↓ SELECT requested fields ↓ Return matching rows
Core idea: SELECT chooses columns; WHERE chooses rows.

2. WHERE Basics

A WHERE clause keeps only rows for which its condition evaluates to true. 

SELECT title,
       release_year
FROM films
WHERE release_year = 2020;

3. Filtering Numbers

Exact numeric match

SELECT title,
       release_year
FROM films
WHERE release_year = 2019;

Range with comparison operators

SELECT title,
       imdb_score
FROM films
WHERE imdb_score >= 7.5;

Exclude one numeric value

SELECT title,
       duration
FROM films
WHERE duration <> 120;
Numeric literals are not placed in quotes. Write 2020, not '2020', when the field is numeric.

4. Filtering Text

Text values use single quotes. 

SELECT title,
       country
FROM films
WHERE country = 'Canada';
SELECT title,
       language
FROM films
WHERE language <> 'English';
Double quotes are for identifiers in PostgreSQL. Single quotes are for text values.

5. Combining Conditions with AND and OR

AND: every condition must be true

SELECT title,
       country,
       imdb_score
FROM films
WHERE country = 'Canada'
  AND imdb_score >= 7.0;

OR: at least one condition must be true

SELECT title,
       country
FROM films
WHERE country = 'Canada'
   OR country = 'Germany';

Use parentheses when mixing AND and OR

SELECT title,
       country,
       release_year
FROM films
WHERE (country = 'Canada' OR country = 'Germany')
  AND release_year >= 2019;
Memory rule: AND narrows; OR broadens.

6. Filtering Ranges with BETWEEN

BETWEEN is inclusive of both endpoints. 

SELECT title,
       release_year
FROM films
WHERE release_year BETWEEN 2018 AND 2021;

This is equivalent to:

SELECT title,
       release_year
FROM films
WHERE release_year >= 2018
  AND release_year <= 2021;
Important: BETWEEN 2018 AND 2021 includes both 2018 and 2021.

7. Pattern Matching with LIKE and NOT LIKE

Wildcard Meaning Example pattern
%Zero or more characters'M%'
_Exactly one character'_a%'

Starts with

SELECT title
FROM films
WHERE title LIKE 'B%';

Contains

SELECT title
FROM films
WHERE title LIKE '%Market%';

Does not match a pattern

SELECT title
FROM films
WHERE title NOT LIKE '%Film%';

Case-insensitive PostgreSQL search

SELECT title
FROM films
WHERE title ILIKE '%market%';
ILIKE is PostgreSQL-specific and performs case-insensitive pattern matching.

8. Matching a List with IN and NOT IN

SELECT title,
       country
FROM films
WHERE country IN ('Canada', 'Germany', 'France');

This is cleaner than repeating several OR conditions.

SELECT title,
       certification
FROM films
WHERE certification NOT IN ('R', 'PG-13');
Be careful when a NOT IN list or subquery contains NULL. NULL can make the comparison evaluate to unknown rather than true.

9. Combining Filtering and Selecting

Choose only the needed columns and then filter the source rows. 

SELECT title,
       country,
       release_year,
       imdb_score
FROM films
WHERE release_year >= 2020
  AND country IN ('Canada', 'United States', 'United Kingdom')
  AND imdb_score >= 7.0;
A strong query answers a specific question with only the necessary rows and columns.

10. Understanding and Filtering NULL Values

NULL means a value is missing, unknown, or not applicable. It is not zero, not an empty string, and not the text 'NULL'.

Find missing values

SELECT title,
       budget
FROM films
WHERE budget IS NULL;

Find known values

SELECT title,
       imdb_score
FROM films
WHERE imdb_score IS NOT NULL;
Do not write budget = NULL or budget <> NULL. Comparisons with NULL evaluate to unknown. Use IS NULL or IS NOT NULL.

NULL and COUNT

SELECT COUNT(*) AS total_rows,
       COUNT(budget) AS known_budgets
FROM films;

COUNT(*) counts all rows. COUNT(budget) counts only non-NULL budget values.

Three-valued logic

TRUE

The row passes the WHERE filter.

FALSE

The row is removed.

UNKNOWN

The row is also removed. NULL comparisons often produce UNKNOWN.

11. Common Mistakes

Using double quotes for text PostgreSQL uses single quotes for string values: country = 'Canada'.
Using = NULL Use IS NULL or IS NOT NULL.
Forgetting BETWEEN is inclusive Both boundary values are included.
Mixing AND and OR without parentheses Parentheses make the intended logic explicit and prevent precedence surprises.
Using = with wildcard characters Use LIKE, not =, when using % or _.
Assuming LIKE is always case-insensitive In PostgreSQL, LIKE is case-sensitive and ILIKE is case-insensitive.

12. Interview Translation

What is the purpose of WHERE? It filters source rows so only records satisfying the condition remain.
What is the difference between AND and OR? AND requires all conditions to be true, while OR requires at least one condition to be true.
Is BETWEEN inclusive? Yes. It includes both the lower and upper boundary.
What do % and _ mean in LIKE? % matches zero or more characters; _ matches exactly one character.
How do you test for NULL? Use IS NULL or IS NOT NULL, not equality operators.
What does NULL mean? It represents missing, unknown, or not-applicable data and participates in three-valued logic.

13. Memory Review

Eight-sentence chapter summary

  2. Numeric values are normally unquoted.
  3. Text values use single quotes.
  4. AND narrows and OR broadens.
  5. BETWEEN includes both endpoints.
  6. LIKE uses % and _ wildcards.
  7. IN matches against a list of values.
  8. NULL requires IS NULL or IS NOT NULL.
