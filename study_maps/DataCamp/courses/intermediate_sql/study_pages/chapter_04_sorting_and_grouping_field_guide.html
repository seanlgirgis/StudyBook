Sorting and Grouping

Sort rows with ORDER BY, group records with GROUP BY, filter aggregate results with HAVING, and combine these clauses to answer practical business questions about film performance, durations, budgets, and trends.

1. Big Picture

Sorting changes the order in which rows appear. Grouping changes the level of detail by collapsing rows into categories and calculating summaries for each category.

ORDER BY

Rearranges rows without changing how many rows exist.

GROUP BY

Combines rows into groups and usually returns one row per group.

Core idea: sorting changes presentation; grouping changes granularity.

2. Sorting Results with ORDER BY

ORDER BY sorts the final result set.

Ascending order

SELECT title,
       release_year
FROM films
ORDER BY release_year;

ASC is the default:

SELECT title,
       release_year
FROM films
ORDER BY release_year ASC;

Descending order

SELECT title,
       imdb_score
FROM films
ORDER BY imdb_score DESC;
Without ORDER BY, row order is not guaranteed.

3. Sorting by Multiple Fields

SQL sorts by the first expression, then uses the second expression to break ties. 

SELECT title,
       release_year,
       imdb_score
FROM films
ORDER BY release_year ASC,
         imdb_score DESC;
Primary sort: release_year ascending ↓ Tie-breaker: imdb_score descending

Mixing directions

SELECT title,
       country,
       release_year
FROM films
ORDER BY country ASC,
         release_year DESC;
Memory rule: sort priority follows the left-to-right order of expressions.

4. Grouping Data with GROUP BY

GROUP BY creates one group for each unique value and allows an aggregate function to summarize each group. 

SELECT country,
       COUNT(*) AS film_count
FROM films
GROUP BY country;
SELECT genre,
       ROUND(AVG(imdb_score), 2) AS average_score
FROM films
GROUP BY genre;
In a grouped query, every selected expression must either be aggregated or appear in GROUP BY.

Invalid pattern

SELECT country,
       title,
       COUNT(*)
FROM films
GROUP BY country;

The database cannot choose one title to represent an entire country group.

5. GROUP BY Multiple Fields

Grouping by multiple fields creates one group per unique combination. 

SELECT country,
       language,
       COUNT(*) AS film_count
FROM films
GROUP BY country,
         language;

(Canada, English) and (Canada, French) are separate groups. 

SELECT release_year,
       genre,
       AVG(duration) AS average_duration
FROM films
GROUP BY release_year,
         genre;
More grouping columns produce more detailed groups and usually more output rows.

6. Answering Business Questions

Which countries produced the most films?

SELECT country,
       COUNT(*) AS film_count
FROM films
GROUP BY country
ORDER BY film_count DESC;

Which genre has the highest average score?

SELECT genre,
       ROUND(AVG(imdb_score), 2) AS average_score
FROM films
GROUP BY genre
ORDER BY average_score DESC;

How did average duration change over time?

SELECT release_year,
       ROUND(AVG(duration), 2) AS average_duration
FROM films
GROUP BY release_year
ORDER BY release_year;
Grouped SQL is powerful because it translates business categories into one summary row per category.

7. Filtering Grouped Data with HAVING

WHERE filters individual rows before grouping. HAVING filters groups after aggregation. 

SELECT country,
       COUNT(*) AS film_count
FROM films
GROUP BY country
HAVING COUNT(*) >= 2;
SELECT genre,
       AVG(imdb_score) AS average_score
FROM films
GROUP BY genre
HAVING AVG(imdb_score) >= 7.5;

WHERE

Filters rows before they enter groups.

HAVING

Filters completed groups using aggregate conditions.

Using both WHERE and HAVING

SELECT country,
       COUNT(*) AS recent_film_count
FROM films
WHERE release_year >= 2019
GROUP BY country
HAVING COUNT(*) >= 2;

8. Combining HAVING and ORDER BY

SELECT country,
       COUNT(*) AS film_count,
       ROUND(AVG(imdb_score), 2) AS average_score
FROM films
WHERE imdb_score IS NOT NULL
GROUP BY country
HAVING COUNT(*) >= 2
ORDER BY average_score DESC,
         film_count DESC;
First form the groups, then filter the groups, then sort the remaining output.

Using aliases in ORDER BY

PostgreSQL allows selected aliases in ORDER BY because sorting occurs after the select list has been produced. 

SELECT country,
       COUNT(*) AS film_count
FROM films
GROUP BY country
ORDER BY film_count DESC;

9. Logical Query Execution Order

1. FROM 2. WHERE 3. GROUP BY 4. HAVING 5. SELECT 6. DISTINCT 7. ORDER BY 8. LIMIT
Clause Role
FROMIdentify source rows
WHEREFilter individual rows
GROUP BYBuild groups
HAVINGFilter groups
SELECTProduce result expressions
ORDER BYSort final results
LIMITRestrict returned rows
This order explains why aggregate conditions usually belong in HAVING, not WHERE.

10. Common Mistakes

Assuming rows are naturally ordered Use ORDER BY whenever output order matters.
Forgetting the sort direction applies per expression Each sort field may have its own ASC or DESC.
Selecting a non-aggregated field that is not grouped Every non-aggregate selected expression must appear in GROUP BY.
Using WHERE with an aggregate function Use HAVING to filter aggregate results.
Grouping by too many fields Extra grouping fields increase granularity and may prevent the intended summarization.
Forgetting NULL behavior in aggregates Most aggregates ignore NULL values, so grouped averages and counts may use different denominators.

11. Interview Translation

What is the difference between ORDER BY and GROUP BY? ORDER BY changes result order, while GROUP BY changes result granularity by combining rows into categories.
What is the difference between WHERE and HAVING? WHERE filters rows before grouping; HAVING filters groups after aggregation.
How does multi-column sorting work? SQL sorts by the first expression, then uses later expressions as tie-breakers.
Why must non-aggregate selected columns appear in GROUP BY? Each output row represents a group, so SQL needs a single defined value for every selected non-aggregate expression.
What happens when you add another GROUP BY column? The grouping becomes more detailed, producing one group for each unique combination of grouping values.
Can an alias be used in ORDER BY? In PostgreSQL, yes, because ORDER BY is logically evaluated after the select list.

12. Memory Review

Eight-sentence chapter summary
  1. ORDER BY sorts results.
  2. ASC is the default and DESC reverses the direction.
  3. Multiple sort expressions are applied from left to right.
  4. GROUP BY creates one group per unique value or combination.
  5. Aggregates summarize each group.
  6. WHERE filters rows before grouping.
  7. HAVING filters groups after aggregation.
  8. ORDER BY can sort the grouped output.
