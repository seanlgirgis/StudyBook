1. Big Picture

Selecting data means asking the database to return only the columns or summary values needed to answer a question. The central pattern is still SELECT ... FROM ..., but this chapter adds counting, duplicate removal, logical execution order, debugging, and clean SQL style.

Business question ↓ Choose the source table ↓ Choose fields or expressions ↓ Execute the SQL query ↓ Inspect and validate the result
Core idea: do not begin by selecting everything. Begin by asking, “Which table contains the data, and which fields answer the question?”

2. Querying a Database with SELECT and FROM

SELECT defines what appears in the result. FROM identifies the source table.

Select one field

SELECT title
FROM films;

Select several fields

SELECT title,
       release_year,
       country
FROM films;

Select all fields

SELECT *
FROM films;
Part Purpose Question answered
SELECT Chooses columns or expressions What should appear?
FROM Chooses the source table Where should SQL read from?
; Terminates the statement Where does the statement end?
Production habit: use named columns instead of * when the query will be reused. Named columns are clearer and less fragile when table structures change.

3. Counting Rows with COUNT()

COUNT() is an aggregate function. It returns one summarized value rather than returning every matching row.

Count all rows

SELECT COUNT(*)
FROM films;

Count non-NULL values in one field

SELECT COUNT(budget)
FROM films;

Count unique non-NULL values

SELECT COUNT(DISTINCT country)
FROM films;

Count a non-NULL expression

SELECT COUNT(budget + gross) AS films_with_both_values
FROM films;

The expression is counted only when its result is not NULL. If either budget or gross is NULL, then budget + gross is also NULL and that row is skipped.

Conditional count with CASE

SELECT COUNT(
         CASE
           WHEN country = 'Canada' THEN 1
         END
       ) AS canadian_films
FROM films;

The CASE expression returns 1 for Canadian films and NULL for all other rows. Because COUNT(expression) ignores NULL, only the matching rows are counted.

Conditional count with PostgreSQL FILTER

SELECT COUNT(*) FILTER (
         WHERE country = 'Canada'
       ) AS canadian_films
FROM films;

PostgreSQL's FILTER clause is often the clearest way to write conditional aggregates.

Count distinct combinations in PostgreSQL

SELECT COUNT(DISTINCT (country, language))
       AS unique_country_language_pairs
FROM films;

This counts unique row combinations such as (Canada, English) and (Canada, French).

Expression What it counts NULL behavior
COUNT(*) Rows Counts every row
COUNT(field) Non-NULL values in the field Ignores NULL
COUNT(DISTINCT field) Unique non-NULL field values Ignores NULL and duplicates
COUNT(expression) Non-NULL expression results Skips rows where the expression evaluates to NULL
COUNT(CASE WHEN ...) Rows meeting a condition Counts non-NULL CASE results
COUNT(*) FILTER (WHERE ...) Rows meeting a condition PostgreSQL conditional aggregate form
Memory rule: COUNT(*) counts rows; COUNT(column) counts known values in that column.

4. Removing Duplicate Results with DISTINCT

DISTINCT removes duplicate rows from the selected result.

Unique values from one field

SELECT DISTINCT country
FROM films;

Unique combinations across multiple fields

SELECT DISTINCT country,
                language
FROM films;
With several selected fields, DISTINCT applies to the complete row combination. It does not make each field independently unique.

DISTINCT versus COUNT(DISTINCT ...)

SELECT DISTINCT country

Returns the list of unique countries.

COUNT(DISTINCT country)

Returns one number: how many unique countries exist.

5. Written Order versus Logical Query Execution

SQL is written in a human-friendly order, but the database logically evaluates major clauses in a different order.

Written order

SELECT title
FROM films;

Logical execution order for this basic query

1. FROM films Locate the source table and make its fields available. 2. SELECT title Return the requested field from that source.
Punchline: SQL must find the table before it can return a field from it.

This distinction becomes more important as queries add WHERE, GROUP BY, HAVING, and ORDER BY.

Written clause Simplified logical position Purpose
FROM First Identify the source data
SELECT Later Choose final output fields or expressions

6. Debugging SQL Errors

SQL errors are usually easier to solve when you read the message, locate the indicated position, and inspect the nearby syntax instead of rewriting the entire query.

Missing comma 
-- Incorrect
SELECT title release_year
FROM films;

-- Correct
SELECT title,
       release_year
FROM films;
Misspelled keyword 
-- Incorrect
SELEC title
FROM films;

-- Correct
SELECT title
FROM films;
Wrong table or field name Confirm the schema and spelling. SQL cannot return a field that does not exist in the selected source table.
Missing quote or delimiter An opening quote, parenthesis, or identifier delimiter must have a matching closing one.
Debugging workflow: read the error → inspect the marked location → check the token immediately before it → reduce the query to the smallest working form.

7. SQL Style and Best Practices

SQL style does not normally change the result, but it strongly affects readability, reviewability, and maintenance.

  • Write SQL keywords consistently, commonly in uppercase.
  • Write table and field names consistently, commonly in lowercase.
  • Place major clauses on separate lines.
  • Put one selected field per line when the list becomes long.
  • Indent continuation lines consistently.
  • Use a semicolon to mark the end of the statement.
  • Prefer descriptive aliases and names over cryptic abbreviations.

Hard to scan

select title,release_year,country from films;

Easier to scan

SELECT title,
       release_year,
       country
FROM films;
Consistency matters more than arguing over one perfect formatting style.

8. Formatting Longer SELECT Lists

Recommended pattern

SELECT title,
       director,
       release_year,
       duration,
       budget,
       gross
FROM films;

Why this helps

  • Missing commas become easier to spot.
  • Source-control changes are easier to review.
  • Fields can be added or removed without rewriting the entire line.
  • Long queries remain readable on smaller screens.
The final selected field normally has no trailing comma. A comma immediately before FROM is a common syntax error.

9. Non-Standard Field Names

Field names containing spaces, punctuation, reserved words, or unusual capitalization may require identifier delimiters. In PostgreSQL, double quotes delimit identifiers. 

SELECT "release year",
       "Language"
FROM films;
Single quotes represent text values, not identifiers. Use 'English' for a string value and "Language" only when referring to a quoted identifier.
Form Meaning
'English' A text/string value
"Language" A quoted PostgreSQL identifier
language A normal unquoted identifier
Best prevention: use simple lowercase names with underscores, such as release_year, whenever you control the schema.

10. Common Mistakes

Confusing COUNT(*) and COUNT(column) The first counts rows. The second ignores NULL values in the named column.
Expecting DISTINCT to make each field separately unique With multiple fields, it removes duplicate combinations of the full selected row.
Assuming SQL executes in the order it is written The source table is logically processed before the selected output.
Using single quotes around a field name Single quotes create a string literal. PostgreSQL uses double quotes for unusual identifiers.
Leaving a comma before FROM The final item in a SELECT list should not normally end with a comma.
Using SELECT * without purpose It may return unnecessary data and hides which fields the query truly depends on.

11. Interview Translation

What is the difference between COUNT(*) and COUNT(column)? COUNT(*) counts rows, while COUNT(column) counts only non-NULL values in that column.
What can COUNT accept besides * or a column? It can count non-NULL expression results, distinct values, conditional CASE results, and in PostgreSQL it can use FILTER (WHERE ...) for conditional counting.
What does DISTINCT do? It removes duplicate rows from the query result based on the complete set of selected fields.
Why is SQL execution order important? It explains when tables, filters, grouping, selected expressions, and sorting become available, which helps with both query design and debugging.
How do you debug a syntax error? I read the database error, inspect the indicated token and the token immediately before it, then reduce the query to a small working version and rebuild it incrementally.
Why does SQL formatting matter? Consistent formatting improves readability, code review, troubleshooting, and long-term maintenance without changing the query result.
How does PostgreSQL distinguish strings from quoted identifiers? String values use single quotes, while quoted identifiers use double quotes.

12. Memory Review

Seven-sentence chapter summary
  1. SELECT chooses the output fields or expressions.
  2. FROM identifies the source table.
  3. COUNT(*) counts rows.
  4. COUNT(column) counts non-NULL values.
  5. DISTINCT removes duplicate result rows or combinations.
  6. Logical execution begins with the source before producing the selected output.
  7. Readable formatting and careful debugging make SQL easier to maintain.
