Selecting and Counting

SELECT

Choose output columns or expressions.

SELECT title, country
FROM films;
Trap: SELECT * is convenient but often too broad.

FROM

Choose the source table.

SELECT title
FROM films;
Trap: SQL must identify the source before it can return fields.

DISTINCT

Remove duplicate result rows.

SELECT DISTINCT country
FROM films;
Trap: with several columns, it applies to the full combination.

COUNT(*)

Count rows.

SELECT COUNT(*)
FROM films;
Trap: this is the safest total-row count.

COUNT(column)

Count non-NULL values.

SELECT COUNT(budget)
FROM films;
Trap: NULL values are skipped.

COUNT(DISTINCT column)

Count unique non-NULL values.

SELECT COUNT(DISTINCT country)
FROM films;
Trap: both duplicates and NULL are ignored.

Filtering

WHERE

Keep rows matching a condition.

SELECT title
FROM films
WHERE release_year = 2020;
Trap: aggregate conditions normally belong in HAVING.

Comparison operators

Compare numbers, text, or dates.

=  !=  <>
>  >=
<  <=
Trap: text values use single quotes.

AND

Require every condition to be true.

WHERE country = 'Canada'
  AND imdb_score >= 7.0
Memory: AND narrows.

OR

Require at least one condition to be true.

WHERE country = 'Canada'
   OR country = 'Germany'
Memory: OR broadens.

BETWEEN

Filter an inclusive range.

WHERE release_year
BETWEEN 2018 AND 2021
Trap: both endpoints are included.

IN

Match one value from a list.

WHERE country IN
('Canada', 'Germany')
Trap: cleaner than repeated OR conditions.

NOT IN

Exclude values from a list.

WHERE certification NOT IN
('R', 'PG-13')
Trap: NULL inside a list or subquery can produce surprising results.

Text Patterns and NULL

LIKE

Case-sensitive pattern matching in PostgreSQL.

WHERE title LIKE 'B%'
% = many characters; _ = one character.

NOT LIKE

Exclude rows matching a pattern.

WHERE title NOT LIKE '%Film%'
Trap: use LIKE operators, not =, with wildcards.

ILIKE

PostgreSQL case-insensitive pattern matching.

WHERE title ILIKE '%market%'
Trap: PostgreSQL-specific.

IS NULL

Find missing values.

WHERE budget IS NULL
Trap: never use = NULL.

IS NOT NULL

Find known values.

WHERE imdb_score IS NOT NULL
Trap: NULL is not zero or an empty string.

Aggregate Functions and Arithmetic

SUM

Add numeric values.

SELECT SUM(gross)
FROM films;
Trap: NULL values are ignored.

AVG

Calculate the arithmetic mean.

SELECT AVG(duration)
FROM films;
Trap: NULL values are not treated as zero.

MIN

Return the smallest value.

SELECT MIN(release_year)
FROM films;
Trap: text values use lexical ordering.

MAX

Return the largest value.

SELECT MAX(imdb_score)
FROM films;
Trap: cast text when the meaning is numeric.

ROUND(value, places)

Control numeric precision.

ROUND(AVG(budget), -3)
Positive = right of decimal; negative = left.

Arithmetic

Create derived values.

SELECT gross - budget AS profit
FROM films;
Trap: arithmetic with NULL returns NULL.

Safe division

Protect against division by zero.

gross / NULLIF(budget, 0)
Trap: integer division can discard decimals.

Alias

Give a result expression a readable name.

SELECT AVG(duration)
       AS average_duration
FROM films;
Trap: aliases do not rename stored columns.

CAST

Convert a value to another data type.

year_text::integer

CAST(year_text AS integer)
Trap: dirty text can make the cast fail.

Sorting and Grouping

ORDER BY

Sort the final result.

ORDER BY release_year
Trap: without ORDER BY, row order is not guaranteed.

ASC

Ascending sort direction.

ORDER BY release_year ASC
Trap: ASC is the default.

DESC

Descending sort direction.

ORDER BY imdb_score DESC
Trap: direction applies to each expression separately.

Multiple ORDER BY fields

Use later fields as tie-breakers.

ORDER BY release_year ASC,
         imdb_score DESC
Trap: priority is left to right.

GROUP BY

Create one group per unique value or combination.

SELECT country, COUNT(*)
FROM films
GROUP BY country;
Trap: every non-aggregate selected field must be grouped.

HAVING

Filter grouped aggregate results.

GROUP BY country
HAVING COUNT(*) >= 2
Trap: HAVING filters groups; WHERE filters rows.

WHERE vs HAVING

Filter at different stages.

WHERE release_year >= 2019
GROUP BY country
HAVING COUNT(*) >= 2
Trap: execution order determines which clause is valid.

Logical Execution Order

1. FROM 2. WHERE 3. GROUP BY 4. HAVING 5. SELECT 6. DISTINCT 7. ORDER BY 8. LIMIT
This order explains why aggregates cannot normally be filtered in WHERE, why aliases are often available in ORDER BY, and why LIMIT is applied last.
