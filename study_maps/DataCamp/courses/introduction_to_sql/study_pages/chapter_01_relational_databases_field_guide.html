1. Big Picture

A database is an organized place for storing data so that software and people can retrieve, update, and analyze it reliably. SQL is the language used to communicate with many relational databases.

User or application ↓ SQL Database management system ↓ Tables stored on a server
Core idea: SQL is not the database itself. SQL is the language used to ask the database management system to read or change stored data.

2. What Is a Database?

A database is a structured collection of related data. In the course example, a library database can contain information about patrons, books, and checkouts.

Patrons

People who use the library, including their card number, name, membership year, and fines.

Books

Books available in the library, including title, author, genre, and publication year.

Checkouts

Transactions connecting a patron to a book, including checkout and due dates.

Relationships

Shared identifiers connect separate tables without placing everything into one oversized table.

Databases are powerful because they store many related tables and allow SQL to combine the needed data later.

3. Relational Data Organization

A relational database organizes data into tables. Each table represents one main subject or event. Tables can then be related through matching identifiers.

patrons card_num ───────────────┐ name │ member_year │ total_fine │ │ checkouts │ id │ card_num ◀──────────────┘ book_id ───────────────┐ start_date │ due_date │ │ books │ id ◀───────────────┘ title author genre pub_year

This separation reduces repeated data. A patron's name is stored once in the patrons table, while many checkout records can refer to that patron by card number.

4. Tables, Rows, Columns, Records, and Fields

Term Meaning Library example
Table A structured set of related data patrons
Row / record One individual item or observation One patron
Column / field One attribute stored for every row member_year
Cell One value at the intersection of a row and column 2022
Memory sentence: A row represents one thing; a column describes one attribute of that thing.

5. Table and Field Naming

Good table names

  • Are clear and descriptive.
  • Refer directly to the data being stored.
  • Use one consistent naming convention across the database.

Good field names

  • Use lowercase letters.
  • Use underscores instead of spaces.
  • Prefer singular names for individual attributes.
  • Remain distinct from the table name and from other fields.
Better Avoid Why
member_year Member Year Spaces complicate queries and mixed capitalization is inconsistent.
total_fine total fine Underscores make multiword names readable and query-friendly.
name patrons A field name should describe the attribute, not repeat the table name.

6. Unique Identifiers and Keys

A unique identifier distinguishes one row from every other row in a table. In a patrons table, card_num can serve as the unique identifier.

A unique identifier is often called a key. When it uniquely identifies each row in its own table, it is commonly used as the table's primary key.

Why keys matter

  • They prevent ambiguity between rows.
  • They help connect related tables.
  • They support accurate updates and deletes.
  • They make relationships easier to define and query.
Names are usually poor identifiers because two people can have the same name and names can change.

7. Data Types

A data type tells the database what kind of value a column is allowed to store. Data types protect consistency and affect which operations are valid.

Data type family Typical PostgreSQL example Library example
Integer INT Card number, publication year, book ID
Text VARCHAR Name, title, author, genre
Decimal number NUMERIC Total fine such as 9.86
Date DATE Checkout date and due date

Choosing a data type

  • Choose a type that matches the real meaning of the data.
  • Use numeric types for values that need arithmetic.
  • Use dates for calendar values rather than storing them as plain text.
  • Use text for names and labels.
  • Avoid storing unrelated formats in the same column.
A value may look numeric without behaving like a number. For example, an ID may be stored as text if leading zeros matter or if arithmetic has no meaning.

8. Database Schema

A schema describes the database structure: tables, columns, data types, and relationships. It acts like a blueprint for how the data is organized.

patrons card_num INT name VARCHAR member_year INT total_fine NUMERIC books id INT title VARCHAR author VARCHAR genre VARCHAR pub_year INT checkouts id INT start_date DATE due_date DATE card_num INT book_id INT
A schema is not the data itself. It is the definition of how the data is structured.

9. Understanding Servers

Database data is typically stored and managed on a server. The server runs database software, receives SQL requests, applies rules, and returns results.

Your computer or application │ │ sends SQL ▼ Database server │ │ reads or changes ▼ Stored database tables

PostgreSQL and SQL Server are examples of database management systems that can run on servers. They both use SQL, although some syntax and features differ.

10. Common Mistakes

Mistake: Treating SQL as the database SQL is the language. PostgreSQL, SQL Server, and similar systems are database management systems.
Mistake: Thinking rows and columns mean the same thing A row is one record. A column is one attribute shared across records.
Mistake: Using names as unique IDs Names may repeat or change. Use a stable identifier such as a card number or generated ID.
Mistake: Choosing a data type only by appearance Consider meaning and future operations. An ID that looks numeric may still belong in a text field.
Mistake: Placing every subject in one giant table Separate distinct subjects such as patrons, books, and checkouts, then connect them through keys.

11. Interview Translation

What is a relational database? A relational database stores structured data in tables and connects those tables through shared keys.
What is the difference between a row and a column? A row represents one record, while a column represents one attribute of all records in the table.
Why are primary keys important? They uniquely identify rows and provide a reliable way to connect tables and target specific records.
Why do data types matter? They define valid values, protect data quality, influence storage, and determine which operations are possible.
What is a schema? A schema is the structural blueprint of a database, including tables, columns, data types, and relationships.

12. Memory Review

  3. Rows are records and columns are attributes.
