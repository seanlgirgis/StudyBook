2. Relational Databases

A database is an organized collection of data. A relational database separates related subjects into tables and connects those tables through shared identifiers.

  • A library may store patrons, books, and checkouts in separate tables.
  • Separate tables reduce repeated data.
  • Keys allow related rows to be connected later.
  • SQL communicates with the database management system.
SQL is the language. PostgreSQL and SQL Server are database management systems.

3. Tables and Structure

Term Meaning
Table A structured collection of related rows and columns.
Row / record One individual item or observation.
Column / field One attribute stored for all rows.
Key A stable identifier used to distinguish rows and connect tables.
A row represents one thing. A column describes one attribute of that thing.

4. Data Types and Schemas

Data types define the kind of value a column may store. A schema defines the overall database structure.

Purpose Typical type Example
Whole numbers INT Publication year
Text VARCHAR Book title
Decimal values NUMERIC Fine amount
Calendar dates DATE Checkout date
Choose a type based on meaning, not appearance. An identifier may look numeric but still belong in text.

5. Basic Queries

SELECT title, author
FROM books;

SELECT chooses the output columns. FROM chooses the source table.

All columns

SELECT *
FROM books;
SELECT * is useful for quick exploration, but named columns are better for reusable queries.

6. DISTINCT and Aliases

Return unique values

SELECT DISTINCT genre
FROM books;

Rename a result column

SELECT name AS patron_name
FROM patrons;
  • DISTINCT removes duplicate result rows.
  • With multiple columns, it returns unique combinations.
  • AS changes the result label, not the stored column name.

7. Views

A view is a named saved query that can be queried like a table. 

CREATE VIEW patron_names AS
SELECT card_num,
       name
FROM patrons;
SELECT *
FROM patron_names;
Views help reuse logic, simplify access, and expose only the columns users need.

8. SQL Flavors

Database system Common dialect detail
PostgreSQL Uses LIMIT to restrict rows.
SQL Server Commonly uses TOP to restrict rows. 
-- PostgreSQL
SELECT title
FROM books
LIMIT 5;
-- SQL Server
SELECT TOP 5 title
FROM books;

9. Core Syntax Patterns

-- One column
SELECT title
FROM books;

-- Several columns
SELECT title, author, pub_year
FROM books;

-- Unique values
SELECT DISTINCT genre
FROM books;

-- Alias
SELECT name AS patron_name
FROM patrons;

-- PostgreSQL row limit
SELECT title
FROM books
LIMIT 5;

10. Common Mistakes

Confusing rows and columns Rows are records; columns are attributes.
Using a person’s name as a unique ID Names can repeat or change. Use a stable identifier.
Forgetting commas between selected columns Write SELECT title, author.
Misunderstanding DISTINCT It applies to the full selected row combination.
Thinking AS permanently renames a column It creates only a temporary output label.
Assuming SQL syntax is identical everywhere Core SQL transfers well, but dialect-specific syntax differs.

11. Interview Translation

What is a relational database? A system that stores structured data in tables and connects those tables through shared keys.
What is a primary key? A column or set of columns that uniquely identifies each row in a table.
What does SELECT do? It specifies the columns or expressions returned by a query.
What does DISTINCT do? It removes duplicate result rows based on all selected columns.
What is a view? A named saved query used to simplify or reuse data-access logic.

12. Final Course Review

Seven things to remember: database, table, row, column, key, data type, and query.
  • A relational database separates subjects into related tables.
  • Rows are records; columns are attributes.
  • Keys identify rows and connect tables.
  • Data types protect structure and meaning.
  • SELECT and FROM form the basic query.
  • DISTINCT, aliases, and views improve usefulness and reuse.
  • SQL dialects share a common core but differ in some syntax.
