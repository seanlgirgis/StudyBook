1. What Is a Query?

A query is a request for data. In SQL, queries are written with keywords that tell the database what to return and where to retrieve it from.

Core idea: SQL turns a business question into a structured request against database tables.

Business question

Which books are in the library?

SQL question

Select the relevant columns from the books table.

2. The Basic Query Pattern: SELECT and FROM

SELECT specifies the columns to return. FROM specifies the table that contains those columns. 

SELECT name
FROM patrons;
Clause Question it answers
SELECT Which columns should appear in the result?
FROM Which table should SQL read?
SQL keywords are commonly written in uppercase for readability, even though many database systems do not require uppercase.

3. Selecting One, Multiple, or All Columns

One column

SELECT title
FROM books;

Multiple columns

SELECT title, author, pub_year
FROM books;

All columns

SELECT *
FROM books;
Use * carefully: it is convenient for exploration, but named columns are clearer, more stable, and usually better in production queries.

4. Developing Good SQL Style

  • Write SQL keywords in uppercase.
  • Place major clauses on separate lines.
  • Use indentation when a query becomes longer.
  • End statements with a semicolon.
  • Use clear table and column names.
SELECT title,
       author,
       pub_year
FROM books;
Good SQL style does not change the result. It makes the query easier to read, review, debug, and maintain.

5. Returning Unique Values with DISTINCT

DISTINCT removes duplicate rows from the selected result. 

SELECT DISTINCT genre
FROM books;

DISTINCT across multiple columns

SELECT DISTINCT genre, pub_year
FROM books;
With multiple columns, SQL returns unique combinations. It does not make each column independently unique.

6. Renaming Output Columns with Aliases

An alias changes the column label in the query result. It does not rename the original database column. 

SELECT name AS patron_name
FROM patrons;

Aliases are useful for clarity, shorter names, and user-friendly report headings.

Memory rule: AS renames the result column, not the stored field.

7. Saving a Query as a View

A view is a saved SQL query that can be queried like a table. It stores the query definition, not usually a separate copy of the underlying data. 

CREATE VIEW patron_names AS
SELECT card_num,
       name
FROM patrons;
SELECT *
FROM patron_names;
Views help reuse logic, simplify repeated queries, and expose only the columns users need.

8. SQL Flavors

SQL is standardized, but database systems add their own features and syntax. These variations are commonly called SQL flavors or dialects.

System Key idea
PostgreSQL Free, open-source database system with its own PostgreSQL SQL dialect.
SQL Server Microsoft database system that commonly uses the T-SQL dialect.
Core patterns such as SELECT and FROM transfer well across systems. Some functions, data types, and limiting syntax differ.

9. Limiting Results

Limiting results is useful when exploring a large table or checking query output.

PostgreSQL

SELECT title
FROM books
LIMIT 5;

SQL Server

SELECT TOP 5 title
FROM books;
Without ORDER BY, a limited result is not guaranteed to represent the “first” rows in a meaningful order.

10. Common Mistakes

Forgetting the comma between selected columns Use commas between column names: SELECT title, author.
Thinking DISTINCT affects one column only It applies to the entire selected row combination.
Thinking an alias changes the database schema An alias changes only the result label.
Using PostgreSQL LIMIT in SQL Server SQL Server commonly uses TOP instead.
Using SELECT * everywhere It can return unnecessary data and make queries fragile when table structures change.

11. Interview Translation

What does SELECT do? It specifies which columns or expressions should appear in the query result.
What does DISTINCT do? It removes duplicate result rows based on the full set of selected columns.
What is an alias? A temporary name assigned to a result column or table for clarity or brevity.
What is a view? A named saved query that can be queried like a table and helps reuse or simplify logic.
What is a SQL dialect? A database-specific variation of standard SQL, such as PostgreSQL SQL or Microsoft T-SQL.

12. Memory Review

Six-sentence chapter summary
  1. SELECT chooses columns.
  2. FROM chooses the source table.
  3. DISTINCT removes duplicate result rows.
  4. AS creates a temporary alias.
  5. A view saves a reusable query definition.
  6. SQL dialects share a common core but differ in some syntax.

  • Can you explain why DISTINCT genre, pub_year returns unique combinations?
  • Can you distinguish an alias from a permanent rename?
  • Can you explain the purpose of a view?
  • Can you translate PostgreSQL LIMIT 5 into SQL Server syntax?
