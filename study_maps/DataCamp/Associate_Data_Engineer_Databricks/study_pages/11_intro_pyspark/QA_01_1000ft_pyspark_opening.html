QA 01 - 1000-Foot PySpark Opening

Final accepted answers for Course 11 interview rehearsal (Q01-Q17).

Spark and PySpark Big Picture

Q01. What is Spark?

Punch line: Spark is the distributed engine for large-scale parallel data processing.

Q02. What is PySpark?

Punch line: PySpark is Python authoring over Spark's distributed execution engine.

Q03. Why does this job care about PySpark?

Punch line: The role needs scalable ETL plus production support for data pipelines.

Spark Architecture

Q04. What is the driver?

Punch line: Driver coordinates planning and dispatches work.

Q05. What are executors?

Punch line: Executors are workers processing partitions in parallel.

DataFrame Work

Q06. What is a SparkSession?

Punch line: SparkSession is the entry point into Spark from PySpark.

Q07. What is a DataFrame in PySpark?

Punch line: A distributed, table-like structure for Spark ETL and analytics.

Execution Model

Q08. Difference between transformations and actions?

Punch line: Transformations build plans; actions trigger execution.

Q09. What is lazy evaluation?

Punch line: Spark plans first and runs when an action is called.

Q10. What are partitions and shuffle?

Punch line: Partitions enable parallelism; shuffle is expensive cross-worker movement.

Production Support Mindset

Q11. How do you support a PySpark job in production?

Punch line: Check logs, counts, data quality, dependencies, and rerun safety.

Q12. What to check when a job fails?

Punch line: Diagnose execution + data pipeline side before rerun.

Orchestration and Internals Touchpoints

Q13. What is a DAG in Spark?

Punch line: Spark DAG is Spark's internal execution plan.

Q14. Spark DAG vs Airflow DAG?

Punch line: Spark DAG is compute execution; Airflow DAG is workflow orchestration.

Q15. Where does Airflow fit?

Punch line: Airflow schedules/monitors; Spark executes distributed work.

Q16. Is PySpark only Python runtime?

Punch line: PySpark is Python interface with Spark/JVM execution underneath.

Q17. Safe internals statement?

Punch line: Know practical internals for building/supporting jobs without overclaiming deep engine internals.

RDDs and Spark Foundations

Q48. What is an RDD in PySpark?

Accepted answer: RDD is Spark's lower-level distributed, immutable data abstraction (Resilient Distributed Dataset).

Q49. What is the difference between an RDD and a DataFrame?

Accepted answer: RDD is lower-level and manual; DataFrame is schema-aware and usually preferred for structured ETL and analytics.

Q50. Why should collect() be used carefully?

Accepted answer: collect() brings distributed data to driver memory, so use only for tiny result sets.

Spark SQL and Temporary Views

Q51. What is Spark SQL?

Accepted answer: Spark SQL lets SQL syntax run inside PySpark workflows and still returns DataFrames for continued processing.

Q52. How do you create a temporary view in PySpark?

Accepted answer: Register DataFrame with createOrReplaceTempView("name"), then query it via spark.sql().

Q53. What does spark.sql() return?

Accepted answer: spark.sql() returns a DataFrame.

Q54. What is the production risk of temporary views?

Accepted answer: Temp views are session-scoped, so production pipelines must persist outputs explicitly where needed.

Aggregations and Summary Metrics

Q55. How do you perform aggregations in PySpark?

Accepted answer: Use Spark SQL or DataFrame API groupBy/agg with sum, avg, count, max, min.

Q56. Why should data types be checked before aggregation?

Accepted answer: SUM/AVG on string-typed numeric columns can fail or mislead, so cast and validate first.

Q57. Why should you filter early before aggregating?

Accepted answer: early filtering reduces data volume and improves relevance/performance.

Q58. When would you use Spark SQL versus DataFrame API for aggregations?

Accepted answer: choose whichever is clearer and maintainable for the team; both are interoperable.

Q59. Why are RDDs usually not preferred for structured aggregations?

Accepted answer: RDDs are more manual/verbose; DataFrame and SQL paths are schema-aware and easier to optimize.

PySpark at Scale and Optimization

Q60. What does explain() do in PySpark?

Accepted answer: explain() exposes logical/physical plans for optimization and shuffle awareness.

Q61. When should you cache a DataFrame?

Accepted answer: when a DataFrame is reused across multiple actions and recomputation is expensive.

Q62. What is the difference between cache() and persist()?

Accepted answer: cache() uses default storage behavior; persist() allows explicit storage levels.

Q63. Why should you unpersist cached DataFrames?

Accepted answer: to release resources and reduce memory pressure after reuse is done.

Q64. What is a broadcast join?

Accepted answer: it broadcasts a small lookup side to reduce large join shuffle cost.

Q65. Why should repeated actions be avoided?

Accepted answer: repeated actions trigger repeated jobs and multiply runtime/cost.
