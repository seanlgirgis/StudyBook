The project question

The project asks whether the amount of time an international student has stayed in the host country is associated with three mental-health measures.

Plain-English version:
Group international students by how many years they have stayed, then compare their average depression, social-connectedness, and acculturative-stress scores.
Students table→ International students→ Group by stay→ Count and average→ 9 result rows
2

The columns that matter

The table contains many fields, but this project needs only five:

Column Meaning Role in the query
inter_dom International or domestic student Filter to 'Inter'
stay Length of stay in years Grouping column
todep Total depression score Average PHQ result
tosc Total social-connectedness score Average SCS result
toas Total acculturative-stress score Average AS result
Memory rule: stay creates the groups. COUNT() tells us group size. AVG() summarizes the scores.
3

The SQL logic

1. Clean Remove rows that are missing a field needed by the analysis.
2. Filter Keep only rows where inter_dom = 'Inter'.
3. Group Put students into buckets based on stay.
4. Summarize Count rows and calculate the three averages.
5. Round Keep two decimal places for readable results.
6. Sort Show the longest stays first with DESC.
4

Build the query in small steps

Step A — inspect the needed columns

SELECT
    inter_dom,
    stay,
    todep,
    tosc,
    toas
FROM students;

Step B — keep international students only

SELECT
    stay,
    todep,
    tosc,
    toas
FROM students
WHERE inter_dom = 'Inter';

Step C — create one row per stay group

SELECT
    stay,
    COUNT(*) AS count_int
FROM students
WHERE inter_dom = 'Inter'
GROUP BY stay
ORDER BY stay DESC;

Step D — add the averages

SELECT
    stay,
    COUNT(*) AS count_int,
    ROUND(AVG(todep), 2) AS average_phq,
    ROUND(AVG(tosc), 2) AS average_scs,
    ROUND(AVG(toas), 2) AS average_as
FROM students
WHERE inter_dom = 'Inter'
GROUP BY stay
ORDER BY stay DESC;
5

The final project solution

The final version uses a common table expression, or CTE, to separate data cleaning from the analysis. 

WITH clean_students AS (
    SELECT
        inter_dom,
        stay,
        todep,
        tosc,
        toas
    FROM students
    WHERE inter_dom IS NOT NULL
      AND stay IS NOT NULL
      AND todep IS NOT NULL
      AND tosc IS NOT NULL
      AND toas IS NOT NULL
)
SELECT
    stay,
    COUNT(*) AS count_int,
    ROUND(AVG(todep), 2) AS average_phq,
    ROUND(AVG(tosc), 2) AS average_scs,
    ROUND(AVG(toas), 2) AS average_as
FROM clean_students
WHERE inter_dom = 'Inter'
GROUP BY stay
ORDER BY stay DESC;
The CTE is not required for this small query, but it makes the two stages easy to see: first clean the rows, then analyze them.

7

How to interpret the result safely

The result is descriptive. It shows average scores within each stay group. It does not prove that length of stay caused any score to rise or fall.

Groups with long stays contain very few students. For example, several groups contain only one student. Their averages are therefore not stable enough for strong conclusions.

The largest and more dependable groups are the one-, two-, and three-year groups. Even there, this project should be described as an exploratory SQL analysis rather than a causal study.

Safe conclusion: The query summarizes how mental-health scores vary across length-of-stay groups among international students. Further statistical analysis would be required to determine whether the differences are meaningful.

Common mistakes

Mistake Why it is a problem Correction
Forgetting WHERE inter_dom = 'Inter' Domestic students would be mixed into the result. Filter before grouping.
Selecting stay without grouping it PostgreSQL rejects a non-aggregated selected column. Add GROUP BY stay.
Using COUNT(stay) without understanding nulls It ignores rows where stay is null. Clean first, then use COUNT(*).
Leaving averages unrounded The output contains unnecessary decimal precision. Use ROUND(AVG(column), 2).
Claiming causation The query only summarizes observational data. Say “associated with” or “varies by,” not “caused by.”
Ignoring group size An average based on one student can be misleading. Always read count_int with the averages.

Interview translation

How would you explain this project?

I analyzed a student mental-health dataset in PostgreSQL. I filtered to international students, removed incomplete records for the fields used in the analysis, grouped the data by length of stay, and calculated group counts and average depression, social-connectedness, and acculturative-stress scores. I also validated the local result against the expected nine stay groups.

What SQL skills did the project demonstrate?

  • Filtering with WHERE
  • Data-quality checks with IS NOT NULL
  • Common table expressions with WITH
  • Grouping with GROUP BY
  • Aggregation with COUNT() and AVG()
  • Output formatting with ROUND()
  • Sorting with ORDER BY ... DESC
  • Interpreting results without overclaiming

What would you improve in a production analysis?

  • Profile all missing values and confirm the intended null policy.
  • Use a data dictionary to verify score ranges and meanings.
  • Flag or suppress groups with very small sample sizes.
  • Add statistical tests or confidence intervals before drawing conclusions.
  • Document dataset lineage, ethics, and privacy controls.
