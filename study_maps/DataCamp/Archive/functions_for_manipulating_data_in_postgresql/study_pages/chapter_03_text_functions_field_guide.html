Section 4

Concatenation

Use concatenation when you need labels, full names, readable report text, or one combined searchable/display field built from multiple source values.

|| operator

SELECT
  first_name || ' ' || last_name AS full_name
FROM customer;

Best when strict concatenation is acceptable and you want the classic PostgreSQL operator form.

CONCAT()

SELECT
  CONCAT(first_name, ' ', last_name) AS full_name
FROM customer;

Best when NULL-friendly display output matters more than strict null propagation.

Readable label

SELECT
  CONCAT('Customer: ', first_name, ' ', last_name) AS customer_label
FROM customer;

Useful for report labels and exported display strings.

Separator example

SELECT
  city || ', ' || state AS city_state
FROM address_book;

Make separators explicit so the output stays readable.

MethodNULL behaviorBest use
||NULL can make whole result NULLstrict concatenation
CONCAT()skips NULL as empty textfriendlier display text
Common trap Do not assume || and CONCAT() handle NULL the same way.

Case Conversion

Core case functions

SELECT
  UPPER(first_name) AS upper_name,
  LOWER(first_name) AS lower_name,
  INITCAP(first_name) AS title_name
FROM customer;

Use these when you need standardized display text or consistent comparison prep.

Cleanup-first capitalization

SELECT
  INITCAP(TRIM(raw_text)) AS cleaned_name
FROM lab_dirty_text;

Clean outside spaces before applying capitalization.

Normalized comparison prep

SELECT
  LOWER(TRIM(email_text)) AS comparable_email
FROM customer_import;

Lowercasing helps when you want stable text comparison inputs.

Cleanup before grouping

SELECT
  INITCAP(LOWER(TRIM(city_name))) AS clean_city,
  COUNT(*) AS row_count
FROM source_data
GROUP BY INITCAP(LOWER(TRIM(city_name)));

Normalize before grouping so dirty case variants do not split counts.

  • normalized comparisons
  • display formatting
  • cleanup before grouping
  • case-insensitive matching preparation
Trap INITCAP() follows word boundaries mechanically and may not preserve special brand or personal-name capitalization.

Replacement

Literal replacement

SELECT REPLACE('PostgreSQL Course', 'Course', 'Guide');

REPLACE() is for exact literal text replacement.

Remove exact characters

SELECT REPLACE(phone_text, '-', '') AS digits_without_dashes
FROM contacts;

Good when the unwanted character pattern is known and literal.

One-pass space cleanup

SELECT REPLACE(raw_text, '  ', ' ') AS one_pass_space_cleanup
FROM lab_dirty_text;

This can help in simple cases, but repeated runs may still be needed for messy text.

Literal versus pattern

SELECT REPLACE(raw_code, '#', '') AS literal_cleanup
FROM source_data;

Use literal replacement for exact text, not pattern families.

What to remember REPLACE() replaces exact literal text. It does not understand patterns.

Reverse and Length

REVERSE()

SELECT
  raw_text,
  REVERSE(raw_text) AS reversed_text
FROM lab_dirty_text;

Useful when you need to inspect suffix behavior or odd trailing content.

LENGTH() versus trimmed length

SELECT
  raw_text,
  LENGTH(raw_text) AS raw_length,
  LENGTH(TRIM(raw_text)) AS trimmed_length
FROM lab_dirty_text;

Great for spotting hidden padding and validating cleanup impact.

CHAR_LENGTH()

SELECT
  raw_text,
  CHAR_LENGTH(raw_text) AS character_count
FROM lab_dirty_text;

Use when you want an explicit character-counting name.

Validation example

SELECT
  raw_code,
  LENGTH(raw_code) AS code_length
FROM source_data
WHERE LENGTH(raw_code) < 4
   OR LENGTH(raw_code) > 12;

Helpful for flagging unexpectedly short or long values before downstream logic.

  • validating code length
  • finding trailing or leading junk
  • comparing raw versus cleaned text
  • detecting unexpectedly short or long values
Trap Length before trimming may include unwanted spaces.

Position and Search

POSITION()

SELECT
  POSITION('ELF' IN comparison_text) AS elf_position
FROM lab_dirty_text;

Uses POSITION('x' IN text) syntax and returns a one-based position.

STRPOS()

SELECT
  STRPOS(comparison_text, 'ELF') AS elf_position
FROM lab_dirty_text;

Uses STRPOS(text, 'x') syntax and returns the same kind of position result.

Contains check

SELECT
  comparison_text,
  POSITION('ELF' IN comparison_text) > 0 AS contains_elf
FROM lab_dirty_text;

Turn the numeric location into an explicit boolean-like check.

Not-found behavior

SELECT
  comparison_text,
  STRPOS(comparison_text, 'XYZ') AS xyz_position
FROM lab_dirty_text;

Useful for proving that 0 means not found.

FunctionSyntax style
POSITION()POSITION('x' IN text)
STRPOS()STRPOS(text, 'x')
Trap PostgreSQL string positions start at 1. A result of 0 means not found.

Section 9

Substring Extraction

LEFT()

SELECT LEFT(comparison_text, 3) AS first_three;

Best for prefix-style extraction.

RIGHT()

SELECT RIGHT(comparison_text, 4) AS last_four;

Best for suffix-style extraction.

SUBSTRING()

SELECT SUBSTRING(comparison_text FROM 2 FOR 5) AS middle_piece;

Readable standard form for middle slices.

SUBSTR()

SELECT SUBSTR(comparison_text, 2, 5) AS middle_piece;

Short PostgreSQL-friendly version of the same idea.

Partial identifier example

SELECT
  LEFT(order_code, 2) AS region_prefix,
  RIGHT(order_code, 4) AS serial_suffix
FROM order_feed;

Useful for prefixes, suffixes, and region codes.

Masking example

SELECT
  LEFT(card_token, 4) || '...' || RIGHT(card_token, 4) AS masked_token
FROM payment_feed;

Useful when you want a safe visible slice instead of the full value.

Truncate text without cutting a word

Business question: How do I create a short description that ends at the last complete word within the first 50 characters?

SELECT
  title,
  LEFT(
    description,
    50 - POSITION(
      ' ' IN REVERSE(LEFT(description, 50))
    )
  ) AS short_description
FROM film;
SELECT
  UPPER(c.name) || ': ' || f.title AS film_category,
  LEFT(
    f.description,
    50 - POSITION(
      ' ' IN REVERSE(LEFT(f.description, 50))
    )
  ) AS short_description
FROM film AS f
INNER JOIN film_category AS fc
  ON f.film_id = fc.film_id
INNER JOIN category AS c
  ON fc.category_id = c.category_id;

Step-by-step:

  1. LEFT(description, 50) takes the first 50 characters.
  2. REVERSE(...) reverses that 50-character preview.
  3. POSITION(' ' IN reversed_text) finds the first space in the reversed text, which represents the last space in the original preview.
  4. 50 - that position calculates the safe length ending before the partial final word.
  5. The outer LEFT() returns only complete words.
Take first N → reverse → find first space → subtract from N → keep complete words

Common trap: If the first 50 characters contain no space, POSITION() returns 0, so this expression returns all 50 characters and may still cut a long word.

Edge-case note: This pattern assumes spaces are the desired word separator. For normal descriptions containing multiple words, this pattern works well. For unbroken identifiers or very long single words, add explicit edge-case handling.

  • prefixes
  • suffixes
  • region codes
  • year portions
  • partial identifiers
  • masking part of a value
Trap Text positions start at 1, not 0.

SPLIT_PART()

Delimited region example

SELECT SPLIT_PART('north-america-sales', '-', 1) AS region;

First field from a dash-delimited value.

Second field example

SELECT SPLIT_PART('north-america-sales', '-', 2) AS area;

Pull the second token without needing array syntax.

Email user

SELECT SPLIT_PART(email_address, '@', 1) AS email_user
FROM contacts;

Useful for username extraction from structured text.

Email domain

SELECT SPLIT_PART(email_address, '@', 2) AS email_domain
FROM contacts;

Useful for domain grouping and validation.

Generated code parsing

SELECT
  SPLIT_PART(raw_code || '-' || comparison_text, '-', 1) AS code_part,
  SPLIT_PART(raw_code || '-' || comparison_text, '-', 2) AS text_part
FROM lab_dirty_text;

Matches the Chapter 3 live lab parsing pattern.

Missing part behavior

SELECT SPLIT_PART('alpha-beta', '-', 3) AS third_part;

If the requested part does not exist, the result comes back empty.

Trap SPLIT_PART positions start at 1. It does not return an array.

Trim Functions

TRIM()

SELECT TRIM(raw_text) AS trimmed_text
FROM lab_dirty_text;

Use for outside whitespace on both ends.

LTRIM() and RTRIM()

SELECT
  LTRIM(raw_text) AS left_trimmed,
  RTRIM(raw_text) AS right_trimmed
FROM lab_dirty_text;

Use when only one side of the value needs outside cleanup.

Specific character trimming

SELECT TRIM(BOTH '-' FROM '--ABC--') AS clean_code;

Trimming works with requested outer characters, not just spaces.

Leading character trim

SELECT TRIM(LEADING '0' FROM '000123') AS without_leading_zeros;

Useful when imported text values include non-meaningful fill characters.

Important distinction TRIM() removes characters from the outside. It does not collapse repeated spaces inside the string.

Padding

Good for fixed-width display codes and normalized text output.

RPAD()

SELECT RPAD('SQL', 8, '.') AS padded_label;

Good for right-side label fill or visual alignment.

Padding numeric-looking IDs

SELECT
  customer_id,
  LPAD(customer_id::text, 6, '0') AS display_customer_id
FROM customer;

Cast numeric values to text first so padding behaves as expected.

Display-only formatting

SELECT
  raw_code,
  LPAD(raw_code, 4, '0') AS display_code
FROM source_data;

Useful in reports, but different from changing the underlying business key.

REGEXP_REPLACE()

Syntax shape REGEXP_REPLACE(text, pattern, replacement, 'g')

Collapse repeated whitespace

SELECT
  REGEXP_REPLACE(raw_text, '\s+', ' ', 'g') AS collapsed_spaces
FROM lab_dirty_text;

Use this when internal repeated spaces should collapse to one normal space.

Digits only

SELECT
  REGEXP_REPLACE(phone_text, '[^0-9]', '', 'g') AS digits_only
FROM contacts;

Handy for phone-style cleanup before validation.

Letters only

SELECT
  REGEXP_REPLACE(raw_code, '[^A-Za-z]', '', 'g') AS letters_only
FROM source_data;

Useful when mixed punctuation or numbers should be stripped.

Punctuation cleanup

SELECT
  REGEXP_REPLACE(raw_text, '[[:punct:]]+', ' ', 'g') AS punctuation_cleaned
FROM lab_dirty_text;

Helpful when punctuation runs create noise in text columns.

NeedPattern idea
repeated whitespace\s+
anything except digits[^0-9]
anything except letters[^A-Za-z]
punctuation runs[[:punct:]]+
Important Without the g flag, only the first matching occurrence is replaced.
Caution Regex cleanup can remove meaningful characters. Always compare raw and cleaned output before updating stored data.

Section 14

Cleanup Pipelines

inspect raw text → trim outside whitespace → collapse internal whitespace → normalize capitalization → replace or remove unwanted characters → validate length and emptiness

Clean customer name

Business question: How do I turn messy imported name text into stable display text?

SELECT
  raw_name,
  INITCAP(
    REGEXP_REPLACE(
      TRIM(raw_name),
      '\s+',
      ' ',
      'g'
    )
  ) AS cleaned_name
FROM customer_import;

Why the order matters: trim outside junk first, then collapse internal spacing, then format capitalization.

Likely mistake: applying INITCAP() before removing extra spaces.

Clean and normalize code

Business question: How do I normalize imported codes before reporting?

SELECT
  raw_code,
  UPPER(
    REGEXP_REPLACE(
      TRIM(raw_code),
      '[^A-Za-z0-9]',
      '',
      'g'
    )
  ) AS cleaned_code
FROM source_data;

What to validate: compare raw and cleaned values so you do not remove meaningful symbols accidentally.

Likely mistake: deleting punctuation without checking whether some symbols carry business meaning.

Empty string to NULL

Business question: How do I normalize blank text values?

SELECT
  NULLIF(TRIM(raw_text), '') AS normalized_text
FROM lab_dirty_text;

Why the order matters: values with only spaces should become blank first, then convert to NULL.

Likely mistake: checking for '' before trimming.

CTE cleanup pipeline

Business question: How do I build reusable cleanup logic without repeating expressions everywhere?

WITH cleaned AS (
  SELECT
    id,
    raw_text,
    TRIM(raw_text) AS trimmed_text
  FROM lab_dirty_text
),
normalized AS (
  SELECT
    id,
    raw_text,
    REGEXP_REPLACE(trimmed_text, '\s+', ' ', 'g')
      AS normalized_text
  FROM cleaned
)
SELECT
  id,
  raw_text,
  normalized_text
FROM normalized;

What to validate: keep raw and normalized output together in the final SELECT so the transformation is easy to review.

Likely mistake: repeating the same cleanup chain in multiple clauses instead of calculating once.

Combined Examples

Example 1: Build full customer name

Business question: How do I join two name columns for display?

SELECT
  first_name || ' ' || last_name AS full_name
FROM customer;

What to notice: The separator has to be inserted manually.

Likely mistake: Forgetting the space separator.

Example 2: Build label with CONCAT()

Business question: How do I build a readable customer label?

SELECT
  CONCAT('Customer: ', first_name, ' ', last_name) AS customer_label
FROM customer;

What to notice: NULL values behave more safely for display text.

Likely mistake: Assuming || would handle NULL the same way.

Example 3: Normalize capitalization

Business question: How do I make messy imported names readable?

SELECT
  INITCAP(LOWER(TRIM(raw_text))) AS normalized_name
FROM lab_dirty_text;

What to notice: Clean spacing before case formatting.

Likely mistake: Leaving padded spaces in the display output.

Example 4: Compare raw and trimmed length

Business question: How do I flag hidden padding?

SELECT
  raw_text,
  LENGTH(raw_text) AS raw_length,
  LENGTH(TRIM(raw_text)) AS clean_length
FROM lab_dirty_text;

What to notice: Length difference is a useful quality signal.

Likely mistake: Trusting visual inspection alone.

Example 5: Find a substring position

Business question: Does this text contain the token ELF?

SELECT
  comparison_text,
  POSITION('ELF' IN comparison_text) AS elf_position
FROM lab_dirty_text;

What to notice: 0 means not found.

Likely mistake: Treating 0 as the first position.

Example 6: Extract code prefix and suffix

Business question: How do I pull the start and end of a code?

SELECT
  LEFT(order_code, 3) AS prefix_code,
  RIGHT(order_code, 4) AS suffix_code
FROM order_feed;

What to notice: Prefix and suffix extraction are simpler than generic substring logic.

Likely mistake: Using fixed-width logic on inconsistent text shapes.

Example 7: Split an email address

Business question: How do I separate email user and domain?

SELECT
  SPLIT_PART(email_address, '@', 1) AS email_user,
  SPLIT_PART(email_address, '@', 2) AS email_domain
FROM contacts;

What to notice: The same delimiter can feed multiple extracted fields.

Likely mistake: Using index 0.

Example 8: Pad customer ID

Business question: How do I make customer IDs fixed-width for display?

SELECT
  customer_id,
  LPAD(customer_id::text, 6, '0') AS display_customer_id
FROM customer;

What to notice: Cast to text before padding.

Likely mistake: Treating the padded display string like a new key.

Example 9: Collapse repeated spaces

Business question: How do I normalize internal spacing?

SELECT
  REGEXP_REPLACE(raw_text, '\s+', ' ', 'g') AS collapsed_spaces
FROM lab_dirty_text;

What to notice: Regex handles repeated internal whitespace better than TRIM.

Likely mistake: Forgetting the 'g' flag.

Example 10: Full cleanup pipeline

Business question: How do I produce one stable cleaned display value?

SELECT
  INITCAP(
    REGEXP_REPLACE(
      TRIM(raw_text),
      '\s+',
      ' ',
      'g'
    )
  ) AS clean_display_text
FROM lab_dirty_text;

What to notice: Trim first, regex second, case format third.

Likely mistake: Doing the same steps in a less safe order.

Example 11: Convert empty string to NULL

Business question: How do I normalize blank text values before loading?

SELECT
  NULLIF(TRIM(raw_text), '') AS normalized_text
FROM lab_dirty_text;

What to notice: This turns space-only values into NULL too.

Likely mistake: Treating blank strings and NULL as identical without checking.

Example 12: Clean phone number to digits only

Business question: How do I keep only numbers from messy phone text?

SELECT
  REGEXP_REPLACE(phone_text, '[^0-9]', '', 'g') AS digits_only
FROM contacts;

What to notice: Regex is safer than chaining many literal replacements for broad cleanup.

Likely mistake: Updating stored values before reviewing the cleaned output in SELECT form.

Example 13: Safe short-description preview

Business question: How do I create a short description that ends at the last complete word within the first 50 characters?

SELECT
  title,
  LEFT(
    description,
    50 - POSITION(
      ' ' IN REVERSE(LEFT(description, 50))
    )
  ) AS short_description
FROM film;

What to notice: The first LEFT() limits the search area. REVERSE() makes the final word boundary easy to locate.

Likely mistake: Using LEFT(description, 50) alone can cut the last word in half.

Section 17

Interview Q&A

|| versus CONCAT()?

|| is operator-style concatenation and can return NULL for the whole result. CONCAT() treats NULL values as empty text.

How does NULL affect concatenation?

With ||, a NULL side can null out the full expression. With CONCAT(), NULL is skipped like empty text.

UPPER() versus LOWER()?

Both normalize case. Use upper when codes or standardized uppercase output is preferred, and lower when comparison-friendly lowercase is preferred.

What does INITCAP() do?

It title-cases text mechanically by word boundaries. It is helpful for cleanup, but not perfect for every real-world name.

REPLACE() versus REGEXP_REPLACE()?

REPLACE() is exact literal replacement. REGEXP_REPLACE() handles pattern-based replacement.

How do you collapse repeated spaces?

Use REGEXP_REPLACE(text, '\s+', ' ', 'g').

What does the regex g flag mean?

It means global replacement: replace all matches, not just the first one.

How are PostgreSQL string positions numbered?

They are 1-based. Position 1 is the first character, and 0 means not found in search functions.

POSITION() versus STRPOS()?

They solve the same location problem with different syntax styles: POSITION('x' IN text) versus STRPOS(text, 'x').

LEFT() versus SUBSTRING()?

LEFT() is best for fixed prefix extraction. SUBSTRING() is better for middle slices and more flexible extraction.

What does SPLIT_PART() return?

It returns one requested field directly, not an array.

TRIM() versus LTRIM() versus RTRIM()?

TRIM() removes outside characters on both sides, LTRIM() removes from the left, and RTRIM() removes from the right.

When do you use LPAD()?

Use it when fixed-width display output matters, especially for leading-zero IDs or report-friendly code formatting.

Why may numbers need casting before padding?

Padding works on text output. Cast numeric values to text first so the format rule applies correctly.

How do you normalize empty strings?

Use NULLIF(TRIM(text), '') when blank text should become NULL.

How do you build a safe text-cleaning pipeline?

Inspect raw text, trim outside junk, collapse internal whitespace, normalize case, validate output, and only then consider updates.

Why should raw text often be preserved?

Because cleanup rules can remove meaningful information, and raw text helps validation, auditing, and rollback logic.

How do you validate a cleanup rule before UPDATE?

Run the cleanup as a SELECT that shows raw and cleaned output side by side, then review edge cases before mutating stored data.

How can you truncate text without cutting the last word?

Take the first N characters, reverse that preview, find the first space in the reversed text, subtract that distance from N, and use the result as the final LEFT() length.
