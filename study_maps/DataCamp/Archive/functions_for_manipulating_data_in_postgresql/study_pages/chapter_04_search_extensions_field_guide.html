Section 4

LIKE and ILIKE

LIKE and ILIKE compare character patterns. They do not understand word meaning, stemming, or linguistic normalization.

Pattern examples

SELECT *
FROM lab_films
WHERE title LIKE 'POSTGRES%';
SELECT *
FROM lab_films
WHERE title LIKE '%HERO';
SELECT *
FROM lab_films
WHERE title LIKE '%GRES%';
SELECT *
FROM lab_films
WHERE title LIKE 'POSTGRES HER_';

Case-insensitive example

SELECT *
FROM lab_films
WHERE title ILIKE '%postgres%';
SELECT *
FROM lab_films
WHERE title LIKE 'POSTGRES_HERO';
SELECT *
FROM lab_films
WHERE title ILIKE 'postgres%';

Section 6

to_tsvector()

Use to_tsvector() to build a searchable document. It uses a dictionary such as 'english', normalizes words into lexemes, drops some stop words, and stores position information.

SELECT
  title,
  to_tsvector('english', title) AS title_document
FROM lab_films;
SELECT
  title,
  description,
  to_tsvector(
    'english',
    title || ' ' || description
  ) AS searchable_document
FROM lab_films;
SELECT
  description,
  to_tsvector('english', description) AS description_document
FROM lab_films;
SELECT
  title,
  to_tsvector('english', title || ' ' || description) AS combined_document
FROM lab_films;
Normalization note

to_tsvector() does not keep every original word exactly as typed. It normalizes words into searchable lexemes.

Section 7

to_tsquery()

Use to_tsquery() when you want structured full-text query syntax with lexemes and boolean operators.

SELECT to_tsquery('english', 'elf');
SELECT to_tsquery('english', 'elf & adventure');
SELECT to_tsquery('english', 'elf | postgres');
SELECT to_tsquery('english', 'elf & !winter');
SELECT to_tsquery('english', 'postgres');
SELECT to_tsquery('english', 'postgres | database');
Syntax note

to_tsquery() expects full-text query syntax. It is not intended for arbitrary raw user sentences.

Section 11

Stemming and Prefix Search

Stemming is language normalization. Words that look related to a person may not always normalize to the same lexeme.

SELECT
  plainto_tsquery('english', 'elf') AS elf_query,
  plainto_tsquery('english', 'elves') AS elves_query;
elf → 'elf' elves → 'elv'
SELECT
  film_id,
  title,
  description
FROM lab_films
WHERE to_tsvector(
        'english',
        title || ' ' || description
      )
      @@ to_tsquery(
        'english',
        'el:*'
      )
ORDER BY film_id;
SELECT
  plainto_tsquery('english', 'hero') AS hero_query,
  plainto_tsquery('english', 'heroes') AS heroes_query;
SELECT
  to_tsquery('english', 'post:*') AS postgres_prefix_query;
Prefix note

:* means lexeme-prefix search. Full-text prefix search is not the same as LIKE 'el%'.

Section 13

CREATE FUNCTION and Routine Discovery

User-defined functions let you package reusable logic behind a name, parameter list, return type, body, and declared language. The DataCamp video uses a small plpgsql example first.

CREATE FUNCTION squared(i integer)
RETURNS integer AS $$
BEGIN
  RETURN i * i;
END;
$$ LANGUAGE plpgsql;

What each piece means

  • CREATE FUNCTION squared defines a reusable function named squared.
  • (i integer) declares one input parameter named i with integer type.
  • RETURNS integer declares the output type the function must send back.
  • AS $$ ... $$ wraps the function body using dollar quoting.
  • BEGIN starts the procedural block.
  • RETURN i * i; sends the calculated square back to the caller.
  • END; closes the procedural block.
  • LANGUAGE plpgsql says the body is written in PostgreSQL's procedural language.

Function vs procedure

A function returns a value or result and can be called in a query expression. PostgreSQL also supports CREATE PROCEDURE, but this lesson focuses on CREATE FUNCTION.

SELECT squared(5) AS squared_value;

Expected result: 25.

SQL-language alternative

This is a valid alternative for a single-expression body, but it is not the exact video example.

CREATE FUNCTION squared_sql(i integer)
RETURNS integer
AS $$
  SELECT i * i;
$$
LANGUAGE SQL;

Dollar quoting note

Dollar quoting keeps the function body readable because you do not need to escape normal single quotes the same way you would inside one large string literal. It marks the body boundary, while LANGUAGE plpgsql or LANGUAGE SQL tells PostgreSQL how to interpret the body.

Section 15

levenshtein()

Levenshtein distance measures insertions, deletions, and substitutions. Exact match is 0. Lower is better.

SELECT
  levenshtein('cat', 'cat') AS exact_match,
  levenshtein('cat', 'cut') AS one_letter_changed,
  levenshtein('cat', 'cats') AS one_letter_added,
  levenshtein('cat', 'dog') AS very_different;
SELECT levenshtein('GUMBO', 'GAMBOL');

Levenshtein distance = number of edits needed to make the strings match. Lower is better. 0 means exact match.

SELECT
  levenshtein(
    'POSTGRES HERO',
    'POSTGRES HER0'
  ) AS edit_distance;
SELECT
  film_id,
  title,
  levenshtein(
    title,
    'POSTGRES HEROES'
  ) AS title_distance
FROM lab_films
WHERE levenshtein(
        title,
        'POSTGRES HEROES'
      ) <= 3
ORDER BY title_distance, film_id;
WITH title_distances AS (
  SELECT
    film_id,
    title,
    levenshtein(
      title,
      'POSTGRES HEROES'
    ) AS title_distance
  FROM lab_films
)
SELECT
  film_id,
  title,
  title_distance,
  CASE
    WHEN title_distance = 0 THEN 'Exact'
    WHEN title_distance <= 1 THEN 'Very close'
    WHEN title_distance <= 3 THEN 'Close'
    ELSE 'Too far'
  END AS threshold_label
FROM title_distances
ORDER BY title_distance, film_id;
SELECT levenshtein('POSTGRES', 'POSTGRES');
SELECT levenshtein('POSTGRES', 'POSTGERS');
SELECT levenshtein('POSTGRES HERO', 'POSTGRES HEROES');
Threshold note

Thresholds are business decisions. A good threshold for short names may be too strict or too loose for long titles.

Section 16

soundex() and difference()

Use phonetic matching when pronunciation matters more than exact spelling, but remember this is English-centric and can produce false positives.

SELECT
  soundex('Smith') AS smith_soundex,
  soundex('Smyth') AS smyth_soundex,
  soundex('Robert') AS robert_soundex,
  soundex('Rupert') AS rupert_soundex;
SELECT
  difference('Smith', 'Smyth') AS smith_smyth_difference,
  difference('Robert', 'Rupert') AS robert_rupert_difference,
  difference('Smith', 'Robert') AS smith_robert_difference;
SELECT
  customer_id,
  first_name,
  soundex(first_name) AS first_name_soundex,
  difference(first_name, 'Shaun') AS sound_score
FROM lab_customers
ORDER BY sound_score DESC, customer_id;
difference(): 4 = strongest phonetic similarity 0 = weakest
WITH name_scores AS (
  SELECT
    customer_id,
    first_name,
    difference(
      first_name,
      'Shaun'
    ) AS sound_score,
    levenshtein(
      first_name,
      'Shaun'
    ) AS edit_distance
  FROM lab_customers
)
SELECT
  customer_id,
  first_name,
  sound_score,
  edit_distance,
  CASE
    WHEN sound_score = 4
         AND edit_distance <= 2
      THEN 'Strong fuzzy match'
    WHEN sound_score >= 3
      THEN 'Possible sound match'
    WHEN edit_distance <= 2
      THEN 'Possible typo match'
    ELSE 'Not a good match'
  END AS fuzzy_match_label
FROM name_scores
ORDER BY sound_score DESC,
         edit_distance,
         customer_id;
SELECT soundex('Hero') AS hero_soundex;
SELECT difference('Hero', 'Hiro') AS hero_hiro_difference;
SELECT difference('Smith', 'Robert') AS smith_robert_difference;

Section 17

pg_trgm

pg_trgm breaks strings into overlapping character trigrams. It is useful for approximate text similarity and typo-tolerant search.

A trigram is an overlapping group of three characters. similarity() returns a score from 0 to 1, where higher is better.

CREATE EXTENSION IF NOT EXISTS pg_trgm;
SELECT similarity('GUMBO', 'GAMBOL');

Observed result: 0.181818.

A score of 0 means no matching trigrams. A score of 1 means perfect match. Higher similarity is better.

SELECT show_limit();
SHOW pg_trgm.similarity_threshold;
POSTGRES contains overlapping 3-character pieces. Similarity compares how many trigram pieces the strings share.

Section 18

similarity() and Thresholds

Trigram similarity scores run from 0 to 1. Higher is better. Exact or nearly exact strings usually score higher.

SELECT
  similarity(
    'POSTGRES HERO',
    'POSTGRES HER0'
  ) AS hero_zero_similarity,
  similarity(
    'POSTGRES HERO',
    'POSTGRES HEROES'
  ) AS heroes_similarity,

word_similarity()

Use word_similarity() when a matching phrase may appear inside longer text. It compares against the best matching continuous extent in the other text.

SELECT
  similarity(
    'POSTGRES HERO',
    'please find POSTGRES HER0 for me'
  ) AS regular_similarity,
  word_similarity(
    'POSTGRES HERO',
    'please find POSTGRES HER0 for me'
  ) AS word_similarity_score;
SELECT
  film_id,
  title,
  word_similarity(
    title,
    'please find POSTGRES HER0 for me'
  ) AS word_score
FROM lab_films
WHERE word_similarity(
        title,
        'please find POSTGRES HER0 for me'
      ) >= 0.3
ORDER BY word_score DESC,
         film_id;
SELECT
  word_similarity('POSTGRES HERO', 'POSTGRES HER0') AS short_phrase_score;
SELECT
  word_similarity('POSTGRES HERO', 'please find POSTGRES HER0 for me') AS sentence_score;
Whole string vs longer sentence

similarity() compares whole strings. word_similarity() is better when the matching phrase appears inside longer text.

Trigram Distance

The <-> operator is trigram distance. Lower is better. Exact match distance is 0.

SELECT
  title,
  similarity(
    title,
    'POSTGRES HER0'
  ) AS similarity_score,
  title <-> 'POSTGRES HER0'
    AS trigram_distance
FROM lab_films
ORDER BY trigram_distance ASC,
         title;
SELECT
  title,
  title <-> 'POSTGRES HER0'
    AS trigram_distance
FROM lab_films
WHERE title % 'POSTGRES HER0'
ORDER BY trigram_distance ASC;
SELECT
  'POSTGRES HERO' <-> 'POSTGRES HER0' AS close_distance;
SELECT
  'POSTGRES HERO' <-> 'ELF ADVENTURE' AS far_distance;
similarity(): higher is better distance <->: lower is better

Example 1: Case-insensitive title fragment search

Business question: How do I find titles containing postgres regardless of case?

SELECT *
FROM lab_films
WHERE title ILIKE '%postgres%';

What to notice: Best for character fragments, not linguistic word search.

Likely mistake: Expecting stemming or typo tolerance.

Example 2: Full-text description search

Business question: How do I search descriptions for the word elf as a word token?

SELECT *
FROM lab_films
WHERE to_tsvector('english', description)
      @@ to_tsquery('english', 'elf');

What to notice: Word-based matching is different from substring matching.

Likely mistake: Reaching for LIKE when word logic matters.

Example 3: Combined title and description search

Business question: How do I search both title and description at once?

SELECT *
FROM lab_films
WHERE to_tsvector(
        'english',
        title || ' ' || description
      )
      @@ to_tsquery('english', 'postgres');

What to notice: Build one searchable document from multiple fields.

Likely mistake: Searching only one column and missing matches.

Example 4: Plain user-word search

Business question: How do I search a normal user phrase safely?

SELECT *
FROM lab_films
WHERE to_tsvector(
        'english',
        title || ' ' || description
      )
      @@ plainto_tsquery(
        'english',
        'postgres database'
      );

What to notice: plainto_tsquery handles plain words.

Likely mistake: Feeding raw sentences straight into to_tsquery.

Example 5: Boolean AND search

Business question: How do I require two words?

SELECT *
FROM lab_films
WHERE to_tsvector('english', description)
      @@ to_tsquery('english', 'elf & adventure');

What to notice: Both lexemes must match.

Likely mistake: Writing plain English AND instead of &.

Example 6: Stemming surprise

Business question: Why do elf and elves not always behave the same?

SELECT
  plainto_tsquery('english', 'elf') AS elf_query,
  plainto_tsquery('english', 'elves') AS elves_query;

What to notice: Related words may normalize differently.

Likely mistake: Assuming human-related words always share one lexeme.

Example 7: Prefix full-text search

Business question: How do I search a lexeme prefix?

SELECT *
FROM lab_films
WHERE to_tsvector(
        'english',
        title || ' ' || description
      )
      @@ to_tsquery(
        'english',
        'el:*'
      );

What to notice: Prefix search uses lexeme logic, not raw characters.

Likely mistake: Treating it like LIKE prefix matching.

Example 8: Levenshtein typo filter

Business question: Which titles are within three edits of POSTGRES HEROES?

SELECT
  film_id,
  title,
  levenshtein(title, 'POSTGRES HEROES') AS title_distance
FROM lab_films
WHERE levenshtein(title, 'POSTGRES HEROES') <= 3
ORDER BY title_distance, film_id;

What to notice: Lower edit count means closer match.

Likely mistake: Using one cutoff blindly for every text length.

Example 9: Soundex name candidates

Business question: Which customer names sound like Shaun?

SELECT
  customer_id,
  first_name,
  soundex(first_name) AS first_name_soundex,
  difference(first_name, 'Shaun') AS sound_score
FROM lab_customers
ORDER BY sound_score DESC, customer_id;

What to notice: difference score is higher when sound is closer.

Likely mistake: Reading difference like edit distance.

Example 10: Combined sound and edit score

Business question: How do I combine phonetic and typo scoring?

WITH name_scores AS (
  SELECT
    customer_id,
    first_name,
    difference(first_name, 'Shaun') AS sound_score,
    levenshtein(first_name, 'Shaun') AS edit_distance
  FROM lab_customers
)
SELECT
  customer_id,
  first_name,
  sound_score,
  edit_distance
FROM name_scores
ORDER BY sound_score DESC, edit_distance, customer_id;

What to notice: Two weak fuzzy signals together can be stronger than one alone.

Likely mistake: Trusting only one similarity family.

Example 11: pg_trgm similarity threshold

Business question: Which titles have a trigram similarity score of at least 0.3?

SELECT
  film_id,
  title,
  similarity(title, 'POSTGRES HER0') AS title_similarity
FROM lab_films
WHERE similarity(title, 'POSTGRES HER0') >= 0.3
ORDER BY title_similarity DESC, film_id;

What to notice: This is manual thresholding with explicit score output.

Likely mistake: Confusing score filtering with the % operator.

Example 12: % operator search

Business question: Which titles pass the current pg_trgm similarity threshold?

SELECT
  film_id,
  title,
  similarity(title, 'POSTGRES HER0') AS title_similarity
FROM lab_films
WHERE title % 'POSTGRES HER0'
ORDER BY title_similarity DESC, film_id;

What to notice: Percent means pass/fail fuzzy threshold here.

Likely mistake: Mixing it up with LIKE wildcard percent.

Example 13: word_similarity inside sentence

Business question: How do I find a title inside a longer messy sentence?

SELECT
  film_id,
  title,
  word_similarity(
    title,
    'please find POSTGRES HER0 for me'
  ) AS word_score
FROM lab_films
ORDER BY word_score DESC, film_id;

What to notice: Better for embedded phrase matching than whole-string similarity.

Likely mistake: Expecting whole-string similarity to stay strong with extra surrounding words.

Example 14: Trigram distance ranking

Business question: How do I rank nearest fuzzy matches first?

SELECT
  title,
  title <-> 'POSTGRES HER0' AS trigram_distance
FROM lab_films
WHERE title % 'POSTGRES HER0'
ORDER BY trigram_distance ASC;

What to notice: Distance is the inverse direction from similarity.

Likely mistake: Sorting descending and pushing worse matches to the top.

Section 24

Interview Q&A

LIKE versus ILIKE?

LIKE is case-sensitive character-pattern matching. ILIKE is case-insensitive character-pattern matching.

LIKE versus full-text search?

LIKE works on raw character patterns. Full-text search works on normalized word tokens and lexemes.

What does to_tsvector do?

It turns text into a searchable document of normalized lexemes with position information.

What does to_tsquery do?

It builds a structured full-text query using lexemes and operators such as AND, OR, and NOT.

What does plainto_tsquery do?

It converts plain user-style words into a valid full-text query.

What does @@ mean?

It means a searchable document matches a full-text query.

How do full-text AND, OR, and NOT work?

Use & for AND, | for OR, and ! for NOT.

What is a lexeme?

It is PostgreSQL's normalized searchable word form used by full-text search.

What does stemming mean?

It means normalizing related word forms toward a base searchable form.

Why might elf and elves normalize differently?

Because stemming is dictionary-driven and does not guarantee every human-related word form maps the way you expect.

What does :* mean?

It means lexeme-prefix search in a full-text query.

What is a PostgreSQL extension?

It is a packaged set of database capabilities that can be enabled in a PostgreSQL database.

What does pg_available_extensions show?

It shows extensions this PostgreSQL installation knows how to install.

What does pg_extension show?

It shows extensions already enabled in the current database.

Available versus installed extensions?

Available means the extension can be enabled. Installed means it is already enabled in the current database.

Why use IF NOT EXISTS?

It lets setup be rerun without throwing an error when the extension is already enabled.

What does PostGIS add?

It adds spatial and location-query support inside PostgreSQL.

What does PostPic add?

It adds image-processing capabilities inside PostgreSQL.

What does fuzzystrmatch add?

It adds edit-distance and phonetic string-comparison helpers such as levenshtein(), soundex(), and difference().

What does pg_trgm add?

It adds trigram-based fuzzy string similarity, threshold matching, and distance ranking.

Where are extensions installed?

They are enabled in the current database.

Where do extension objects live?

They live in a schema, which may matter for search_path or schema-qualified calls.

What language does the video use for squared()?

The video uses LANGUAGE plpgsql with a BEGIN ... END block and an explicit RETURN.

What does CREATE FUNCTION do?

It creates a named reusable routine with parameters, a return type, a body, and a declared language.

What does BEGIN do in the video example?

It starts the procedural body of the plpgsql function.

What does RETURN do?

It sends the computed result back to the caller using the declared return type.

What does END do?

It closes the procedural block that started with BEGIN.

What does LANGUAGE plpgsql mean?

It tells PostgreSQL to interpret the body using its procedural language rather than plain SQL only.

Why use dollar quoting in a function body?

It keeps the function body readable by avoiding awkward quote escaping; it is a delimiter choice, not the language choice.

When is LANGUAGE SQL enough?

It is enough for a simple function body that can be expressed as a single SQL query or expression, like the squared_sql() alternative.

What does RETURNS mean in a function definition?

It declares the data type the function sends back to the caller.

How do you discover existing functions?

Use information_schema.routines for a portable view, or pg_proc joined to pg_namespace plus PostgreSQL helper functions for signature detail.

How do you inspect function arguments?

Use pg_get_function_identity_arguments(p.oid) from pg_proc to retrieve the input-argument signature safely.

How do you inspect a function return type?

Check data_type in information_schema.routines or pg_get_function_result(p.oid) in pg_proc.

Why verify Sakila helper-function signatures first?

Sample-database versions can differ slightly, so metadata inspection is safer than inventing argument counts or types.

What does pg_proc store?

It stores PostgreSQL function metadata, including names, schema linkage, and information that can be expanded into argument and return-type detail.

What does levenshtein measure?

It measures edit distance: the number of insertions, deletions, or substitutions needed to change one string into another.

Why is lower Levenshtein better?

Because smaller edit distance means fewer changes are needed, and exact match is 0.

Why is levenshtein('GUMBO', 'GAMBOL') equal to 2?

Because one edit replaces U with A, and one edit adds L at the end.

What does Soundex measure?

It creates a rough phonetic code so similar-sounding strings can group together.

What does difference return?

It returns a phonetic similarity score from 0 to 4 based on Soundex codes.

What does pg_trgm do?

It compares strings by overlapping character trigrams for approximate similarity search.

What does a similarity score mean?

It is a trigram similarity score from 0 to 1, where higher is better.

What does a similarity score of 0 mean?

It means there are no matching trigrams between the compared strings.

What does a similarity score of 1 mean?

It means the strings are a perfect trigram match.

What does % mean in pg_trgm?

It means the similarity passes the current trigram threshold.

What does the threshold control?

It controls which rows pass the % operator, not the raw similarity score.

similarity versus word_similarity?

similarity compares whole strings. word_similarity is better when a matching phrase appears inside longer text.

What does <-> mean?

It is trigram distance, which is roughly 1 minus similarity, so lower is better.

How do you rank fuzzy matches?

Use descending similarity scores or ascending trigram distance, depending on the metric you expose.

When do you combine phonetic and edit-distance scoring?

When sound-alike matching alone or typo distance alone is too weak and you want a stronger fuzzy candidate report.
