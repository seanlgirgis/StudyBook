# Interview Notes: Apple / Carla Capacity SQL Lab

## How to Use This in Interview Prep
- Practice translating each query result into a capacity decision.
- Keep explanations in plain business terms: risk, efficiency, headroom,
  forecast confidence, and action.

## Talk Track Examples
- "I use grouped telemetry to identify which services are capacity constrained
  vs over-allocated."
- "I compare forecast vs actual to explain model accuracy and variance drivers."
- "I use thresholds and ranking so stakeholder teams can prioritize action."

## What to Emphasize
- SQL is not the end product; it enables planning decisions.
- P95 + headroom + variance are core capacity narratives.
- Capacity findings should map to concrete actions: rightsize, scale,
  rebalance, or investigate bottlenecks.

## Truthful Positioning Reminders
- Strong hands-on: AWS-focused telemetry/capacity analytics.
- GCP framing: transferable concepts, not deep production ownership claims.
- Billing ownership: support through technical analysis, not finance ownership.
