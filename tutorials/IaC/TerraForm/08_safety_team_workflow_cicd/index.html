Terraform Safety, Team Workflow, and CI/CD

This tutorial frames Terraform as team change management: code review, plan evidence, approvals, and protected execution paths.

Apply is intentionally not part of this safe lab. CI/CD is pseudo-workflow only.

Inline Code Excerpts

main.tf

terraform {
  required_version = ">= 1.4.0"
}

locals {
  change_summary = {
    change_type       = var.change_type
    environment       = var.environment
    requested_by      = var.requested_by
    approval_required = var.approval_required
    blast_radius      = var.blast_radius
  }

  safety_message = "Review ${var.change_type} change for ${var.environment} before any apply."
}

resource "terraform_data" "safety_review_demo" {
  input = {
    change_summary = local.change_summary
    safety_message = local.safety_message
    lesson         = "Terraform safety is about review, plan visibility, controlled apply, and protected state."
  }
}

variable "approval_required" { type = bool, default = true }
variable "blast_radius" { type = string, default = "low" }

Checklist excerpt

- right branch?
- right pull request?
- right environment?
- right workspace?
- right backend/state?
- right credentials?
- right approval?
- plan reviewed?
- destroy/replacement checked?
- rollback path understood?

Expected Output Explanations

Plan output should remain local-safe, showing only terraform_data and review metadata. No cloud resources, no remote backend configuration, no apply.

Common Mistakes

  • Treating validate as safety approval.
  • Skipping plan review in high-risk environments.
  • Confusing PR approval with apply approval.
  • Assuming rollback is always trivial.

Terraform as Team Change Management

Terraform maturity is process maturity: review evidence, approval discipline, and controlled execution.

Version Control and Pull Requests

Version control and PRs provide traceability, review history, and shared accountability.

Format, Validate, and Plan

fmt/validate are quality gates; plan is the actionable infrastructure preview.

Plan Review and Blast Radius

Review what changes and how much impact is possible before approving execution.

Apply Control

Apply should be gated by role, environment, and explicit approval, especially for production.

Remote State and Locking

Shared state with locking reduces race conditions and state corruption risk.

Least Privilege

Credentials should grant only what is required for intended operations.

CI/CD Pipeline Shape

CI/CD should standardize checks and plan evidence; apply remains controlled and gated.

Policy Checks

Policy checks add repeatable guardrails for security, compliance, and operational discipline.

Rollback Thinking

Plan rollback paths before change; not all infrastructure rollback paths are simple.

Safe Interview Wording

“Terraform safety is not only syntax checks. Mature teams combine PR review, plan evidence, blast-radius assessment, controlled apply, protected state, and least-privilege access.”
