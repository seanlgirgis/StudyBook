AWS Foundation Resources

Terraform often participates in standardizing storage, IAM, network boundaries, compute support, and monitoring assets.

S3 for Data and Logs

S3 appears in pipeline storage, log retention, and analytics workflows.

IAM and Least Privilege

IAM changes are high risk; least-privilege review is essential.

Networking and Blast Radius

Small network changes can have broad service impact, so review and safety gates matter.

Compute and Capacity

Compute definitions and capacity visibility must inform each other.

CloudWatch and Observability

Monitoring resources should align with ownership, signal quality, and action paths.

Dashboards as Code

Versioned dashboards improve repeatability and review clarity.

Alerts as Code

Versioned alerts improve threshold discipline and reduce drift.

Data Engineering Connection

Pipelines depend on cloud foundations that Terraform discussions regularly touch.

Capacity Planning Connection

Terraform defines what should exist; telemetry and forecasting evaluate whether it is enough.

Safe Interview Wording

“I understand Terraform workflow and how it supports repeatable cloud infrastructure. My strongest background is data engineering, telemetry, monitoring, and capacity forecasting. I use Terraform fluency to collaborate better with platform/cloud teams.”

What Not To Claim

Do not claim enterprise Terraform platform ownership if that was not your role. Use precise, collaboration-focused language.
