# Terraform AWS, Observability, and Interview Bridge

## Purpose
This package builds interview fluency and architecture understanding by connecting Terraform concepts to AWS infrastructure, observability practices, data engineering support, and capacity conversations.

## What This Package Teaches
- AWS foundation resources in Terraform conversations
- S3, IAM, networking, and compute concepts
- CloudWatch and broader observability-tool concepts
- dashboards and alerts as code
- data engineering and capacity-planning connections
- safe interview positioning without overclaiming ownership

## How To Use This Tutorial
1. Start with `index.html` for the bridge narrative.
2. Read conceptual Terraform snippets as design examples only.
3. Practice interview positioning from the `interview/` files.
4. Use checklists to sharpen review and collaboration language.

## AWS Foundation Concepts
Terraform often appears in conversations about foundational cloud resources and governance patterns.

## S3 Concept
S3 commonly supports logs, exports, and data-lake style storage.

## IAM Concept
IAM is high risk and should be reviewed carefully with least-privilege discipline.

## Networking Concept
Network changes can have broad impact and require blast-radius awareness.

## Compute Concept
Compute choices influence runtime behavior, cost, and capacity patterns.

## CloudWatch Concept
CloudWatch connects cloud resources to metrics, logs, and alerting signals.

## Observability Tools Concept
Many observability assets can be versioned and reviewed as code, even when not fully managed by Terraform.

## Dashboards as Code
Versioned dashboards improve consistency, ownership, and repeatability.

## Alerts as Code
Versioned alerts improve threshold consistency, routing clarity, and review discipline.

## Capacity Connection
Terraform defines infrastructure shape; capacity practice evaluates headroom and trend risk.

## Data Engineering Connection
Data pipelines depend on storage, IAM, compute, networking, and monitoring foundations.

## Safe Interview Story
Use Terraform fluency to show collaboration strength with platform/cloud teams, without claiming platform ownership.

## Overclaim Guardrails
See `interview/overclaim_guardrails.md` for safe claims, risky claims, and recovery lines.
