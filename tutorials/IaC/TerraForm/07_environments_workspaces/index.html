Terraform Environments and Workspaces

This tutorial expands the map with a safe, local-only lab: one Terraform configuration, multiple environment inputs, and safety-first planning discipline.

Inline Lab Files

main.tf

terraform {
  required_version = ">= 1.4.0"
}

locals {
  name_prefix = "${var.environment}-${var.application_name}"

  common_tags = {
    environment = var.environment
    application = var.application_name
    owner       = var.owner
    managed_by  = "terraform"
  }

  environment_summary = {
    environment     = var.environment
    size            = var.size
    retention_days  = var.retention_days
    approval_needed = var.approval_required
  }
}

resource "terraform_data" "environment_demo" {
  input = {
    name_prefix = local.name_prefix
    tags        = local.common_tags
    summary     = local.environment_summary
    lesson      = "Same Terraform pattern, different environment inputs."
  }
}

variables.tf

variable "environment" { type = string, default = "dev" }
variable "application_name" { type = string, default = "learnterraform" }
variable "owner" { type = string, default = "Sean" }
variable "size" { type = string, default = "small" }
variable "retention_days" { type = number, default = 7 }
variable "approval_required" { type = bool, default = false }

outputs.tf

output "name_prefix" { value = local.name_prefix }
output "environment_summary" { value = local.environment_summary }
output "environment_demo_output" { value = terraform_data.environment_demo.output }

What an Environment Is

An environment is a separate deployment context (dev/test/prod) with different risk and control expectations.

Folder Strategy

Folder boundaries make intent visible and reduce accidental cross-environment operations.

tfvars Per Environment

Use one reusable config and switch only approved input values via per-environment tfvars files.

Workspaces and Caution

Workspaces can isolate state instances, but wrong workspace selection is a major operational risk.

Backend Per Environment

Keep state boundaries aligned with environment boundaries. Backend, workspace, and provider are different concerns.

Promotion Path

Safer flow: validate in dev, review in test, approve for prod. Production should not be first test.

Wrong Environment Risk Checklist

  • Right folder?
  • Right variable file?
  • Right workspace?
  • Right backend/state?
  • Right cloud account?
  • Right approval?

Common Mistakes

  • Using prod values in dev plans by mistake.
  • Confusing tfvars with workspace selection.
  • Treating workspace as complete production safety boundary.
  • Assuming validate proves operational safety.
