# 🧠 The short answer

> The pipeline talks to Postgres using the **service name as a hostname over Docker’s internal network**.

---

# 🔗 The key line from your setup

In your `docker-compose.yml`, you have:

```yaml
environment:
  - DB_HOST=postgres
```

👉 That word **`postgres`** is the magic.

---

# 🧱 What Docker did behind the scenes

When you ran Compose, Docker created:

```text
Network: 36_docker_internal
```

Inside that network:

| Service  | Hostname   |
| -------- | ---------- |
| postgres | `postgres` |
| redis    | `redis`    |
| pipeline | `pipeline` |

👉 These are **automatic DNS names**

---

# 🧠 So inside the pipeline container

Your code connects like this:

```python
host = "postgres"
port = 5432
```

👉 Which really means:

```text
“Connect to the container named postgres on the Docker network”
```

# 🧪 Real connection string (what your app would use)

Inside the container:

```text
postgresql://pipeline:password@postgres:5432/studybook
```

Breakdown:

| Part        | Meaning                  |
| ----------- | ------------------------ |
| `pipeline`  | username                 |
| `password`  | from `.env`              |
| `postgres`  | service name (hostname!) |
| `5432`      | port                     |
| `studybook` | database                 |

---

# ⚠️ Important clarification

👉 This only works **inside Docker network**

From your Windows machine:

```text
localhost:5432
```

From container:

```text
postgres:5432
```
