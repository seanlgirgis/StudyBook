This file is a **Docker lesson runner**.

In layman words:

> It builds two Docker boxes, compares them, opens them up to show what made them big, then runs the better box and saves output back to your Windows folder.

## What each component does

**Header**
Tells you what lesson this file belongs to, what it teaches, what you need, and how to run it.

**Imports**
These are helper tools Python needs:

* `subprocess` runs Docker commands from Python.
* `Path` works with folders/files.
* `shutil` checks if Docker exists.
* `re` helps read image sizes like `586MB`.

**`BUILD_OUTPUTS = {}`**
A notebook. It remembers the Docker build output so the script can later say, “Docker reused cache here.”

**`_emit()`**
A safe printer. It prints text without crashing if Windows PowerShell dislikes a symbol.

**`_run()`**
The command runner. This is the function that actually runs things like:

```powershell
docker build ...
docker images ...
docker history ...
docker run ...
```

**`_print_combined_output()`**
Takes Docker’s output and prints it line by line.

**`_size_to_bytes()`**
Converts sizes like `304MB` or `1.87GB` into numbers so Python can sort the biggest layers.

**`build_image()`**
Builds a Docker image from a Dockerfile. In plain English:

> “Docker, read this Dockerfile and create an image with this name.”

It builds:

* `Dockerfile.base`
* `Dockerfile.optimized`

**`compare_image_sizes()`**
Checks how big each image is.

This is where you saw:

```text
base      1.87GB
optimized 586MB
```

**`inspect_layers()`**
Opens the Docker image history and shows what each layer added.

In plain English:

> “Show me which Dockerfile steps made this image huge.”

**`run_pipeline_container()`**
Runs the optimized Docker image as a container.

This is where it maps your Windows folders into the container:

```text
Windows runtime_data/input  -> container /data/input
Windows runtime_data/output -> container /data/output
```

**`explain_caching()`**
Explains whether Docker reused previous work.

In plain English:

> “Did Docker rebuild everything, or did it skip parts it already built before?”

**`main()`**
This is the boss function. It controls the whole sequence.

## Sequence of actions

When you run:

```powershell
python 01_dockerfile_basics.py
```

the file does this:

1. Checks that Docker exists.
2. Builds the big/base image from `Dockerfile.base`.
3. Builds the smaller/optimized image from `Dockerfile.optimized`.
4. Compares image sizes.
5. Shows the layer history for each image.
6. Explains Docker cache reuse.
7. Creates these local folders if needed:

```text
runtime_data/input
runtime_data/output
```

8. Runs the optimized container.
9. Inside the container, the app reads/writes using `/data`.
10. On your Windows machine, the result appears in:

```text
D:\Workarea\StudyBook\tutorials\36_docker\runtime_data\output\summary.json
```

11. Prints the final summary file.

## One-sentence summary

> This script teaches Docker by building a bad image and a good image, comparing them, inspecting what made them big, then running the good image with your local folder connected to the container.
