# 🧭 Where is `/data`?

👉 **Inside the container only — not your Windows machine.**

Think of it like this:

* `/data` = path **inside Docker container (Linux world)**
* `D:\Workarea\...` = path **on your Windows machine**

---

# 🔗 The connection (this is the key)

From your run command:

```
-v D:\Workarea\StudyBook\tutorials\36_docker\runtime_data\input:/data/input
-v D:\Workarea\StudyBook\tutorials\36_docker\runtime_data\output:/data/output
```

👉 This means:

| Windows (host)  | Container      |
| --------------- | -------------- |
| `D:\...\input`  | `/data/input`  |
| `D:\...\output` | `/data/output` |

---

# 🧠 So when your code says:

```python
input_path = pathlib.Path("/data/input/records.csv")
```

👉 It is reading from:

```
D:\Workarea\StudyBook\tutorials\36_docker\runtime_data\input\records.csv
```

# ⚡ The important concept (this is BIG)

👉 `/data` is just a **container path**

👉 `-v` (volume mount) = **bridge between worlds**

Without `-v`:

* `/data` would disappear when container stops ❌

With `-v`:

* Data persists on your machine ✅

---

# 🧠 One-liner to remember

> “`/data` lives inside the container, but is mapped to my local folder using `-v`.”
