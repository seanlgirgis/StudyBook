# 🧠 What this command is doing

```bash
docker images tutorial36-pipeline
```

👉 In plain English:

> “Hey Docker, show me all images on this machine that match `tutorial36-pipeline`.”

---

# ⚙️ Is it querying a service?

👉 **Yes — but locally**

More precisely:

> It sends a request to the **Docker Engine** running on your machine.

### Step-by-step:

1. You type the command in PowerShell
2. Docker CLI receives it (`docker`)
3. CLI talks to Docker Engine (daemon)
4. Engine looks in its local image store
5. Returns matching images
6. CLI prints them

---

# 🧠 Important clarification

❌ It is NOT:

* querying the internet
* querying Docker Hub

✅ It IS:

* querying your **local Docker engine**

---

# 🔍 Breaking down the command

```bash
docker images tutorial36-pipeline
```

### `docker`

The CLI tool (your interface)

### `images`

“Show me stored images”

### `tutorial36-pipeline`

Filter (like a search keyword)

---

# 📊 Your output explained

```text
IMAGE                                  DISK USAGE   CONTENT SIZE
tutorial36-pipeline:base-1.0.0         1.87GB       469MB
tutorial36-pipeline:multistage-1.0.0    586MB       135MB
tutorial36-pipeline:optimized-1.0.0     586MB       135MB
```

### 🧠 Two important columns:

#### DISK USAGE

👉 Total space used on your machine

#### CONTENT SIZE

👉 Actual size of this image’s unique layers

---

# 🔥 Why base is huge

```text
1.87GB vs 586MB
```

👉 Because:

* full OS (`bookworm`)
* no cleanup
* copies everything

---

# 🧠 Why optimized & multistage match

```text
586MB / 135MB content
```

👉 They share layers:

* same base image
* same dependencies

Docker deduplicates layers internally
